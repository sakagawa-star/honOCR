# fixes/ — OCR 誤りの手動修正定義

## 目的

MinerU の OCR には後処理で機械的に解消できない個別の認識誤りが残ることがある。
final の Markdown を直接手動修正すると、再OCR後に final を再構築した時点で
修正が失われる。そこで修正1件を「修正前の文字列（old）→ 修正後の文字列
（new）」のペアとして章ごとの**修正定義ファイル**（JSON）に記録し、
`scripts/apply_fixes.py` で機械適用する。再OCR後も定義ファイルを再適用すれば
1コマンドで修正が復元され、OCR 出力の変化で old が見つからなくなった場合は
エラーで停止して気づける（黙って壊れない）。

## 実体の置き場所

修正定義ファイルの実体は `{BASE}/ocr/fixes/{name}.json`（`{BASE}` は
`docs/PROJECT_KNOWLEDGE.md`（データ節）に定義されたデータルート、`name` は
`chap01` 等の章名）に置く。

**書籍本文の文字列を含むため、このディレクトリ（`fixes/`）にはコミットしない。**
`fixes/` にはこの README と書式サンプルの `template.json` のみを置く。

## 書式

`template.json` を参照。トップレベルは `{"fixes": [...]}`。各要素（1つの修正）
は次の4キーをすべて持つ（すべて文字列型）:

| キー | 内容 |
|---|---|
| `id` | 修正の識別子。ファイル内で一意、非空 |
| `reason` | 修正理由（人間向けメモ） |
| `old` | 修正前の完全一致文字列。非空 |
| `new` | 修正後の文字列。非空（削除だけの修正は前後の残す文字列を含めて old→new として表現する） |

`old` / `new` は「正規化・HTML表変換・脚注挿入がすべて済んだ md」の文字列と
して書く。

## 適用規則

各修正を定義ファイルの記載順に適用する。`count(s)` = md 内の文字列 s の
出現回数。

1. `count(old) == 1` → old を new に 1 回置換し applied に数える
2. `count(old) == 0` かつ `count(new) == 1` → 適用済みとみなし skipped に
   数える（置換しない）
3. `count(old) == 0` かつ `count(new) == 0` → エラー（OCR 出力が変化して
   修正が適用不能）
4. `count(old) == 0` かつ `count(new) >= 2` → エラー（適用済みかどうかを
   一意に判定できない）
5. `count(old) >= 2` → エラー（一意に適用できない）

いずれかの修正でエラーが発生した場合、出力ファイルは一切書かない（部分適用
状態を残さない）。各判定はそれ以前の修正の置換結果を反映した md に対して
行う（記載順の逐次適用）。

さらに、規則 1〜5 をエラーなしで通過した後、出力直前に全修正の
`count(old) == 0` かつ `count(new) == 1` を最終確認する（最終不変条件）。
1件でも violate すればエラーとし出力ファイルを書かない。これは「old が
new の部分文字列である修正」や「後続の修正が先行の修正の new を書き換える
修正」など、再実行時に全件 skipped とならない定義を初回適用時に検出する
ためのもの。

## 実行方法

1 ファイルへの適用:

```
uv run python scripts/apply_fixes.py <md> {BASE}/ocr/fixes/<name>.json -o <出力先> --overwrite
```

`ocr_dir.py` 経由での一括適用（脚注挿入の直後、パイプラインの最終段で
適用される。`{name}.json` が存在しない章は何もせずスキップする）:

```
uv run python scripts/ocr_dir.py <TIFディレクトリ> -o <出力ルート> --fixes-dir {BASE}/ocr/fixes
```

## 注意

- old は「正規化・表変換・脚注挿入がすべて済んだ md」の文字列として書く
- エラーで止まったら OCR 出力が変わったサイン。old を新しい md に合わせて
  更新する
- 最終不変条件エラー（old が new の部分文字列になっている等）が出たら、
  old / new の抜粋範囲（前後文脈）を広げて一意化する
- 修正定義の変更履歴を残したい場合は、`{BASE}/ocr/fixes/` にローカル専用の
  git リポジトリを別途作ればよい（本リポジトリとは独立、任意運用）
