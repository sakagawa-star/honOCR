## 1. 背景

2026-08-28 に『プログラミングのための確率統計』の全10章（383ページ）を
`ocr_dir.py --punct-style touten --final` で処理し、全章 PASS した（約35分）。

その実行中に、feat-011 で導入した「JIS X 0208 外漢字の警告」（feat-011 FR-003）が
**置換表に未登録の中国語字を9種**検出した。警告は設計どおり機能し、
`apply_fixes.py` に回すべき個別誤認識と、置換表に追加すべき字を切り分ける材料になった。

さらに調査したところ、**JIS X 0208 内にあるため警告に現れない旧字体が4種**含まれていた。
警告の仕組みだけでは検出できない種類の誤りである（feat-011 ADR-4 で明示していた限界）。

## 4. 重要な発見: 旧字体は固有名詞では正当

chap09 の奥付に次の1行がある。

```
印刷·製本 廣済堂
```

**廣済堂は旧字を正式名称に用いる実在の社名**であり、これは OCR 誤りではない。
`廣→広` を無条件に置換すると、この正しい表記を壊す。

2026-08-28 のユーザー決定により、本案件では
「旧字体は置換表に入れて一律置換し、固有名詞は修正定義ファイルで個別に元へ戻す」
方針を採る（design.md ADR-1）。新しい書籍では旧字体の出現箇所を目視確認する運用を
CLAUDE.md に明記する。

## 5. 判明した既存機能の制約（本案件では変更しない）

feat-011 の JIS 外漢字警告は**正規化の時点**で出力される。
`insert_footnotes.py`（feat-009）は正規化より後の工程で content_list から md へ
脚注を挿入するため、そこで持ち込まれる文字は md 側の警告に現れない。

実例: chap04 の「揾」は正規化時点の警告では json 側にのみ1件計上され、md 側は0件だった。
しかし脚注挿入後の最終的な md には1件存在する。

content_list は全ブロックを保持しているため検出漏れは生じない（json 側で必ず検出される）。
運用上は「json 側の警告を正とみなす」ことで足りるため、警告の出力位置は変更しない。

## 7. 実装中の発見（2026-08-28。実装は中断し、設計を修正して再開する）

### 7.1 事象

design.md §5.1・§5.4 で定義した chap02・chap06 の修正が、`apply_fixes.py` の
**最終不変条件**（feat-010）に違反して停止した。

```
chap02.json: chap02-001: final invariant violated - new count is 12
chap06.json: chap06-001: final invariant violated - new count is 2
```

`apply_fixes.py` の no-partial-write 保証が働き、chap02・chap06 の md は書き換えられていない。

### 7.2 原因

修正を `old = "\text {亻}"` / `new = "\text {イ}"` と定義していたが、
**`new` が他所に正当に存在していた**。

- chap02: `\text {イ}` が11件（ア/イ/ウ の選択肢を扱う確率の問題が同章に多数ある）
- chap06: `\text {イ}` が1件（別の式にも式番号「（イ）」がある）

そのため置換後の `count(new)` が 1 にならず、
「再実行が冪等にならない定義」として feat-010 の検査が正しく検出した。

design.md §5.6 は `old` の一意性しか確認しておらず、**`new` の適用後の一意性を
確認する手順が欠けていた**（設計の欠陥）。

### 7.3 対処

`old` / `new` の両方に前後の文脈を含めて一意にする。2026-08-28 に再実測して確定した。

| 章 | 修正前の定義 | 修正後の定義 | 適用後の `count(new)` |
|---|---|---|---|
| chap02 | `\text {亻}` → `\text {イ}` | `\underline {{\text {亻}}} \| Y` → `\underline {{\text {イ}}} \| Y` | 1 |
| chap06 | `\text {亻}` → `\text {イ}` | `\dots \dots (\text {亻})` → `\dots \dots (\text {イ})` | 1 |

あわせて design.md §5.6 を「`old` と `new` の両方の一意性を確認する」手順に改め、
確定値の表を追加した。要求仕様書 FR-003 にも受け入れ基準3として明記した。

## 8. 実装再開時の発見（2026-08-28。設計文書の記述の訂正）

実装再開時の確認で、design.md §6 手順4 項目2 の
「『，』『．』が0件であることを確認する」という記述が**不正確**であることが判明した。

`touten` スタイルは「、。→，．」の置換を行わないだけであり、
**原本が正当に用いている「，．」を除去するものではない**。実測では全10章に計21件が存在し、
いずれも原本由来であることを確認した。

| 章 | ， | ． | 内容 |
|---|---|---|---|
| chap02 | 1 | 2 | 数式の区切り／「確率0.9で．を書く」（文字そのものへの言及） |
| chap03 | 0 | 1 | 「．が (k-1) 回出て」（同上） |
| chap04 | 1 | 0 | 数式の区切り（`z=2xe^{x-y}，w=x-y`） |
| chap05 | 0 | 3 | 箇条書き記号「イ．」「ロ．」「ハ．」 |
| chap09 | 13 | 0 | 参考文献リスト（`…確率論とその応用Ⅰ・Ⅱ（各上下巻），紀伊国屋書店，1960-1970.`） |

本作業でこれらが増減していないことは、手順1（正規化）が touten スタイルでは
句読点を一切置換しないことから原理的に保証される。
`ocr_dir.py` の `check_normalized` も touten スタイルで「，．」の0件を要求していない
（置換表の対象文字の残存のみを検査する）。

design.md §6 手順4 項目2 は上記のとおり訂正した。実装・成果物への影響はない。
