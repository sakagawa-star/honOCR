# feat-009 要求仕様書: MinerU 出力から欠落する脚注（訳注）の Markdown 挿入

- 案件: `docs/issues/feat-009-insert-footnotes/`
- 作成日: 2026-08-25
- 準拠基準: `docs/REQUIREMENTS_STANDARD.md`

## 1. プロジェクト概要

- **何を作るのか**: MinerU の content_list.json に含まれる `page_footnote` 型ブロック（脚注・訳注）を、対応する Markdown の該当ページ末尾位置に blockquote として挿入する後処理 CLI `scripts/insert_footnotes.py` を作る。`scripts/ocr_dir.py` の一括パイプラインに組み込み、既存の最終成果物（`{BASE}/ocr/final/` および `{BASE}/ocr/mineru-full/chapNN/run-01-normalized/`）にも適用する
- **なぜ作るのか**: MinerU は `page_footnote` 型ブロックを Markdown に出力しないため、最終成果物の Markdown から全脚注（chap01 に訳注 1〜13 を含む計 31 ブロック）が欠落している。本書の訳注は本文理解に必要な情報であり、LLM に渡す Markdown に含める必要がある
- **誰が使うのか**: プロジェクトオーナー（ユーザー）。ocr_dir.py 経由では Claude Code なしで実行される
- **どこで使うのか**: 本プロジェクトのローカル環境（Linux、Python 3.12、uv 管理）

## 2. 用語定義

機能設計書・コード内でも同じ用語を使う。

| 用語 | 定義 |
|---|---|
| `{BASE}` | `/home/sakagawa/work/Pattern_Recognition_and_Machine_Learning`（CLAUDE.md と同一） |
| content_list | MinerU が出力する `*_content_list.json`。ブロック（dict）のリスト。各ブロックは `type`・`page_idx`（0 始まり）・`text`・`bbox`（`[x0, y0, x1, y1]`、0–1000 正規化、ページ左上原点）等を持つ |
| 脚注ブロック | content_list 中の `type == "page_footnote"` のブロック |
| 浮遊断片 | 脚注ブロックのうち、同一ページ内の別の脚注ブロックのテキストの一部を重複して切り出したもの（空白を除去して比較したとき他ブロックの部分文字列になるもの） |
| 組み立て済み脚注 | 1 ページ分の脚注ブロックから浮遊断片を除去し、bbox の読み順に並べ、脚注番号プレフィックスを持たないブロックを直前の脚注に連結して得られる文字列（1 個の脚注に対応） |
| アンカー | 脚注挿入位置の基準となるブロック。同一ページ（`page_idx` が等しい）のブロックのうち、md 内で出現位置を特定できる最後のもの |
| 脚注番号プレフィックス | ブロックテキスト先頭の「算用数字列または上付き数字列（⁰¹²³⁴⁵⁶⁷⁸⁹）＋空白類 1 文字」のパターン |
| blockquote | Markdown の引用記法。行頭 `> ` で始まる段落 |

## 3. 機能要求一覧

### FR-001: 脚注挿入 CLI

- **機能名**: `scripts/insert_footnotes.py`
- **概要**: Markdown 1 ファイルと対応する content_list 1 ファイルを入力に取り、脚注を挿入した Markdown を出力する
- **入力**: 位置引数 `md`（UTF-8 Markdown ファイルパス）、位置引数 `content_list`（JSON ファイルパス）、`-o/--outdir`（出力ディレクトリ、必須）、`--overwrite`（出力先の同名ファイルが既存でも上書きする。既定は拒否）
- **出力**: `outdir/<md と同じベース名>` に挿入後の Markdown を書き出す。標準出力に `"{md 名}: {N} inserted, {M} skipped"` と `"total: {N} inserted, {M} skipped"` の 2 行のサマリを出す。アンカー未発見によるスキップ（FR-005）発生時は標準エラーにページごと 1 行の警告を出す。既挿入による冪等性スキップ（FR-004）は警告を出さない。終了コードは成功 0、エラー 1
- **受け入れ基準**: `final/chap01` の md・content_list に適用すると 14 件挿入・1 件スキップ（page_idx 83、アンカーなし）、`final/chap02` は 3 件挿入・0 件スキップ、`final/chap06` は 2 件挿入・0 件スキップとなる。chap01 の挿入結果で「4 訳注：データ集合を…」「5 訳注：頻度主義と…」が式 (1.45)〜(1.46) を含むページの本文末尾の直後にこの順（4 → 5）で blockquote として現れる

### FR-002: 脚注の組み立て

- **機能名**: ページ単位の脚注組み立て
- **概要**: 1 ページ分の脚注ブロック群を組み立て済み脚注のリストに変換する
- **入力**: 同一 `page_idx` の脚注ブロックのリスト
- **出力**: 組み立て済み脚注（文字列）のリスト。変換規則は以下ですべてとする:
  1. `text` が空文字列または空白のみのブロックを除外する
  2. 浮遊断片（空白除去後の自テキストが、同一ページの他の脚注ブロックの空白除去後テキストの真部分文字列であるもの）を除外する。空白除去後テキストが完全に一致するブロックが複数ある場合は最初の 1 個のみ残す
  3. 残りを bbox の `(y0, x0)` 昇順で並べ替える（bbox が欠落したブロックは `[0, 0, 0, 0]` として扱う）
  4. 先頭から走査し、脚注番号プレフィックスを持つブロックは新しい組み立て済み脚注を開始、持たないブロックは直前の組み立て済み脚注に半角スペース 1 個で連結する。先頭のブロックが番号プレフィックスを持たない場合は、それ自身を新しい組み立て済み脚注とする（前ページからの続き。連結はしない）
  5. 各ブロックのテキストは前後空白を除去し、テキスト内の改行は半角スペース 1 個に置換する
- **受け入れ基準**: chap01 p64 の 4 ブロック（idx 568〜571）が 1 個の脚注「10 訳注：…条件付き期待値と同様に， $\mathrm{var}[…]…$ で定義される．」に組み立てられる。chap01 p69 の 3 ブロックが 1 個、p79 の 4 ブロックが 1 個になる。chap06 p24 の 3 ブロック（うち 1 個は空白差のある浮遊断片 `$|U|=1$`）が 1 個になる

### FR-003: 挿入位置と挿入形式

- **機能名**: ページ末尾への blockquote 挿入
- **概要**: 各ページの組み立て済み脚注を、そのページのアンカーの直後の段落境界に挿入する
- **入力**: md 全文、content_list、ページごとの組み立て済み脚注
- **出力**: 挿入後の md 全文。規則は以下ですべてとする:
  1. アンカー決定: content_list を先頭から走査し、`type` が `text`/`ref_text`/`equation` なら `text` を、`image`/`chart` なら `img_path` を検索文字列として、md 内を前回発見位置以降から `str.find` で検索する（単調増加カーソル）。`table` は次の 3 候補を順に試し、最初に発見できたものを使う: (a) `table_body`（前後空白除去。HTML 表が未変換の md に一致）、(b) `table_body` を `html_table_to_md.convert_table` で変換して得た行を `"\n"` で連結した文字列（feat-008 変換後の md に一致。変換がスキップ（reason 非 None）の場合この候補はなし）、(c) `img_path`。発見できたブロックのうち、ページごとに md 内終端位置が最大のものをそのページのアンカーとする
  2. 挿入点: アンカーの md 内終端位置以降で最初に現れる `"\n\n"` の直前。`"\n\n"` がなければ md 末尾
  3. 挿入内容: そのページの組み立て済み脚注を順に `"\n\n> " + 脚注文字列` として連結した 1 個の文字列を、挿入点に 1 回で挿入する（同一ページ内の順序が保たれる）
  4. 複数ページの挿入は挿入点の降順に適用する（先の挿入が後の挿入位置をずらさないようにする）
- **受け入れ基準**: FR-001 の受け入れ基準と同一の位置・順序で挿入される。挿入後の md の既存部分（挿入文字列以外）はバイト単位で無変更である

### FR-004: 冪等性

- **機能名**: 再実行時の重複挿入防止
- **概要**: 挿入済みの md に再実行しても重複挿入しない
- **入力**: 挿入済み md ＋同じ content_list
- **出力**: `"> " + 組み立て済み脚注` が md に既に部分文字列として存在する場合、その脚注は挿入せずスキップ数に数える。警告は出さない
- **受け入れ基準**: FR-001 適用後の chap01 md に再実行すると 0 件挿入・15 件スキップ（既挿入 14 件＋page_idx 83 のアンカーなし 1 件）となり、md はバイト単位で無変更である。標準エラーは page_idx 83 の no anchor 警告 1 行のみである

### FR-005: アンカーなしページの扱い

- **機能名**: アンカー未発見時のスキップ
- **概要**: ページ内のどのブロックも md 内で発見できない場合、そのページの脚注は挿入しない
- **入力**: アンカーが決定できないページの組み立て済み脚注
- **出力**: 該当脚注をスキップ数に数え、標準エラーに `"{md 名}: page {page_idx}: no anchor; {件数} note(s) skipped"` を 1 行出力する
- **受け入れ基準**: chap01 の page_idx 83（第2章冒頭が写ったページ。本文が md に存在しない）の脚注 1 件がこの規則でスキップされ、警告 1 行が出る

### FR-006: ocr_dir.py への組み込み

- **機能名**: 一括パイプラインへの統合
- **概要**: `scripts/ocr_dir.py` の HTML 表変換（feat-008）の直後に、正規化済み md へ脚注挿入を実行する
- **入力**: 正規化済み md（`run-NN-normalized/*.md`）と正規化済み content_list（同ディレクトリの `*_content_list.json`）
- **出力**: 正規化済み md をインプレース更新（`-o` に同ディレクトリ、`--overwrite` 付き）。`DirResult` に挿入件数・スキップ件数を追加し、PASS 行に `footnotes={N}+{M}skipped` を表示する。insert_footnotes.py が非 0 終了またはサマリ解析不能の場合はそのディレクトリを FAIL とする
- **受け入れ基準**: `tests/test_ocr_dir.py` の既存テストが全件成功し、脚注挿入ステップの成功・失敗を検証する追加テストが成功する

### FR-007: 既存データへの適用

- **機能名**: final / run-01-normalized への一括適用
- **概要**: 既存の全 8 章の md に脚注挿入を適用する
- **入力**: `{BASE}/ocr/final/chapNN/chapNN_gray300.md`（＋同ディレクトリの content_list）および `{BASE}/ocr/mineru-full/chapNN/run-01-normalized/chapNN_gray300.md`（＋同ディレクトリの content_list）、NN = 00〜07
- **出力**: 両系統の md をインプレース更新する。content_list.json・images/ は無改変とする
- **受け入れ基準**: 挿入件数が chap01 = 14、chap02 = 3、chap06 = 2、その他 5 章 = 0 である。適用後、各章の final md と run-01-normalized md がバイト同一（`cmp`）である。全 16 個の content_list.json が適用前とバイト同一である

### FR-008: 自動テスト

- **機能名**: `tests/test_insert_footnotes.py`
- **概要**: FR-001〜FR-005 の規則を合成データで検証する自動テスト
- **入力**: `uv run pytest -v`
- **出力**: 全テスト成功。結果を `tests/results/feat-009_test_result.txt` に保存する
- **受け入れ基準**: 通常挿入・断片除去（空白差含む）・bbox 並べ替え・番号なし先頭ブロック・複数脚注の順序・アンカーなしスキップ・冪等性・画像アンカー・`--overwrite` 拒否の各ケースを検証するテストが存在し、既存テストを含む全件が成功する

## 4. 非機能要求

- **パフォーマンス**: 1 章分（md 約 200KB・ブロック約 900 個）の処理が 10 秒以内に完了する
- **対応環境**: Linux、Python 3.12（uv 管理）。GPU 不要
- **信頼性**: 出力は `normalize_punct.write_text_atomic`（一時ファイル書き込み→`os.replace`）で原子的に書き込む。入力ファイルは変更しない（`-o` が入力と同ディレクトリかつ `--overwrite` の場合のみ置換される）
- **セキュリティ**: 該当なし（ローカルファイル処理のみ）

## 5. 制約条件

- 使用ライブラリは Python 標準ライブラリ（argparse、json、re、sys、pathlib、collections）と既存モジュール `scripts/normalize_punct.py`（`write_text_atomic`）・`scripts/html_table_to_md.py`（`convert_table`）に限定する。新規外部依存を追加しない
- content_list.json は読み取り専用とし、変更しない（MinerU スキーマ維持。feat-008 と同方針）
- 入出力パスはハードコードせず CLI 引数で受け取る（CLAUDE.md コーディング規約）
- ネットワークアクセスなし
