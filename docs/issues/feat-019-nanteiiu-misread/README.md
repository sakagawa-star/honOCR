## 3. feat-017 の修正が原因ではないことの根拠（2026-09-02 再確認）

1. **`content_list.json` にも同じ「なんていいう」が2件含まれている。**
   `apply_fixes.py` は md のみを対象とし `content_list.json` を変更しない（feat-010 の設計）。
   さらに chap03 の `content_list.json` の SHA-256 は feat-017 の実装前に記録された基準値
   `d269034e9b54fd993a3d4f9e092421a3b7974d3441519eb389678055e5103220` と**一致したままである**
   （2026-09-02 実測）。したがってこの誤読は feat-017 の適用前から存在した
2. feat-017 で chap03 に適用した `new` は `等しいなんていう勘違い` /
   `3.5n に近づいていく、なんていうことはない` / `n/2 に近づいていく、なんていうことはない` であり、
   **「なんていいうことはありません」を生成しえない**
3. feat-017 の `old` は本件の文（読点がなく、語尾が「ありません」）と**一致しない**ため、
   そもそもマッチしていない

## 4. 原本での確認（2026-09-02 実施）

`content_list.json` の index 558 の `page_idx`（= 35）から
`{BASE2}/ocr/pdf/chap03_gray300.pdf.manifest.json` の `files[35]["path"]` で原本 TIF
`{BASE2}/dewarping/chap03/out/page-19_1L.tif`（4252 × 5236）を特定し、
`bbox` = `[127, 542, 923, 654]`（0–1000 正規化座標）の領域を切り出して目視確認した。

原本の記述は次のとおりである。

```
　まず一つめ。大数の法則が成り立つのは個数 n で割っているからこそです。単に合計するだけだと分
散は大きくなります（→ 3.4.5 項 (p.97)「独立なら、足し算の分散は分散の足し算」）。n を大きくしても、
サイコロを n 回ふった合計値が 3.5n に近づいていくなんていうことはありませんし、コインを n 回投
げたときに表が出る回数が n/2 に近づいていくなんていうこともありません*15。それぞれ、擬似乱数
列（→ 7 章 (p.253)）を用いた計算機実験の結果を図 3.15 と図 3.16 に示します。
```

**原本は2箇所とも「なんていう」であり、OCR の「なんていいう」は誤読である**（「い」の余分な挿入）。

なお本段落は、feat-017 で修正した図 3.15・3.16 のキャプション（md 1263・1274 行）の
**直前にあり、同じ内容を本文で述べている箇所**である。

## 5. 検出の限界（本件が既存の警告に掛からない理由）

- 「い」は JIS X 0208 内の文字であり、feat-011 の「JIS X 0208 外漢字の警告」には現れない
- 字形の 1 対 1 対応ではない**語彙単位の誤り**であり、feat-013 で21種に拡充した
  字形正規化テーブルでも扱えない（本件は「い」の**挿入**であり、1文字 → 1文字の対応で表現できない）
- feat-015（chap02）・feat-016（上的 → 上の）・feat-017（なんという → なんていう）と同種であり、
  `docs/PROJECT_KNOWLEDGE.md` のドメイン知識に記載済みの既知の類型である。
  機械的な検出手段がなく、ユーザーの手動テストによってのみ発見された

### 5.1 feat-017 で見落とした理由

feat-017 の調査では**「なんという」という文字列だけを検索した**ため、同じ語の別バリアントである
「なんていいう」を発見できなかった。両者は同一ページ（`page-19_1L.tif`）の隣接する段落にあった。

**教訓**: 語彙単位の誤読を調査するときは、誤読された文字列そのものだけでなく、
**正しい語（本件では「なんていう」）を起点に、その表記ゆれ・脱落・挿入のバリアントを
正規表現で網羅的に洗い出す**。本案件の §6 ではこの方法で調査した。
