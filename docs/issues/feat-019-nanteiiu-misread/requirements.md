# feat-019 要求仕様書: chap03 の誤読「なんていいう → なんていう」2件の修正

## 1. プロジェクト概要

### 何を作るのか

『プログラミングのための確率統計』chap03 の既存の修正定義ファイル
`{BASE2}/ocr/fixes/chap03.json`（feat-017 で作成済み・リポジトリ外）に修正を2件追記し、
`apply_fixes.py`（feat-010）で既存成果物に適用したうえで、
`build_final.py`（feat-012）で `final/chap03/` を再構築する。

**リポジトリ内のコード（`scripts/`）とテストコード（`tests/test_*.py`）は一切変更しない。**
本案件で作成・更新する成果物は次の3つに限られる。

1. リポジトリ外の修正定義ファイル1件（`{BASE2}/ocr/fixes/chap03.json` への追記）
2. それを適用したリポジトリ外の既存成果物（`{NORM}/` と `{BASE2}/ocr/final/chap03/`）
3. リポジトリ内の案件ドキュメント（`docs/issues/feat-019-nanteiiu-misread/`）、
   `docs/BACKLOG.md` / `docs/CHANGELOG.md` / `docs/PROJECT_KNOWLEDGE.md` の完了処理、および
   テスト結果の記録 `tests/results/feat-019_test_result.txt`（新規作成。
   CLAUDE.md「テスト」のルールで必須）

**`CLAUDE.md` は更新しない**（update-003 で確定した非対称ルール: CLAUDE.md 本体の変更は
update 案件でのみ行う）。`docs/PROJECT_KNOWLEDGE.md` の更新要否は機能設計書 §11 で定める。

### なぜ作るのか

chap03 の 3.5.4 節「大数の法則に関する注意」の本文で、原本の「なん**ていう**」が
OCR で「なんて**い**いう」と誤読されている（「い」が1文字余分）。同一行に2件ある
（案件 README.md §2・§4 で原本確認済み）。

誤読を残すことは本プロジェクトのゴール「入力への忠実な OCR」に反するため、修正する。
本件を修正すれば、両書籍の「なん〜いう」系の誤読はすべて解消する（案件 README.md §6）。

### 誰が使うのか

本プロジェクトのユーザー。成果物（`{BASE2}/ocr/final/chap03/chap03_gray300.md`）を
LLM に読ませて学習に用いる。

### どこで使うのか

`docs/TECH_STACK.md` に定義された既存環境（Ubuntu 24 系 / Python 3.12.3 / uv）。
新規のライブラリ・モデル・ネットワークアクセスは追加しない。

## 2. 用語定義

feat-010・feat-013・feat-016・feat-017 の要求仕様書の用語を継承する。本書で用いる主な用語は次のとおり。

| 用語 | 定義 |
|---|---|
| 修正定義ファイル | OCR 誤りを「修正前文字列（`old`）→ 修正後文字列（`new`）」のペアで記録した JSON。`{BASE2}/ocr/fixes/{name}.json` に置く。書籍本文を含むためリポジトリに置かない（feat-010） |
| 語彙単位の誤り | 1文字の字形置換では表現できず、複数文字の並びとしてのみ判定できる誤り。本件の「なんていいう → なんていう」がこれにあたる |
| 最終不変条件 | `apply_fixes.py` が適用後に検査する条件。**全 fix について `count(old) == 0` かつ `count(new) == 1`**。1つでも破れると出力を書かずにエラー終了する（feat-010 FR-003 規則6） |
| 再適用 | 既に構築済みの成果物（`run-NN-normalized/` と `final/`）に対し、MinerU を再実行せずに修正適用・final 再構築のみを行うこと（feat-013 §2） |
| `{BASE2}` | `/home/sakagawa/work/確率統計`（git 管理外・リポジトリ外） |
| `{NORM}` | `{BASE2}/ocr/mineru-full/chap03/run-01-normalized`（chap03 の正規化済みディレクトリ） |
| `{FINAL}` | `{BASE2}/ocr/final/chap03`（chap03 の最終成果物ディレクトリ） |

## 3. 機能要求一覧

### FR-001: chap03 の修正定義ファイルへの修正追記

- **機能名**: `{BASE2}/ocr/fixes/chap03.json` への修正2件の追記
- **概要**: 2件の誤読を `fixes/template.json` の書式に従って定義し、
  既存の `chap03-001`〜`chap03-003` の後ろに追記する
- **入力**: 案件 README.md §2・§4 で確定した誤り箇所（2箇所）
- **出力**: `{BASE2}/ocr/fixes/chap03.json`（既存ファイルの更新。UTF-8・JSON）
- **受け入れ基準**:
  1. `fixes/README.md`・`fixes/template.json` の書式に従い、`id` / `reason` / `old` / `new` の
     4キーをすべて文字列で持つ fix が**2件追加**され、追記後の `fixes` 配列の要素数が
     **5件**（既存3件 ＋ 新規2件）になる
  2. 既存の `chap03-001`・`chap03-002`・`chap03-003` の `id` / `reason` / `old` / `new` を
     1文字も変更しない
  3. `apply_fixes.py` の `validate_fixes` がエラーを1件も出さない
  4. 適用**前**の `{NORM}/chap03_gray300.md` において、新規2件の `count(old) == 1` である
  5. 適用**後**の `{NORM}/chap03_gray300.md` において、**5件すべて**について
     `count(old) == 0` かつ `count(new) == 1` である（最終不変条件）
  6. 各 `reason` に、原本 TIF で確認済みであることと、`old` / `new` を一意にするために
     文脈を含めた理由を日本語で記述する
  7. ファイルはリポジトリに置かず、コミットもしない（feat-010 の運用）

### FR-002: 「なんていいう」の誤読の訂正（2件）

- **機能名**: chap03 の md における「なんていいう」→「なんていう」の訂正
- **概要**: 案件 README.md §2 の2箇所を訂正する
- **入力**: `{NORM}/chap03_gray300.md`（適用前）
- **出力**: 同（適用後）
- **受け入れ基準**:
  1. 適用後の md における「なんていいう」の出現回数が **0** である（適用前は 2）
  2. 適用後の md における「なんていう」の出現回数が **5** である（適用前は 3。
     feat-017 で修正した3件 ＋ 本案件の2件）
  3. 件数はすべて Python の `str.count()` による**出現回数**で数える。
     `apply_fixes.py` の不変条件と同じ数え方であり、行数ではない。**`grep -c` を使わない**
  4. 適用後の md の 1256 行目が、次の2つの文字列をいずれも含む（前後に他の変更がない）

     ```
     3.5n に近づいていくなんていうことはありませんし
     ```

     ```
     n/2 に近づいていくなんていうこともありません
     ```

  5. 両書籍の final 全章の md に対し、正規表現 `なん.{0,5}?[いゆ]う` で抽出される出現形が
     `なんていう`（確率統計 12件）と `なんとなくそういう`（確率統計 chap03 1件）の2種のみになる
     （案件 README.md §6 の調査方法と同じ。`なんていいう` が 0 件になることの確認）

### FR-003: 既存成果物への修正の適用と final の再構築

- **機能名**: chap03 の再適用
- **概要**: MinerU と `normalize_punct.py` を再実行せず、`apply_fixes.py` と
  `build_final.py` のみを実行して chap03 の成果物を更新する
- **入力**:
  - `{NORM}/chap03_gray300.md`（feat-017 適用後の状態）
  - `{BASE2}/ocr/fixes/chap03.json`（FR-001 の成果物）
- **出力**:
  - `{NORM}/chap03_gray300.md`（インプレース更新）
  - `{FINAL}/`（再構築）
- **受け入れ基準**:
  1. `apply_fixes.py` の終了コードが 0 で、`applied = 2`・`skipped = 3` である
     （新規2件が適用され、feat-017 で適用済みの3件は skipped になる）
  2. `build_final.py` の終了コードが 0 である（3種類の機械検証がすべて合格）
  3. 適用後の md の文字数が **54007 文字**である（適用前 54009 文字 − 「い」2文字）
  4. 適用後の md の行数が **1462 行**である（適用前と同一。改行の増減がないため）
  5. 適用前後の `diff` の差分ハンクが **1つ**のみであり、1256 行の「い」2文字の削除だけである
  6. `{FINAL}/` の md・content_list.json が `{NORM}/` とバイト同一である
  7. `{FINAL}/images/` のファイル数が **66** のまま変わらない
  8. `{NORM}/chap03_gray300_content_list.json` は**変更されない**
     （`apply_fixes.py` は md のみを対象とする既存ポリシー。feat-010／feat-013 §6.1）。
     SHA-256 で検証する

| 項目 | 要求 |

## 5. 制約条件

- **MinerU を再実行しない**。OCR 結果は同一入力に対して変わらず、10章で約35分の実行コストに
  見合わない（feat-013 ADR-3・feat-015 ADR-4・feat-016 ADR-2・feat-017 ADR-4 と同じ判断）
- **`normalize_punct.py` を再実行しない**。feat-013 で適用済みであり、本案件は字形正規化
  テーブルを変更しないため結果は変わらない
- **`final/` を直接編集しない**。final は `run-NN-normalized/` からのコピーであり、コピー元を
  更新しないと次回の final 再構築で変更が失われる（feat-013 の既存方針）
- **`content_list.json` を修正しない**。MinerU のスキーマを維持する既存ポリシー（feat-010）。
  結果として md と json の当該箇所の表記が一致しなくなるが、これは feat-013 §6.1・
  feat-016 §8・feat-017 design.md §8 で許容済みの既知事項である
- **置換表（`normalize_punct.py`）に「なんていいう → なんていう」を追加しない**
  （機能設計書 ADR-1 で理由を記す）
- **`CLAUDE.md` を変更しない**（update-003 の非対称ルール）
- 修正定義ファイルの実体は**コミット禁止**（書籍本文を含むため）
- 本案件は**コード変更を含まない**。作業中にコード変更が必要と判明した場合は中断して報告する
- **feat-018（中止案件）のドキュメントを流用しない**。本案件の調査・検証はすべて独立に実施した
