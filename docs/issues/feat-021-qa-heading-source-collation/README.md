# feat-021: Q&A コラム見出し全74件の原本突合

- **ステータス**: **Closed**（2026-09-02 起票 / 2026-09-03 完了）
- **結果**: 74件中 **37件が原本と不一致**（P0 37 / P1 37 / P9 0）。詳細は同フォルダの
  `collation_summary.md`、原本の質問文を含む詳細記録は `{BASE2}/ocr/collation/feat-021_qa_headings.md`
  （書籍本文を含むためリポジトリ外）
- **対象書籍**: 『プログラミングのための確率統計』（`{BASE2}` = `/home/sakagawa/work/確率統計`）
- **対象**: final 全10章の Q&A コラム見出し **全74件**
- **種別**: 機能追加（feat）

## 0. 起票の経緯

これまでユーザーが手動テストで発見した OCR の問題は、**すべて Q&A コラム見出しで発生している**。

| 発見された問題 | 扱い |
|---|---|
| Q&A 見出しの2ブロック分断（`? 2.2`） | feat-015（Closed） |
| Q&A 見出し先頭の「？」アイコン分離 8件 | feat-014（Closed） |
| Q&A 見出しが見出しとして認識されない 19件 | feat-020（Open・未着手） |
| `? 2.7` の欠落 | feat-020 の γ型として起票済み |
| `? 2.10` の誤読「こぜんぶ → これぜんぶ」 | 別案件として起票予定（未起票） |

Q&A 見出しは MinerU の layout 解析が繰り返し失敗している箇所であり、かつ**全74件と数が限られる**
ため、**全件を原本 TIF と突き合わせて網羅的に洗い出すことが現実的**である。
これをユーザーが「原本突合は必須。別案件として対応する」と決定した（2026-09-02）。

本案件は、**問題を1件ずつ手動テストで発見していく現状の運用を、Q&A 見出しに関しては
網羅的な突合に置き換える**ことを狙いとする。

## 1. スコープ（2026-09-02 ユーザー決定）

| 項目 | 決定 |
|---|---|
| **突合対象** | **74件全部**（feat-020 の19件を含む） |
| **成果物** | **突合結果の記録まで**（一致/不一致の一覧を作る。修正の実施は含まない） |
| **突合の粒度** | **質問文の全文**（見出し体裁だけでなく、文字列を原本と1字ずつ突き合わせる） |

### 補足

- **74件全部を対象にする理由**: feat-020 の §4-1 が「原本 TIF による全19件の確認」を未実施として
  残しており、55件と19件で突合作業を分けると走査コマンド・記録様式が二重になる。
  本案件で74件を一度に突合し、**feat-020 は本案件の結果を引き継いで修正の実施に専念する**
- **修正を含めない理由**: 突合の結果として何件・どの型の不一致が出るかが未知であり、
  要求仕様・設計・検証手順を事前に確定できない。調査と修正を分けることで、
  修正案件ごとに検証手順を設計できる
- **全文を突き合わせる理由**: `? 2.10` の「こぜんぶ → これぜんぶ」のような**語彙単位の誤読**は、
  見出し体裁（`##`・`?`・番号）の確認だけでは検出できない。
  語彙単位の誤りは機械的な検出手段がなく（`docs/PROJECT_KNOWLEDGE.md`）、原本突合が唯一の手段である

## 2. 現状の把握（起票時点の実測）

`{BASE2}/ocr/final/chapNN/chapNN_gray300.md`（feat-014 適用後・2026-09-02 時点）を
次の正規表現で走査した。

```bash
cd /home/sakagawa/work/確率統計/ocr/final
python3 -c "
import re, glob
pat = re.compile(r'^(##\s+)?([？?][ 　]*)?([0-9A-C]+)\.([0-9]+)(?=[ 　])')
for p in sorted(glob.glob('chap*/chap*_gray300.md')):
    ch = p.split('/')[0]
    for i, line in enumerate(open(p, encoding='utf-8'), 1):
        line = line.rstrip(chr(10))
        m = pat.match(line)
        if m and m.group(2):
            kind = '見出し' if m.group(1) else '★本文段落'
            print(f'{ch} L{i} [{kind}] {m.group(3)}.{m.group(4)} | {line[:60]}')
"
```

結果: 見出し **55件** / 「?」付き本文段落 **14件**。

このうち `chap09 L941` の `?3.8 $^{(p.101)}$ と同じ勘違いですね。…` は
**本文中の相互参照**（p.101 の `? 3.8` を指す記述）であって Q&A 見出しではない。
これを除くと本文段落は **13件**となり、feat-020 が記録した内訳と一致する。

| 分類 | 件数 |
|---|---|
| 正常な見出し（`## ? N.M …`） | 55 |
| α型: 見出しだが「?」欠落 | 3 |
| β型: 「?」付きだが本文段落 | 13 |
| γ型: 「?」も無く本文段落 | 1 |
| δ型: 数式/コードブロックに埋没 | 2 |
| **計** | **74** |

型の定義と19件の全一覧は `docs/issues/feat-020-qa-heading-not-recognized/README.md` を参照する
（本案件で再掲・検証する）。

## 4. 未実施の事項（調査・計画フェーズで行うこと）

本案件は**起票のみ**で、以下はすべて未実施である。

1. **74件それぞれの原本ページの特定**（`content_list.json` の `page_idx` → TIF ファイル名の対応付け）
2. **突合の実施方法の設計** — 74件×（原本画像の目視 ＋ md 文字列の照合）をどう進め、
   どう記録するか。1件あたりの記録項目（番号・章・原本ページ・原本の質問文・md の質問文・
   一致/不一致・不一致の型）を定める
3. **不一致の型の分類体系の定義** — 既知の型（アイコン分離・見出し不認識・語彙誤読・分断）に加え、
   突合で新たに出た型をどう分類するか
4. **合格ライン・判定基準の事前定義**（`CLAUDE.md`「実験・検証の進め方（予測→実行→照合）」）

   調査フェーズで判断する
5. **後続案件への引き渡し方の設計** — 不一致を型ごとにどう束ねて起票するか。
   feat-020 との関係（本案件の結果をどう引き継がせるか）の明確化
