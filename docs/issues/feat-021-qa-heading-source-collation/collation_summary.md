## 7. 適用した解釈（比較規則の運用メモ）

比較規則に明文の定めがなく、実施時に一貫した扱いを決めた点を記録する。

1. **数式境界の前後の空白は比較しない**（例: md の `、 $…$ なんていう` の `$` 前後の空白）。
   数式で分割した地の文セグメントごとに N2（前後の空白除去）を適用した
2. **`\text{}` の境界を数式範囲の区切りとみなした**（chap02 2.5 の δ型）。
   `$…$` が無くても数式と地の文の切り替わりが表現されているため
3. **ローマ数字「Ⅰ」は字形上 `I` と区別できない**ため、不一致の根拠が無いものとして一致とした（chap00 0.3）
4. **`D4` は「数式範囲の個数が合わない」場合を含む**。実際の 18 件のうち大半は
   「原本で数式組版になっている箇所が md では平文になっている」ケースである

## 8. feat-020 の記載の訂正点

本案件の調査で判明した、feat-020 の README を更新すべき点が2つある。**本案件では feat-020 の
ドキュメントを変更していない**（§9 で引き渡す）。

1. **chap04 `? 4.6` はβ型ではない。** content_list では `type=code`・`sub_type=algorithm` であり、
   md 上も `<div class="mineru-algorithm">` ブロックの内側にある。行頭に `? 4.6` があるため
   feat-020 の行頭走査ではβ型に見えていた。**`##` を付けるだけでは見出しにならない**
2. **feat-014 で修正した3件（1.2 / 2.6 / 5.2）は content_list 側では `?` が欠落したままである。**
   md と content_list の状態がずれている（`apply_fixes.py` は md のみを対象とするため。既存ポリシー）。
   content_list を基準に走査すると、これら3件は「見出しだが `?` なし」（本案件の S2）に見える
3. あわせて **feat-020 の未調査事項3（chap05 `? 5.6` の `□` が何の誤認識か）への回答**:
   **`□` は原本にもそのまま `□`（白抜きの正方形）として印刷されており、OCR の誤認識ではない**
