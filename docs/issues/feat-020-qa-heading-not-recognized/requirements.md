# feat-020 要求仕様書: Q&A コラム見出しが見出しとして認識されない19件の修正

## 1. プロジェクト概要

### 何を作るのか

『プログラミングのための確率統計』の **Q&A コラム見出し19件**を、md 上で正しい見出し
（`## ? N.M 質問文`）にする。手段は修正定義ファイル（`{BASE2}/ocr/fixes/chapNN.json`）への
追記と、`apply_fixes.py`（feat-010）→ `build_final.py`（feat-012）の再適用である。

対象は **9章・19件**（chap00 1 / chap01 2 / chap02 6 / chap04 3 / chap05 2 / chap06 1 /
chap07 2 / chap08 1 / chap09 1）。**chap03 は対象外**（8件すべて正常）。

**リポジトリ内のコード（`scripts/`）とテストコード（`tests/test_*.py`）は一切変更しない。**
本案件で作成・更新する成果物は次の3つに限られる。

1. リポジトリ外の修正定義ファイル9件（`chap00.json` は**新規作成**、他8件は既存への追記）
2. それを適用したリポジトリ外の既存成果物（9章の `{NORM_NN}/` と `{FINAL_NN}/`）
3. リポジトリ内の案件ドキュメント（`docs/issues/feat-020-qa-heading-not-recognized/`）、
   `docs/BACKLOG.md` / `docs/CHANGELOG.md` / `docs/PROJECT_KNOWLEDGE.md` の完了処理、および
   テスト結果の記録 `tests/results/feat-020_test_result.txt`（新規作成。
   CLAUDE.md「テスト」のルールで必須）

**`CLAUDE.md` は更新しない**（update-003 で確定した非対称ルール）。
`docs/PROJECT_KNOWLEDGE.md` の更新要否は機能設計書 §11 で定める。

### なぜ作るのか

確率統計の Q&A コラム見出しは全74件あるが、**19件が md 上で見出しになっていない**。
MinerU の layout 解析が当該ブロックを見出しと判定しなかったこと（`content_list.json` の
`text_level` が付かない）に起因し、文字認識の誤りではない。

見出しでないと、LLM が本文と質問を区別できず、目次・アウトライン抽出にも現れない。
これは本プロジェクトのゴール「入力への忠実な OCR」に反する。

### 誰が使うのか

本プロジェクトのユーザー。成果物（`{BASE2}/ocr/final/chapNN/chapNN_gray300.md`）を
LLM に読ませて学習に用いる。

### どこで使うのか

`docs/TECH_STACK.md` に定義された既存環境（Ubuntu 24 系 / Python 3.12.3 / uv）。
新規のライブラリ・モデル・ネットワークアクセスは追加しない。

     （`chap00-001` / `chap01-004`・`005` / `chap02-006`〜`011` / `chap04-003`〜`005` /

### FR-002: 19件すべてを正常な見出しにする

- **機能名**: Q&A コラム見出し19件の体裁の復元
- **概要**: 型ごとに次の変換を行う
  - **型α（3件）**: `## N.M …` → `## ? N.M …`（「? 」を挿入する）
  - **型β（12件）**: `? N.M …` → `## ? N.M …`（行頭に「## 」を挿入する。
    **「?」と番号の間の空白は現状のまま変えない**）
  - **型γ（1件）**: `2.7 …` → `## ? 2.7 …`（「## ? 」を挿入する）
  - **構造復元（3件）**: 質問文を取り込んでいるブロック（数式ブロック・HTML `div`・
    コードブロック）を解体し、質問文を `## ? N.M …` の見出しにする
- **入力**: 各 `{NORM_NN}/chapNN_gray300.md`（適用前）
- **出力**: 同（適用後）
- **受け入れ基準**:
  1. 適用後の確率統計 final 全10章の md に対し、正規表現
     `^(##\s+)?([？?][ 　]*)?([0-9A-C]+)\.([0-9]+)(?=[ 　])` で走査したとき、
     **`?` を伴う出現のうち `##` 付き（見出し）が 74 件、`##` 無しが 1 件**である
     （案件 README §3.1 と同じ走査。2026-09-05 に適用をシミュレートして実測）
  2. 上記の `##` 付き **74 件**が Q&A コラム見出しの全数である（適用前は 55。55 + 19 = 74）
  3. 上記の `##` 無しの **1 件**は `chap09` の `?3.8 $^{(p.101)}$ と同じ勘違いですね。…`
     （**本文中の相互参照**であって見出しではない。feat-021 で母集団74件から除外済み）であり、
     **これ以外に `##` の無い Q&A コラム見出しが存在しない**。適用前は 14 件
     （本案件の対象13件 ＋ この相互参照1件。型γ の 2.7 は `?` が無いためこの走査に現れない）
  4. 構造復元3件について、適用後の md が次の状態になる:
     - chap02 2.5: `$$` … `$$` の数式ブロックが消え、`## ? 2.5 もし $\mathrm{P}(X = a) = 0$ だったら $\mathrm{P}(Y = b \mid X = a)$ はどうなるの？` の1行になる
     - chap04 4.6: `<div class="mineru-algorithm" …>` … `</div>` が消え、
       見出し1行＋空行＋答えの段落1行になる
     - chap07 7.3: ` ```txt ` … ` ``` ` のコードブロックが消え、
       見出し1行＋（コードブロック内にあった本文がそのまま）になる
  5. 構造復元の痕跡が残っていないこと。具体的には次の3つを満たす:
     - chap04: 文字列 `mineru-algorithm` の出現回数が **0**（適用前は 1）
     - chap07: ` ```txt ` フェンスの出現回数が **5 → 4** に減る。
       **0 にはならない**——chap07 には Q&A 見出しとは無関係の正当なコードブロックが
       **4 つ**あるため（プログラム例1つと端末セッション3つ。2026-09-05 実測で
       md 283・544・565・576 行）。**「0 件」を基準にしてはならない**
     - chap07 に残る4つの ` ```txt ` ブロックについて、**フェンスの直後の行が
       Q&A 見出しの形（`N.M ` で始まる）であるものが 0 件**である
       （＝コードブロックに取り込まれた Q&A 見出しが残っていない）
  6. 件数はすべて Python の `str.count()` による**出現回数**で数える。**`grep -c` を使わない**

### FR-005: 構造復元3件における例外の限定

- **機能名**: 構造復元に伴う不可避な変更の範囲の明示
- **概要**: 構造復元3件は、ブロックの解体に伴って見出し以外の文字列にも手が及ぶ。
  その範囲を限定して定義する
- **受け入れ基準**:
  1. **chap02 2.5**: 数式ブロック内の `\text {…}` による表現を、通常の地の文＋インライン数式に
     書き換える。**この1件に限りインライン数式の記法を変更してよい**（`$$` ブロックのままでは
     見出しにできないため不可避）。書き換え後の数式は原本に一致させる
     （`$\mathrm{P}(X = a) = 0$` / `$\mathrm{P}(Y = b \mid X = a)$`）
  2. **chap04 4.6**: `div` 内の2行（質問・答え）は**1文字も変更しない**。
     `div` の開始タグ・終了タグを削除し、質問行の行頭に `## ` を補い、
     質問と答えの間に空行を1行入れるだけとする
  3. **chap07 7.3**: コードブロック内の本文（質問行を除く8行）は**1文字も変更しない**。
     フェンス（` ```txt ` と ` ``` `）を削除し、質問行を `## ? 7.3 [0,1) って何ですか？` に
     置き換えるだけとする
  4. 上記1〜3以外の箇所で、質問文・本文の文字を変更しない
