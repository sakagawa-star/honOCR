## 指摘

### 高-1: 正しい修正でも差分ハンク数の受け入れ基準に違反する

**指摘内容**（原文の要旨）:

> `requirements.md:175`・`design.md:728` の「差分ハンク数 ＝ 新規 fix 件数」という基準について、
> **19件を実データにメモリ上で適用して通常形式の diff で確認したところ、
> chap04 は期待3に対して4ハンク、chap07 は期待2に対して3ハンク**だった。
> 構造復元では、見出し側の変更と終了タグ・フェンスの削除が別ハンクになる。
> このままでは正常な成果物を不合格にする。

**修正案**: 両文書の期待値を実測値に修正し、「ハンク数＝fix件数」という条件を撤回する。

**判定: 妥当。** 本案件側でも同じ手順で再実測し、chap04 = 4・chap07 = 3 を確認した。

### 高-2: 修正定義の退避失敗を見逃し、復元時に既存 JSON を削除しうる

**指摘内容**（原文の要旨）:

> `design.md:475`・`design.md:624`。退避確認は md と final のみで、**JSON のコピー失敗を
> 検査していない**。既存 JSON の退避に失敗しても `BACKUP_OK` が出る。その後に失敗すると、
> 復元コードは退避ファイルが無いことを理由に、**chap01 以降の既存 JSON まで削除する**。

**修正案**: 既存8ファイルのコピー成功とバイト一致を退避完了条件に追加する。
復元時の削除は `ch == chap00` に限定し、他章の退避欠落時は削除せず中断する。

**判定: 妥当。** `rm -f "$B2/ocr/fixes/${ch}.json"` にコメントで「chap00 のみ」と書いていたが、
**コード上の条件になっていなかった**。先行案件が作成した修正定義ファイルを失う危険があった。

**なお codex は、19件の置換自体について「全42 fix の最終不変条件、文字数・行数、
見出し74件・本文参照1件を満たした」ことを実データで検証している**（ファイルは変更していない）。

1. **差分ハンク数の期待値を実測値に差し替えた**（`requirements.md` FR-003 基準4 と

   9章分の期待ハンク数と**実測したハンク見出し**（`757,758c757,758` 等）を表にした。
   chap04・chap07 で1つ多くなる理由（ブロックの先頭側の置換と末尾側の削除が非連続）も記載

   失敗時は `BACKUP_NG_MD` / `BACKUP_NG_FINAL` / `BACKUP_NG_FIXES` を出して手順1 に進まない
