## 1. 経緯・目的

### 1.1 契機

update-009 の壁打ち（2026-09-08）で、`docs/issues/feat-024-inline-math-markup-survey/rule_feedback_notes.md`（以下 F 番号はこの文書の項目）の候補 18 件のうち、次元・式の枠で吸収される 10 件（F2・F4・F5・F11〜F14・F16・F17）を第 1 段（update-009）で反映した。残る 8 件は「式が無くても起きる」手順・記録・レビュー単位の穴であり、ユーザーは「一旦、今の壁打ちの範囲でルールを改訂する。そしてその後独立項目を再度見直してルール改訂が必要かを判断する。改訂を2段に分ける」と決定した。本案件がその第 2 段である。

8 件の共通点は、update-009 の規定を置いても残ること（§2 で個別に確認する）。ただし update-009 で「外れた後にエージェントが書けるもの」が制限され、直前予測が「式に実測を代入した値」に固定されたため、8 件のうちいくつかは重みが変わっている（§2 の「update-009 後の状態」列）。

### 1.2 目的

各項目について、**update-009 反映後の `CLAUDE.md`** に照らして「規定に穴が残っているか」「残っているなら規定で埋めるか、記録として残すだけにするか」を判断し、埋めると決めた項目だけを `design.md` で反映する。判定条件は update-008・009 と同じ: 記入欄と手順だけで構成され、エージェントに「これは要るか」「同じ原因か」の判断を要求しないこと。**本案件で規定の項目数を増やすこと自体は目的ではない**（ユーザー 2026-09-07「条件を増やせばいいものではない」）。

### 1.3 採らなかった案と不採用の理由

| 案 | 不採用の理由 |
|---|---|
| 8 件を update-009 に含める | ユーザー判断（update-009 README §5 判断 G）で 2 段に分けた。第 1 段の枠（式と次元）と性格が違い、同時に扱うと第 1 段の Codex レビューの範囲が広がる |

| 8 件をすべて記録のみとして規定化しない | F1（実装と実行の混在）と F7（状態記録の遅れ）は feat-024 で実際に逸脱と誤検出を生み、ユーザーの介入で初めて是正された（`rule_feedback_notes.md` §2.2）。記録だけでは再発する |
