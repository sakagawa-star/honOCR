# feat-003 実験判定基準（criteria）: MinerU 試行の品質判定

CLAUDE.md「実験・検証の進め方」に基づく事前判定基準。**本文書は実験実行前に Codex レビューで重要度「高・中」ゼロに収束させてから固定する（criteria lock）。実行後の変更は行わない。**

## 1. 答える問い

MinerU（3.4.4、hybrid-engine 既定設定）による chap-01（64ページ）の Markdown 出力は、「LLM に読ませて書籍を勉強する」用途に足りる品質か。足りるならフェーズ4（全章の本処理）へ進む（Go）。

## 2. 判定項目・サンプリング方法・合格ライン

判定は3項目。**すべて合格なら Go、1項目でも不合格なら No-Go**（No-Go 時の対策検討は本実験のスコープ外）。

### 項目A: 独立数式の再現性

- **サンプリング（母集団は原本側で確定する）**: **原本** chap-01 を1ページ目から順に走査し、数式番号（例: (1.1)）が付いている独立数式の先頭 **20件**を母集団とする。原本側が 20 件未満の場合は全件（その件数 n を実験ログに記録する）。**n = 0 の場合は判定不能として No-Go とする**
- **判定方法**: 各原本数式について、Markdown 出力の対応ページ（content list の page_idx で対応付ける）に対応する独立数式を探す。**存在しない（MinerU が数式を落とした・独立数式として認識しなかった）場合は不一致**。存在する場合は原本ページ画像と目視比較し、二値判定する。**一致** = 変数名・添字・上付き・分数・総和/積分の構造・ギリシャ文字がすべて原本どおりで、数学的に同じ式として読める。1箇所でも欠落・誤認識・構造崩れがあれば**不一致**
- **合格ライン**: 一致 **16/20 以上（80%以上）**。n < 20 の場合は ceil(0.8 × n) 以上（分母は常に原本側の件数 n）

### 項目B: 日本語本文の再現性

- **サンプリング（母集団は原本側で確定する）**: 原本 chap-01 を1ページ目から順に走査し、次の条件を満たす段落の先頭 **10段落**を取る: 地の文（見出し・図表キャプション・脚注・数式ブロックを除く）で、原本の印刷行で3行以上あるもの。**段落の単位** = 原本の組版上の段落（字下げで始まり、次の字下げまたは空行の直前まで）
- **対応付け**: content list の page_idx で当該原本ページの Markdown 出力ブロックと突き合わせる。Markdown 側で段落が分割・結合されていても、テキスト内容が順序どおりすべて存在すれば欠落とみなさない（分割・結合自体は誤りに数えない。順序は項目C の対象）
- **誤りカウント規則**:
  - 無視する差分: 空白・改行・字下げ・Markdown 装飾記号（見出し `#`、強調 `*`）・**行内数式全体（`$...$` のデリミタと内容の両方。本文と原本の対応位置に行内数式が「存在する」ことだけ確認し、その中身の正誤は数えない**。行内数式の品質は §5 のとおり本実験の判定対象外）
  - 数える単位: Unicode コードポイント（結合文字列は1文字と数える）
  - 誤り = 原本に対する置換・脱落・挿入されたコードポイントの合計数（行内数式の位置自体が欠落している場合は「脱落1文字」と数える）
- **判定方法**: 二値判定。**合格** = 段落の欠落（対応ブロックが存在しない、または内容の一部の行・文が欠ける）がなく、誤りが段落あたり **2文字以下**。誤り3文字以上または欠落があれば**不合格**
- **合格ライン**: 合格 **9/10 以上（90%以上）**。原本側の該当段落が10未満の場合は全件を分母とし、ceil(0.9 × n) 以上（n = 0 は判定不能として No-Go）

### 項目C: 読み順の正しさ

- **サンプリング**: chap-01_gray300.pdf の **5・15・25・35・45 ページ目**（1始まり。該当ページが白紙の場合は次の非白紙ページ）
- **判定単位と対応付け**: content list のうち当該ページ（page_idx = ページ番号 − 1）の要素（text / title / equation ブロック）の並びを「Markdown 側の読み順」とする
- **判定方法**: 二値判定。**合格** = ブロックの並びが原本の読み順（上→下、段組があれば左段→右段）と一致する。入れ替わりが1箇所でもあれば**不合格**
- **合格ライン**: 合格 **4/5 以上（80%以上）**

## 3. 判定の実施者と手順

- 一次判定: Claude Code が原本ページ画像（TIF）と Markdown 出力を突き合わせ、項目ごとの判定表（サンプルID・原本ページ番号・判定・不一致内容）を実験ログに記録する
- 二次確認: ユーザーが判定表と現物を確認し、判定の妥当性を承認する（一次判定の誤りが見つかった場合は該当サンプルを再判定し、履歴を残す）

## 4. 予測する項目の枠（値は各フェーズ直前に確定する）

- フェーズ1（章単位PDF生成）実行前: 各 PDF のページ数・ファイルサイズの予測
- フェーズ2（MinerU 実行）実行前: モデルダウンロード容量・変換所要時間・Markdown 内の独立数式件数の予測
- フェーズ3（品質判定）実行前: 項目A/B/C の実測値の予測

## 5. 除外事項（本実験で判定しないもの）

- 行内数式（`$...$`）の品質（独立数式より判定の客観性が低い。フェーズ4の計画時に必要なら別実験とする）
- 図・表の抽出品質
- 変換速度の合否（実測記録のみ）
- chap-00 の品質（chap-01 の結果を代表とみなす）
