## フェーズ2: MinerU による変換（design.md §4.2、実行ディレクトリ: run-01）

### 事前確認

- ディスク空き: 100GB（基準30GB以上 ✓）
- `~/.cache/huggingface` 実行前サイズ: 3.6GB（モデルDL容量算出の基準値）
- 実行ディレクトリ `mineru-trial/run-01/` を新規作成済み

### 予測（実行前に記録）

- モデルダウンロード容量: **約6GB**（根拠: hybrid-engine は MinerU2.5 VLM 1.2B 系＋レイアウト/OCR補助モデルの構成。VLM 本体 2.5GB 前後＋周辺モデルと見積り）
- 変換所要時間: **モデルDL込みで40分以内、変換本体は20分以内**（根拠: 64ページ・GPU 16GB。事前実績がないため上限側に幅を持たせた粗い見積り。乖離時は原因を記録する）
- Markdown 内の独立数式件数: **約120件**（根拠: PRML 第1章は番号付き数式が (1.1)〜(1.117) 程度あり、番号なしの表示数式も一部ある一方、MinerU が行内扱いにするものもあると想定）

### run-01 実測: 失敗（想定外事象）

- 結果: 終了コード 1。変換・モデルダウンロードとも未実施（`~/.cache/huggingface` 3.6GB のまま、run-01/ 空）
- 原因: MinerU 3.4.4 の CLI はローカル API サービス（`http://127.0.0.1:<port>`）を起動しヘルスチェックするが、本環境はプロキシ必須（`/etc/environment` で `http_proxy=http://ufproxy.b.cii.u-fukui.ac.jp:8080/`）かつ `no_proxy=.u-fukui.ac.jp` のみで **`127.0.0.1` / `localhost` が除外されていない**。ヘルスチェック要求がプロキシ（Skyhigh Secure Web Gateway）へ転送され 502 応答となり、タイムアウトで CLI が終了した（run-01.log 13行目）
- 対処方針: design.md §4.2 を修正（mineru 実行コマンドに `no_proxy` / `NO_PROXY` へ `localhost,127.0.0.1` を追加した環境変数プレフィックスを付ける。モデルダウンロードは引き続きプロキシ経由）。修正は Codex レビューを経て再開する（設計にない変更のためフロー準拠で中断）
- 予測との照合: 予測項目（DL容量・時間・数式件数）は実行に到達しなかったため未照合。run-02 で同じ予測を用いる

### run-02 実測（2026-08-17、no_proxy 修正後）

- 結果: **終了コード 0（成功）**、所要 **6分26秒**（モデルダウンロード込み）
- モデルダウンロード: `~/.cache/huggingface` 3.6GB → 6.0GB = **2.4GB**
- 出力レイアウト（確定）: `run-02/chap-01_gray300/hybrid_auto/` 配下に `chap-01_gray300.md`、`*_content_list.json`（フラット785ブロック、全ブロックに `page_idx`）、`*_content_list_v2.json`（ページ別64要素）、`*_middle.json`、`*_model.json`、`*_layout.pdf`、`*_origin.pdf`、`images/`
- Markdown の `$$` 出現数: **314（偶数）** = 独立数式 **157件**
- FR-002 受け入れ基準: (1) Markdown 1個・独立数式1件以上 ✓ (2) page_idx 付き JSON ✓ — **すべて充足**

### run-02 照合

- 所要時間: 予測「DL込み40分以内」に対し6分26秒 ✓（大幅に速い方向の乖離。上限側に幅を持たせた粗い見積りだったため）
- モデルDL容量: 予測6GBに対し2.4GB（−60%）。原因: hybrid-engine のモデル構成が VLM 本体（1.2B、bf16）中心で、周辺モデルが想定より小さかった。実行の妨げになる乖離ではない
- 独立数式件数: 予測120件に対し157件（+31%）。原因: 番号なしの表示数式が想定より多い。項目Aの母集団は原本側の番号付き数式で確定するため判定への影響なし

## フェーズ3: 品質判定（design.md §4.3、criteria.md 準拠）

### 予測（判定作業前に記録）

- 項目A（番号付き独立数式 20件）: 一致 **17/20**（根拠: MinerU の数式CDM 88.46 と、300dpi グレースケール・活字という好条件から、9割弱の一致を見込む）
- 項目B（本文10段落）: 合格 **9/10**（根拠: 日本語活字の OCR は高精度が見込めるが、漢字の微細な誤認識が1段落程度で2文字を超えるリスクを見る）
- 項目C（読み順5ページ）: 合格 **5/5**（根拠: 本書は基本1段組でレイアウトが単純）
