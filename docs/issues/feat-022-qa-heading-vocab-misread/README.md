### 2.1 feat-020 との分担（8.6 の扱い）

feat-020 は本案件の適用後の md に合わせて `old` を書く**ことで解消する（feat-020 は未着手のため
順序を確定できる）。この点は feat-020 への引き渡し事項として §7 に記す。

## 6. 修正の手段と一意性の検証（2026-09-03 実測）

feat-016・017・019 と同じく、`{BASE2}/ocr/fixes/chapNN.json` への追記＋
`apply_fixes.py` → `build_final.py` で対処する見込み。**リポジトリ内のコード変更なしの見込み。**

`docs/PROJECT_KNOWLEDGE.md` の規定に従い、`old` の一意性だけでなく**適用後に `new` がちょうど1件に
なること**も事前に数えた（確率統計 final 全10章の md を横断して計測）。

| 章 | 新 ID（予定） | `old`（候補） | `old` 件数 | `new`（候補） | `new` 件数（適用前） |
|---|---|---|---|---|---|
| chap01 | `chap01-003` | `描いたらいんでしたっけ` | 1 | `描いたらいいんでしたっけ` | 0 |
| chap02 | `chap02-005` | `こぜんぶ` | 1 | `これぜんぶ` | 0 |
| chap03 | `chap03-007` | `賭けるということですよね` | 1 | `賭けろということですよね` | 0 |
| chap08 | `chap08-002` | `そういうことだる` | 1 | `そういうことだろ` | 0 |

4件とも `old` が全10章で1件・`new` が0件であり、適用後に `new` がちょうど1件になる。
既存の修正定義ファイルは4章すべてに存在するため、**すべて追記**である
（chap01 に2件・chap02 に4件・chap03 に6件・chap08 に1件が既存）。

`content_list.json` にも同じ誤読が4件とも存在するが、`apply_fixes.py` は md のみを対象とするため
**json は無改変のまま**になる（md と json の非対称性。既存ポリシー）。

## 8. 検出の限界（本件が既存の警告に掛からない理由）

4件とも構成する文字がすべて JIS X 0208 内にあり、feat-011 の「JIS X 0208 外漢字の警告」にも
feat-013 の字形正規化テーブルにも掛からない。「い」「れ」の脱落は 1 文字 → 1 文字の字形対応で
表現できず（feat-019 ADR-1）、「る」→「ろ」は字形としては正当な文字同士のため置換表に入れられない。
**語彙単位の誤り**として `apply_fixes.py` の修正定義ファイルで個別に対処するほかない
（`docs/PROJECT_KNOWLEDGE.md` 記載の既知の類型）。
