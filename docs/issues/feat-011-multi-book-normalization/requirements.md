# feat-011 要求仕様書: 他書籍対応のための正規化・脚注処理の一般化

## 1. プロジェクト概要

### 何を作るのか

既存の OCR パイプライン（`scripts/normalize_punct.py`・`scripts/insert_footnotes.py`・
`scripts/ocr_dir.py`）から「PRML 専用の前提」を取り除き、書籍ごとに異なる部分を
CLI オプションで選べるようにする。あわせて、MinerU が出力する中国語字（簡体字・繁体字）を
対応する日本語字へ機械的に正規化し、規則化できない残存誤字を検出して警告する。

### なぜ作るのか

第2の書籍『プログラミングのための確率統計』（以下「確率統計」）を OCR して Markdown 化したいが、
現状のパイプラインをそのまま適用すると次の破壊・劣化が起きる（feat-011 README.md §3 の実測）。

- 確率統計の原本は句読点に「、」「。」を用いるが、`ocr_dir.py` は無条件で「，」「．」へ置換する。
  chap07（18ページ）だけで 501 箇所が原本と異なる出力になる
- 脚注の番号が `*N` 形式のため `insert_footnotes.py` の組み立てが劣化し、
  別々の脚注が 1 行に連結される・断片が残留する

また調査の副産物として、**PRML の既存成果物にも中国語字が混入している**ことが判明した
（chap00〜07 の Markdown 合計で、字形正規化により直せるもの 13 件、
規則化できない個別の誤認識 3 件）。

### 誰が使うのか

本プロジェクトのユーザー（Claude Code を介さず `ocr_dir.py` を直接実行する）。

### どこで使うのか

`docs/TECH_STACK.md` に定義された既存環境（Ubuntu 24 系 / Python 3.12.3 / uv / MinerU 3.4.4）。
新規のライブラリ・モデル・ネットワークアクセスは追加しない。

## 2. 用語定義

本書・機能設計書・コード内で同じ用語を使う。

| 用語 | 定義 |
|---|---|
| 句読点スタイル | 書籍が本文で用いる読点・句点の字。本プロジェクトでは 2 種類のみを扱う: **comma スタイル**（「，」「．」。PRML）と **touten スタイル**（「、」「。」。確率統計） |
| 句読点正規化 | MinerU 出力に混在する「、」「。」を「，」「．」へ置換する後処理（feat-004 で導入。comma スタイルの書籍にのみ意味がある） |
| 中国語字 | MinerU が日本語字のかわりに出力する簡体字・繁体字。本書では「対応する日本語字が 1 対 1 で確定する 8 字種」（§3 FR-002 の表）に限定して用いる |
| 字形正規化 | 中国語字を対応する日本語字へ置換する後処理（本案件で新設） |
| JIS 外漢字 | Unicode の CJK 統合漢字（U+4E00〜U+9FFF）のうち、JIS X 0208 に含まれない文字。Python の `str.encode("shift_jis")` が `UnicodeEncodeError` を送出することで判定する |
| 脚注プレフィックス | 脚注テキストの先頭にある注番号の表記。PRML は `4 `（数字＋空白）や上付き数字、確率統計は `\*4 ` や `$^{3}$ ` |
| 断片 | MinerU が 1 つの脚注を分割して出力した部分文字列のブロック。`insert_footnotes.py` は他ブロックの部分文字列であるものを断片として除去する |
| 比較キー | 断片判定のために脚注テキストから空白等を除去した文字列 |
| 本文既存動作 | 本案件の変更前（feat-010 完了時点）の各スクリプトの動作 |

## 3. 機能要求一覧

### FR-001: 句読点スタイルの選択（`normalize_punct.py`）

- **機能名**: 句読点正規化スタイルの CLI 選択
- **概要**: 句読点置換を行うか否かを CLI オプションで選べるようにする
- **入力**: `--punct-style {comma,touten}`（省略時は `comma`）。および従来どおりの入力ファイル群
- **出力**: 出力ディレクトリへ同名で書き出されるテキストファイル
  - `comma` 指定時: 「、」→「，」「。」→「．」を置換する（本文既存動作と同一）
  - `touten` 指定時: 句読点の置換を一切行わない
- **受け入れ基準**:
  1. `--punct-style` を省略した実行の出力が、本文既存動作の出力とバイト単位で一致する
     （ただし FR-002 の字形正規化による差分を除く）
  2. `--punct-style touten` を指定した実行では、入力中の「、」「。」が出力でもそのまま残る
  3. `--punct-style` に `comma` / `touten` 以外の値を与えた場合、argparse がエラー終了する（終了コード 2）
  4. 標準出力の集計行（`{name}: {n} replaced` および `total: {n} replaced in {m} files`）の
     `n` は、そのスタイルで実際に置換した文字数（FR-002 の置換数を含む）と一致する

### FR-002: 中国語字の字形正規化（`normalize_punct.py`）

- **機能名**: 中国語字 → 日本語字の置換
- **概要**: MinerU が出力する中国語字を、対応する日本語字へ無条件（句読点スタイルによらず）に置換する
- **入力**: 従来どおりの入力ファイル群（追加のオプションは設けない）
- **出力**: 次の 8 ペアを置換したテキスト

  | 置換前 | 置換後 | 置換前 | 置換後 |
  |---|---|---|---|
  | 值 | 値 | 图 | 図 |
  | 变 | 変 | 换 | 換 |
  | 单 | 単 | 徵 | 徴 |
  | 对 | 対 | 樣 | 様 |

- **受け入れ基準**:
  1. 上表 8 字種を含む入力に対し、出力では 8 字種が 1 件も残らない
  2. 置換前後で文字列長が変わらない（すべて 1 文字 → 1 文字の置換である）
  3. 確率統計 chap07 のパイロット出力に適用すると、`## Box-Muller 变换` が
     `## Box-Muller 変換` に、`▶ 图 7.4 格子点` が `▶ 図 7.4 格子点` に、
     `一樣分布`（6 件）が `一様分布` になる
  4. PRML 既存 final に適用すると `## 2.1 二值变数` が `## 2.1 二値変数` になる

### FR-003: JIS 外漢字の残存警告（`normalize_punct.py`）

- **機能名**: 正規化後に残る JIS 外漢字の検出と警告
- **概要**: FR-002 の置換で直せない字形誤り（例: PRML の「濵習」→「演習」、「跺な解」→「疎な解」）を
  ユーザーが `apply_fixes.py` で対処できるよう、正規化後のテキストに残る JIS 外漢字を報告する
- **入力**: 追加のオプションは設けない（常時実行する）
- **出力**: 標準エラーへ、ファイルごとに次の形式で出力する
  - 1 行目: `{ファイル名}: JIS外漢字 {字種数} 種 {総件数} 件`
  - 2 行目以降: 字種ごとに `  '{文字}' x{件数}: ...{前後25文字の文脈}...`（文脈は最初の 1 件のみ、
    改行は空白に置換する）
  - JIS 外漢字が 0 件のファイルについては何も出力しない
- **受け入れ基準**:
  1. 「濵」「跺」を含む入力に対し、上記の形式で標準エラーに警告が出る
  2. 警告が出ても終了コードは 0 のままである（警告であって失敗ではない）
  3. 標準出力（集計行）の内容は警告の有無で変わらない
  4. FR-002 で置換される 8 字種は、置換後に検出されないため警告に現れない

### FR-004: `ocr_dir.py` への句読点スタイルの伝播と機械確認の連動

- **機能名**: 一括実行スクリプトの句読点スタイル対応
- **概要**: `ocr_dir.py` に `--punct-style` を追加し、`normalize_punct.py` へ渡すとともに、
  正規化の機械確認（`check_normalized`）の判定条件をスタイルに連動させる
- **入力**: `--punct-style {comma,touten}`（省略時は `comma`）
- **出力**: 機械確認の合否と、PASS/FAIL サマリ行
- **受け入れ基準**:
  1. `--punct-style` 省略時の許可差分は「（、→，）（。→．）」と FR-002 の 8 ペアであり、
     それ以外の差分が 1 箇所でもあれば FAIL する
  2. `--punct-style touten` 指定時の許可差分は FR-002 の 8 ペアのみであり、
     句読点が置換されていれば（差分として現れるため）FAIL する
  3. `--punct-style` 省略時は、正規化後テキストに「、」「。」が残っていれば FAIL する
  4. `--punct-style touten` 指定時は、正規化後テキストに「、」「。」が残っていても FAIL しない
  5. スタイルによらず、正規化後テキストに FR-002 の 8 字種が残っていれば FAIL する
  6. 正規化前後で文字列長が異なれば、スタイルによらず FAIL する（本文既存動作と同一）
  7. FR-003 の警告は `ocr_dir.py` の判定に影響せず、標準エラーへ素通しされる

### FR-005: 脚注プレフィックスの `*N` 形式対応（`insert_footnotes.py`）

- **機能名**: 脚注番号プレフィックスの認識範囲拡張
- **概要**: 脚注の組み立てで「新しい脚注の先頭」と認識する表記に、確率統計で用いられる形式を追加する
- **入力**: 従来どおり（md と content_list。追加のオプションは設けない）
- **出力**: 認識対象を次のとおりとする（いずれも直後に空白が続く場合に限る）
  1. 半角数字列（例: `4 `）— 本文既存動作
  2. 上付き数字列（例: `⁴ `）— 本文既存動作
  3. アスタリスク＋半角数字列（例: `*4 `）。直前のバックスラッシュ（Markdown エスケープ `\*4 `）を許容する
  4. 上付き数式形式（例: `$^{3}$ ` / `$^{*4}$ `）。中括弧内は「アスタリスク 0 個または 1 個 ＋ 半角数字列」に限る
- **受け入れ基準**:
  1. 確率統計 chap07 の p4 において、`\*2 参考文献 [8] の…` と `$^{3}$ ただし精度という…` が
     **別々の** blockquote 行として挿入される（本文既存動作では 1 行に連結される）
  2. PRML chap01〜07 に適用したとき、挿入される blockquote の件数と内容が本文既存動作と一致する
  3. 追加した 3・4 の形式に一致しないテキスト（例: `*` の後に数字がない）は、
     従来どおり直前の脚注に連結される

### FR-006: 断片判定の比較正規化（`insert_footnotes.py`）

- **機能名**: 数式記号を無視する断片判定
- **概要**: 断片除去に用いる比較キーの生成規則を拡張し、MinerU が同じ文字列を
  数式化して出力した場合（`[0,1)` と `$[0,1)$`）にも部分文字列判定が成立するようにする
- **入力**: 従来どおり
- **出力**: 比較キーは、脚注テキストから「空白文字」「`$`」「`\`」をすべて除去した文字列とする
  （比較にのみ用い、挿入されるテキストは元のまま変更しない）
- **受け入れ基準**:
  1. 確率統計 chap07 の p10 において、断片 `[0,1) でなく (0,1]` が除去され、
     親脚注（`\*4 厳密に言えば、…`）1 行だけが挿入される
  2. 挿入されるテキストは正規化前の原文であり、`$` や `\` が失われていない
  3. PRML chap01〜07 に適用したとき、挿入される blockquote の件数と内容が本文既存動作と一致する

### FR-007: 既存データに対する回帰の非破壊

- **機能名**: PRML 既存成果物への影響の限定
- **概要**: 本案件の変更が PRML の成果物に与える差分を、意図した範囲だけに限定する
- **入力**: PRML 既存 final（`{BASE}/ocr/final/chapNN/chapNN_gray300.md` および同 content_list.json、
  `{BASE}` = `/home/sakagawa/work/Pattern_Recognition_and_Machine_Learning`）
- **出力**: 検証結果の報告（実装時に実行し、テスト結果ファイルとともに報告する）
- **受け入れ基準**:
  1. `--punct-style` を省略して PRML final を再正規化したとき、入力との差分が
     FR-002 の 8 ペアによる置換のみである（PRML final は正規化済みのため句読点の差分は 0 件になる）
  2. その差分件数が、chap00〜07 の Markdown 8 ファイル合計で **13 件**
     （`值` 3・`变` 4・`单` 2・`对` 1・`徵` 1・`樣` 2 の合計。確率統計にのみ現れる
     `图`・`换` は 0 件）であり、content_list.json 8 ファイル合計で **23 件**
     （`值` 8・`变` 9・`单` 2・`对` 1・`徵` 1・`樣` 2 の合計）である
     （2026-08-28 実測。Markdown と JSON で件数が異なるのは、MinerU が同じ本文を
     content_list の複数ブロックに重複して持つためである）
  3. PRML final に `insert_footnotes.py`（変更後）を適用したとき、全 8 章で新たな挿入が
     0 件であり、出力が入力とバイト単位で一致する（冪等性の維持）。
     このときスクリプトが報告する skipped は 8 章合計で 20 件である
     （挿入済み blockquote 19 件のスキップ ＋ chap01 の `page_idx` 83 にある
     「アンカーが見つからない脚注」1 件のスキップ）。
     後者は feat-009 の設計どおりの既存挙動であり、本案件の変更前後で同一であることを
     `git show HEAD:scripts/insert_footnotes.py` で取り出した変更前スクリプトとの
     比較で確認する（2026-08-28 の実装時に確認済み。本案件による回帰ではない）
  4. 同じ再正規化で FR-003 の警告が報告する JIS 外漢字が、chap00〜07 の Markdown 合計で
     `跺` 2 件・`濵` 1 件の 2 字種 3 件である（いずれも FR-002 の置換対象外であり、
     `apply_fixes.py` で対処すべき個別の誤認識である）

### FR-008: 自動テスト

- **機能名**: 変更点の自動テスト
- **概要**: 変更した 3 スクリプトについて自動テストを追加し、既存テストを維持する
- **入力**: `uv run pytest -v`
- **出力**: `tests/results/feat-011_test_result.txt`（コマンド出力をそのまま保存）
- **受け入れ基準**:
  1. 既存テスト 143 件がすべて PASS する
  2. FR-001〜FR-006 の各受け入れ基準に対応するテストが追加され、すべて PASS する。
     **ただし FR-003 を採用しない場合、テストの対象は FR-001・FR-002・FR-004・FR-005・FR-006 とし、
     FR-003 に対応するテスト（機能設計書 §10.1 の `test_non_jis_*` および `test_is_jis_x0208`）は
     追加しない。**
  3. 実データ（PRML final・確率統計パイロット出力）に依存するテストを含めない
     （テストはリポジトリ内で自己完結する）

## 4. 非機能要求

- **パフォーマンス**: `normalize_punct.py` と `insert_footnotes.py` の 1 章あたりの処理時間は、
  変更前後で 2 倍を超えて増加しない（PRML chap01 = md 約 480KB での実測で確認する）
- **対応環境**: Ubuntu 24 系 / Python 3.12.3 / uv。GPU は本案件の変更部分では使用しない
- **信頼性**: 出力ファイルの書き込みは既存の `write_text_atomic`（一時ファイル → fsync → 確定）を
  引き続き使用する。`content_list.json` の内容は本案件でも改変しない
  （正規化スクリプトは従来どおり content_list.json も置換対象とするが、
  スキーマ・ブロック構造は変更しない）
- **後方互換性**: 3 スクリプトとも、新規オプションを省略した場合は
  FR-002（字形正規化）と FR-003（警告）の追加を除いて本文既存動作と同一である

## 5. 制約条件

- 使用必須: Python 標準ライブラリのみ（`codecs` / `re` / `argparse`）。
  新規のサードパーティライブラリは追加しない
- 使用禁止: 文字コード変換のための外部辞書ファイル・外部 API
- ネットワーク: 本案件の変更部分はネットワークアクセスを行わない
- 出力互換: `ocr_dir.py` の標準出力の集計行の書式（`{name}: PASS pages=… replaced=…` 等）は
  既存のまま維持する。`--punct-style` の値は集計行に含めない
- 実データ: 確率統計の本処理（全 383 ページの OCR・final 構築）は本案件のスコープ外とする

**MVP の範囲**: FR-003 を除く 7 件（FR-001・FR-002・FR-004・FR-005・FR-006・FR-007・FR-008）。

FR-002（字形正規化）は MVP に含める。FR-004 の許可差分・残存検査（受け入れ基準 1・2・5）と

FR-003（JIS 外漢字の警告）のみを唯一の任意項目とし、人レビューで採否を判断する。
**FR-003 を採用しない場合は、FR-007 の受け入れ基準 4（`跺` 2 件・`濵` 1 件の警告）を
検証対象から外す。**それ以外の受け入れ基準は FR-003 の採否に依存しない
（FR-004 受け入れ基準 7 は「警告を素通しする」という要求であり、警告が存在しなければ
素通しすべき出力もないため自動的に満たされる）。
