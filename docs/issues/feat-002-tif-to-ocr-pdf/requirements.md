# feat-002 要求仕様書: TIF → OCR用可逆PDF生成スクリプト

## 1. プロジェクト概要

- **何を作るのか**: 補正済みスキャン原本の TIF 群を入力に、OCR（MinerU）への入力に適した「300dpi グレースケール・Flate 可逆・複数ページ1ファイル」の PDF を生成する CLI スクリプト
- **なぜ作るのか**: 既存の閲覧用 PDF（300dpi RGB JPEG）は非可逆圧縮ノイズが数式の添字認識に不利であり、OCR 入力には可逆ソースから作り直した PDF が必要なため（CLAUDE.md「テストデータ」「ドメイン知識」参照）
- **誰が使うのか**: 本リポジトリの開発者（ユーザーおよび Claude Code）
- **どこで使うのか**: ローカルマシン（Ubuntu 24.04 / Python 3.12 / uv 環境。feat-001 で構築済み）。GPU は使わない

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 原本TIF | `/home/sakagawa/work/Pattern_Recognition_and_Machine_Learning/chap01/out/page-NN_{1L,2R}.tif`。3683×5806px・600dpi。本文ページは RGB・LZW 可逆、白紙ページのみ 1-bit・G4 |
| OCR用PDF | 本スクリプトが生成する PDF。300dpi・8-bit グレースケール・Flate（zip）可逆圧縮の画像を1ページ1枚格納する |
| Flate | zlib/deflate による可逆圧縮。PDF の FlateDecode フィルタ |
| 1/2縮小 | 2×2 画素の平均による縦横 1/2 の縮小（600dpi → 300dpi 相当） |
| 章 | 書籍の章。どの TIF がどの章に属するかは利用者がスクリプト呼び出し時のファイル指定で表現する（本スクリプトは章対応表を持たない） |

機能設計書・コード内でも上記と同じ用語を使う。

## 3. 機能要求一覧

### FR-001: CLI による PDF 生成

- **機能名**: CLI による PDF 生成
- **概要**: 入力 TIF ファイル群（1個以上）と出力 PDF パスを CLI 引数で受け取り、指定順のページを持つ1つの PDF を生成する
- **入力**: TIF ファイルパスの列（コマンドライン引数、1個以上）、出力 PDF パス（`-o`）
- **出力**: 出力パスに生成された PDF 1ファイル
- **受け入れ基準**: 入力 TIF n 個に対し n ページの PDF が生成され、ページ順が引数の指定順と一致する

### FR-002: 変換仕様（グレースケール・300dpi・可逆）

- **機能名**: 変換仕様
- **概要**: 各ページを 8-bit グレースケールに変換し、1/2縮小（600dpi → 300dpi 相当）した画像を Flate 可逆で PDF に格納する。ページの物理寸法は原本と同じにする
- **入力**: 原本TIF（RGB / 1-bit / 8-bit グレースケールのいずれか）
- **出力**: PDF 内の各ページ画像（8-bit グレースケール、1842×2903px、300dpi、FlateDecode）
- **受け入れ基準**: `pdfimages -list` で全ページが gray / 8-bit / enc が `jpeg` でない / x-ppi・y-ppi が 300 であり、ページサイズが 442.08 × 696.72 pt（各辺 ±0.5pt 以内）である

### FR-003: 入力検証とエラー処理

- **機能名**: 入力検証とエラー処理
- **概要**: 不正入力を変換開始前に検出してエラー終了する。出力先の意図しない上書きを防ぐ
- **入力**: 存在しないファイルパス、未対応モード（1 / L / RGB 以外）の TIF、壊れた（デコードできない）TIF、既存の出力パス
- **出力**: 標準エラー出力へのメッセージ（対象ファイルパスを含む）と終了コード 1。出力 PDF は生成しない（既存ファイルは変更しない）
- **受け入れ基準**: (1) 存在しないファイル指定で終了コード 1、(2) 未対応モードの画像指定で終了コード 1、(3) 壊れた TIF の指定で変換開始前に終了コード 1、(4) 出力パスが既存かつ `--overwrite` 未指定で終了コード 1 かつ既存ファイル不変、(5) `--overwrite` 指定時は上書き成功、(6) 書き込み途中の失敗で既存の出力ファイルが破損しない

### FR-004: 自動テスト

- **機能名**: 自動テスト
- **概要**: 合成 TIF（Pillow で生成する小サイズ画像）を用いて FR-001〜FR-003 を検証する pytest テストを作成・実行する
- **入力**: なし（`uv run pytest -v` の実行）
- **出力**: `tests/test_make_ocr_pdf.py`、`tests/results/feat-002_test_result.txt`
- **受け入れ基準**: `uv run pytest -v` が全件 PASS（失敗 0 件・エラー 0 件。feat-001 の6件を含む）し、出力が `tests/results/feat-002_test_result.txt` に保存されている

## 4. 非機能要求

- **パフォーマンス**: 原本TIF 84 ファイルの一括変換が 10 分以内に完了する（本環境の実測で判定）
- **対応環境**: feat-001 で構築した uv 環境。GPU 不要（CPU のみで動作する）
- **信頼性**: 入力 TIF への書き込みを行わない（読み取り専用）。変換途中で失敗した場合、出力パスに不完全な PDF を残さない
- **出力サイズ**: 84 ページの PDF が 1GB 以下である
- **セキュリティ**: 該当なし

## 5. 制約条件

- **使用必須**: uv（環境管理）、`img2pdf==0.6.3`（PDF 生成。新規導入）、`pillow==12.3.0`（TIF 読込・画像変換。mineru の推移的依存として導入済みの版を明示固定）、`pypdf==6.16.1`（テストでの PDF 検証。dev 依存。mineru の推移的依存として導入済みの版を明示固定）
- **バージョン適合**: pillow / pypdf の固定版は現行 `uv.lock` の解決結果と同一で、mineru 3.4.4 の要求（`pillow>=11.0.0`、`pypdf>=5.6.0`）を満たす
- **使用禁止**: 入出力パス・パラメータのハードコード（CLI 引数 argparse で受け取る。CLAUDE.md「コーディング規約」）
- **ネットワーク**: `uv sync` 時に PyPI へのアクセスが必要（img2pdf の取得。スクリプト実行時は不要）
- **スコープ外**: OCR の実行、MinerU モデルのダウンロード、章とファイルの対応表の管理（対応は利用者の呼び出し時指定に委ねる）
- **テストデータ**: 原本TIF は git 管理外・リポジトリ外。2026-08-17 時点で 84 ファイル。既存の閲覧用 PDF（chap-00: 17ページ、chap-01: 64ページ、計81ページ）とファイル数が一致しないため、章の構成ファイルの決定は利用者が行う
