#### 1.11 ロードマップの次元と式（feat 案件の `roadmap.md` が対象に含まれる場合）

`CLAUDE.md`「パイプラインの切り方（feat 案件の必須手順）」の定義（最終出力の成分・入力の次元・ステージ表・想定値）に照らし、**式の入力と出力を実際に追って**次の 6 項目を確認する。文面に該当する語があるかではなく、式が繋がっているかを判定する。

1. **次元の接続**: 各ステージの出力の次元の式が、次のステージの入力の次元の式と一致する（単位あたりの次元と単位数の両方）。最初のステージの入力は「入力の次元」の実測値に、最後のステージの出力は「最終出力の成分」の次元数に一致する
2. **決める項の被覆**: 独立な成分のすべてが、いずれか 1 つのステージの「決める項」に現れる。従属な成分のすべてが独立な成分からの式を持つ。決める項が「無し」のステージは、手段の単体疎通か測るステージ（測る項が書かれている）のいずれかである
3. **想定値の導出**: 各ステージの想定値が `予想値 = 式（入力値）` の形で書かれ、式のすべての入力が「前のステージの実測」「測るステージの測る項」「ロードマップで固定した定数」のいずれかに由来する。由来の無い入力（推測、根拠の書かれていない目視の値、出所の無い定数）が式に入っている行、式そのものが無い行、式の形をしているが入力の由来が辿れない行は不適合
4. **測るステージの対応**: 想定値の式の入力に実測が無い量があるなら、それを測るステージがその量を使うステージより前に置かれ、測る項がその量と一致する
5. **要求の逆伝播**: 最終出力に対する要求（精度・区間の幅・件数・成立条件）が目標または最終出力の成分に書かれているなら、それが最終ステージから前のステージへ式で翻訳され、該当ステージの停止条件または想定値に現れている。翻訳されていない要求があれば不適合。要求が無いなら「要求は置かない」旨が書かれている（設計上の定数〔許容誤差等〕が最終出力に効いていない場合は、それが要求でないことが明記されている）
6. **幅の計算**: 幅が確率変数に対するものなら、分布・試行数・入力の区間の取り方が書かれている。決定的な量なら幅 0 の理由（乱数・外部状態・順序依存を含まないこと）が書かれている

重要度: 項目 3・5 の不適合は**高**（想定値が式から出ていない、または要求が翻訳されていないと、外れの判定と再検討〔`CLAUDE.md`「ロードマップの改訂（再計画）」〕が成り立たない）。項目 1・2・4・6 の不適合は**中**。

対象に feat 案件の `experiment_log.md` が含まれる場合（ステップ7 の差し戻し、実験ログの書き換えのレビュー）は、項目 3 として次を確認する: 直前予測が `roadmap.md` の当該ステージの想定値の式に前のステージの実測を代入した値であり、式に無い項目や幅の無い点予測が加えられていないこと。不適合は**高**。
