# feat-008 要求仕様書: MinerU 出力の HTML 表を Markdown パイプテーブルに変換

## 1. プロジェクト概要

- **何を作るのか**: MinerU が出力した Markdown 内の HTML 表（`<table>…</table>`）を GFM パイプテーブルに変換する CLI スクリプト `scripts/html_table_to_md.py`。および `scripts/ocr_dir.py` の一括パイプラインへの組み込みと、既存の最終成果物への適用
- **なぜ作るのか**: CommonMark では HTML ブロック内の `$…$` が数式として解釈されないため、VS Code のプレビューで表内の数式（chap01 表 1.1 / 1.2）が LaTeX ソースのまま表示される（ユーザー報告 2026-08-24。詳細は `README.md`）
- **誰が使うのか**: 本リポジトリの開発者（ユーザーおよび Claude Code）
- **どこで使うのか**: ローカルマシン（feat-001 の uv 環境。GPU・ネットワーク不要）

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| HTML 表 | Markdown ファイル中の、`<table` で始まり `</table>` で終わる文字列。MinerU 3.4.4 は表を 1 行の HTML 表として出力する |
| 表行 | Markdown ファイルの 1 行のうち、先頭・末尾の空白を除いた文字列が `<table` で始まり `</table>` で終わる行（= HTML 表が 1 行で完結している行） |
| 単純表 | 次の条件をすべて満たす HTML 表: (a) 表タグ（`<` の直後にタグ名 `table` `thead` `tbody` `tr` `td` `th` のいずれか（大文字小文字不問、`/` 付きの終了タグを含む）が続き `>` で閉じる文字列）に属性がない、(b) 表タグの外側のテキストは `td` / `th` の内側にのみ存在する（`tr` 直下や `table` 直下に空白以外のテキストがない）、(c) セルのテキストに表タグ以外の HTML タグ形式の文字列（正規表現 `</?[A-Za-z]+(\s[^<>]*)?>`。`<br>` `<b>` `<sup>` を含む）を含まない、(d) 行数 1 以上、(e) 全行の列数が同一で 1 以上、(f) どのセルにも `|`（U+007C）を含まない。表タグに該当しない `<`（`$a<b$` のような数式中の不等号）はセルのテキストとして保持する |
| パイプテーブル | GFM（GitHub Flavored Markdown）の表記法による表。1 行目がヘッダ行、2 行目が区切り行（`| --- | --- |`）、3 行目以降がデータ行 |
| 変換 | 表行 1 行を、その HTML 表と同じセル内容を持つパイプテーブル（複数行）に置き換えること |
| スキップ | 表行のうち単純表でないもの、および表行でない `<table` を含む行（複数行にまたがる HTML 表）を変換せずそのまま残すこと |
| 正規化済み md | `scripts/normalize_punct.py` 適用後の Markdown（`{BASE}/ocr/mineru-full/chapNN/run-NN-normalized/chapNN_gray300.md`） |
| final | 最終成果物ディレクトリ `{BASE}/ocr/final/chapNN/`（feat-005） |

`{BASE}` = `/home/sakagawa/work/Pattern_Recognition_and_Machine_Learning`（CLAUDE.md と同一）。機能設計書・コード内でも上記と同じ用語を使う。

## 3. 機能要求一覧

### FR-001: HTML 表変換スクリプト

- **機能名**: HTML 表変換スクリプト
- **概要**: 入力 Markdown ファイル（1 個以上）の各表行を変換し、指定ディレクトリへ同名で出力する CLI。単純表でない表はスキップして警告を出す
- **入力**: Markdown ファイルのパス列（UTF-8）、出力ディレクトリ（`-o`）、上書き許可（`--overwrite`）
- **出力**: 出力ディレクトリ内の変換済みファイル（入力と同じベース名）。標準出力へファイルごとの変換件数・スキップ件数と合計。標準エラーへスキップした表ごとの警告（ファイル名・行番号・理由）
- **受け入れ基準**: (1) 単純表である表行がすべてパイプテーブルに置き換わり、セルのテキスト（先頭・末尾の空白を除き、HTML 文字参照を復元したもの。数式中の `<` を含む）が行・列の順序を保って一致する、(2) 表行以外の行は改行コード（LF / CRLF）を含めてバイト単位で不変（変換したパイプテーブルの直前・直後の行が空行でない場合に空行を 1 行挿入することのみ例外とする）、(3) 単純表でない HTML 表はスキップされ元の行が不変のまま残り、標準エラーに理由が出力される、(4) 変換件数・スキップ件数が標準出力に出力される、(5) 入力ファイルは変更されない、(6) スキップがあっても終了コードは 0

### FR-002: 入力検証とエラー処理

- **機能名**: 入力検証とエラー処理
- **概要**: 不正入力の事前検出と、出力の意図しない上書きの防止（feat-004 `normalize_punct.py` と同一方針）
- **入力**: 存在しないファイルパス、UTF-8 としてデコードできないファイル、ベース名が重複する入力、既存の出力ファイル
- **出力**: 標準エラーへのメッセージ（対象パスを含む）と終了コード 1
- **受け入れ基準**: (1) 存在しないファイル指定で終了コード 1、(2) UTF-8 でないファイル指定で変換開始前に終了コード 1、(3) ベース名重複で終了コード 1、(4) 出力先に同名ファイルが既存かつ `--overwrite` 未指定で終了コード 1 かつ既存ファイル不変、(5) `--overwrite` 指定時は上書き成功（入力と出力が同一パスでも成功する = インプレース変換）

### FR-003: ocr_dir.py への組み込み

- **機能名**: 一括パイプラインへの組み込み
- **概要**: `scripts/ocr_dir.py` の処理（PDF 生成 → MinerU → 正規化 → 機械確認）の末尾に、正規化済み md への HTML 表変換（インプレース）を追加する
- **入力**: `ocr_dir.py` の既存 CLI 引数（新規オプションなし）
- **出力**: 正規化済み md がパイプテーブルに変換された状態になる。PASS 行のサマリに変換件数・スキップ件数が表示される
- **受け入れ基準**: (1) 機械確認が合格したディレクトリでのみ変換が実行される（機械確認は変換前の md に対して行う）、(2) 変換スクリプトが非 0 終了した場合、そのディレクトリは FAIL となり理由が表示される、(3) 変換スクリプトの標準出力から合計行（`total: N converted, M skipped in K files`）を読み取れない場合も FAIL となる、(4) スキップは FAIL の理由にならない（警告は標準エラーに表示する）、(5) 正規化済み content_list.json は無改変

### FR-004: 自動テスト

- **機能名**: 自動テスト
- **概要**: 合成テキストで FR-001〜FR-003 を検証する pytest テスト
- **入力**: なし（`uv run pytest -v` の実行）
- **出力**: `tests/test_html_table_to_md.py`（新規）、`tests/test_ocr_dir.py`（追記）、`tests/results/feat-008_test_result.txt`
- **受け入れ基準**: `uv run pytest -v` が全件 PASS（既存 56 件を含む）し、出力が結果ファイルに保存されている。FR-003 の変換実行部は `subprocess.run` を差し替えたテストで「成功時の件数取得」「非 0 終了で FAIL」「合計行なしで FAIL」「警告ありでも成功」を検証する

### FR-005: 既存の最終成果物への適用と normalized md の復旧

- **機能名**: 既存データへの適用と復旧
- **概要**: HTML 表を含む既存の md（chap01・chap06。final と run-01-normalized の両方、計 4 ファイル）に FR-001 の変換をインプレース適用する。あわせて、feat-005 の final 構築後に外的要因で損傷した run-01-normalized の md 2件（chap06: 末尾49行欠落、chap07: 先頭28行欠落。調査記録は案件 README「実装中の発見」）を、正である final の md をコピーして復旧する
- **入力**: `{BASE}/ocr/final/chap01/chap01_gray300.md`、`{BASE}/ocr/final/chap06/chap06_gray300.md`、`{BASE}/ocr/mineru-full/chap01/run-01-normalized/chap01_gray300.md`、`{BASE}/ocr/mineru-full/chap06/run-01-normalized/chap06_gray300.md`（以上、変換対象）、`{BASE}/ocr/final/chap07/chap07_gray300.md`（復旧のコピー元）、`{BASE}/ocr/mineru-full/chap07/run-01-normalized/chap07_gray300.md`（復旧のコピー先）
- **出力**: 変換済み md 4 ファイル（同一パス）と、final からのコピーで復旧された run-01-normalized の md 2 ファイル（chap06 は変換済み final のコピーで復旧を兼ねる）
- **受け入れ基準**: (1) 変換対象のうち final 側 2 ファイルの変換 = 表の件数（chap01: 2、chap06: 1）、スキップ = 0、(2) 変換・復旧後に final・run-01-normalized の全 md で `<table` を含む行が 0 行、(3) 全8章で final と run-01-normalized の md がバイト同一（`cmp`）、(4) 本手順で書き込む対象は md のみとし、final の chap01・chap06 の content_list.json・images/ について適用前後の `sha256sum` 一致を記録で確認する、(5) ユーザーが VS Code プレビューで chap01 の表 1.1 / 1.2 のセル内数式が描画されることを確認する（手動テスト）

## 4. 非機能要求

- **パフォーマンス**: 1 ファイル（約 0.3MB）の変換は 5 秒以内
- **対応環境**: feat-001 の uv 環境。GPU・ネットワークアクセス不要
- **信頼性**: 書き込み途中の失敗で既存の出力ファイルを破損しない（原子的書き込み）。変換できない表は壊さずスキップする
- **セキュリティ**: 該当なし

## 5. 制約条件

- **使用必須**: uv、Python 3.12 標準ライブラリのみ（新規ライブラリの追加はしない。テストは既存の pytest 9.1.1）
- **使用禁止**: 入出力パスのハードコード（argparse で受け取る）。`html.parser` のような寛容な HTML パーサ（`$a<b$` のような数式中の `<` をタグと誤認するため。設計書 ADR 参照）。`Path.read_text` による本文読み込み（改行コードを変換するため。`read_bytes().decode("utf-8")` を使う）
- **スコープ外**: content_list.json の `table_body` の変換、`colspan` / `rowspan` / 入れ子表 / 複数行にまたがる HTML 表の変換（スキップ対象）、セル内 `|` のエスケープ（スキップ対象）、MinerU の再実行。既存データへの HTML 表変換の適用対象は chap01・chap06 のみ（他章は HTML 表が 0 件のため対象外）。**ただし FR-005 の chap07 run-01-normalized md の復旧（final からのコピー）はスコープに含む**
- **テストデータ**: 既存の OCR 成果物は git 管理外・リポジトリ外
