  2. 厳密準拠: 本書の変更後全文どおりに置換する。本書に書かれていない変更・整形・改善は一切禁止
  3. 想定外事象（§2 の事前検査の不一致、変更前全文の不一致、置換後の検証の不一致）が起きたら、その場で回避せず直ちに中断し、何が起きたか・どこまで適用したかを報告する。復帰先は「ステップ2 の調査 → `README.md` / `design.md` の更新 → ステップ4 のレビュー」
  4. 検証: §5 の S2 を実施し結果を報告する。テスト実行は不要（§7）
  5. 禁止事項: git 操作（add / commit / push）、`BACKLOG.md` / `CHANGELOG.md` / `README.md`（ルート）/ `docs/PROJECT_KNOWLEDGE.md` の更新。`CLAUDE.md` は本書に変更対象として明記したファイルであるため更新してよい（本書に記載のない変更は行わない）
  6. 報告形式: 変更ファイル一覧、適用した U の一覧、§5 の検証結果、想定外事象の有無
- 反映後の `git diff` の検証（§5 の S2-1〜S2-4 の再実行と目視）は Claude Code 本体が行う
- 変更方式はすべて**行内置換**または**1行挿入**である。全置換は行わない（後処理なし）
- 反映元の文面をそのまま使うものと、honOCR 向けに読み替えるものを各 U に明記する。読み替えは U7 の1件だけで、変更前・変更後と、README §5.5 (d) を損なわない理由を U7 に書く
