## 3. feat-017 の修正が原因ではないことの根拠（2026-09-01）

ユーザーからは「おそらく今回の修正の悪影響」との報告を受けたが、調査の結果**無関係**である。
根拠は次の3点である。

1. **`content_list.json` にも同じ「なんていいう」が2件含まれている。**
   `apply_fixes.py` は md のみを対象とし `content_list.json` を変更しない（feat-010 の設計）。
   さらに chap03 の `content_list.json` の SHA-256 は feat-017 の実装前に記録した基準値
   `d269034e9b54fd993a3d4f9e092421a3b7974d3441519eb389678055e5103220` から**変わっていない**。
   したがってこの誤読は feat-017 の適用前から存在した
2. feat-017 で適用した `new` は `3.5n に近づいていく、なんていうことはない` および
   `n/2 に近づいていく、なんていうことはない` であり、
   **「なんていいうことはありません」を生成しえない**
3. feat-017 の `old`（`3.5n に近づいていく、なんということはない` 等）は本件の文
   （読点がなく、語尾が「ありません」）と**一致しない**ため、そもそもマッチしていない

## 4. 原本での確認（2026-09-01）

原本 TIF `{BASE2}/dewarping/chap03/out/page-19_1L.tif` の該当領域
（`content_list.json` index 558 の `bbox` = `[127, 542, 923, 654]`）を切り出して目視確認した。
原本の記述は次のとおりである。

```

散は大きくなります（→ 3.4.5 項 (p.97)「独立なら、足し算の分散は分散の足し算」）。n を大きくしても、
サイコロを n 回ふった合計値が 3.5n に近づいていくなんていうことはありませんし、コインを n 回投
げたときに表が出る回数が n/2 に近づいていくなんていうこともありません*15。それぞれ、擬似乱数
列（→ 7 章 (p.253)）を用いた計算機実験の結果を図 3.15 と図 3.16 に示します。
```

### 5.1 feat-017 で見落とした理由（再発防止）

feat-017 の調査では**「なんという」という文字列だけを検索した**ため、同じ語の別バリアントである
「なんていいう」を発見できなかった。両者は同一ページ（`page-19_1L.tif`）の隣接する段落にあった。

**教訓**: 語彙単位の誤読を調査するときは、誤読された文字列そのものだけでなく、
**正しい語（本件では「なんていう」）を起点に、その表記ゆれ・脱落・挿入のバリアントを
正規表現で網羅的に洗い出す**。本案件の §6 ではこの方法で調査した。
