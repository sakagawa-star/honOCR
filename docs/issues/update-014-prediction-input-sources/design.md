## 6. 設計判断の記録

| # | 判断 | 理由 |
|---|---|---|
| 1 | 由来を 3 種の閉じた列挙に固定し、入力ごとに名指しさせる（V1・V2） | README §5 判断 A・C。「辿れればよい」という読み替えを書き手と検査者の両方が行った。名指しの有無なら機械的に判定できる |
| 2 | 調査で数えた値を「定数」に含め、前提の表に典拠つきで置く（V1・V2） | README §5 判断 B。4 種目を足すと「調査」のラベルで推測が通る経路が残る。前提の表の典拠（いつ・何に・どの規則を当てて数えたか）で数えた値と推測を区別する |
| 3 | 1.11 の不適合の例示（推測・目視・出所の無い定数）は残し、判定の基準を先に書く | 例示を消すと推測の排除という元の目的が文面から消える。「例示に当たらなければ適合」と読まれないよう、判定は名指しの有無だと先に明記する |
| 4 | `CLAUDE.md` と 1.11 を対で直す | Opus の指摘（検査だけ厳しくすると書き手が置き場に困る）。README §1.3 |
| 5 | 「出所が辿れること」を適合の条件から外すのではなく「それだけでは適合としない」と書く（V2） | codex-01 高1。出所を条件から外すと「出所の無い定数は不適合」と矛盾する。名指しと出所の要件の両方を要求する |
| 6 | 反映前の基準の保存を §3 の手順 0（本体）として書く | codex-01 中1。§4 に置くだけでは基準の取得時点が手順に無い（update-013 では本体が手順外で行っていた） |
