## 1. 経緯・目的

### 1.1 契機

feat-025 `roadmap.md` 第2版（update-013 後の全面改稿。Codex 4 回で収束）の人レビュー前の確認で、Claude Code（Fable）が S1・S2 の想定値の入力「調査時点の実測 §4.3」が `docs/REVIEW_CRITERIA.md` 1.11 項目 3 の由来 3 種（前のステージの実測／測るステージの測る項／ロードマップで固定した定数）のどれでもないと指摘した（第1版でも指摘したが未対応。Codex は第1版 11 回・第2版 4 回の計 15 回で一度も指摘していない）。ユーザーが右ペインの Claude Code（Opus 5）に原因を問い、Opus が次の説明を返した（2026-09-09 12:45。要旨）。

**なぜ書き手（Opus）がそうしたか**: `CLAUDE.md` の想定値の項は入力の由来を「前のステージの実測と定数」の 2 種で書いている。S1 はパイプラインの最初のステージで前のステージが無い。98 は調査で数えた値だが、「定数」を `z = 1.96` のような設計上の決め打ちの値と解釈したため、測った値を定数と呼ぶのは不正確だと考え、規定に無い第 3 のラベル「調査時点の実測」を作った。「出所を書けば由来は辿れる」と要求を読み替えていた。**最初のステージには必ず前のステージが無いので、規定に置き場が無い限りすべての feat 案件の M1 で同じことが起きる**（S2 の 414 も同じ）。

**なぜ Codex が通したか**: 1.11 項目 3 は前半で 3 種の閉じた列挙を書き、後半の不適合の例示を「由来の無い」「根拠の書かれていない」「出所の無い」「辿れない」と**根拠の有無**で書いている。前半で読めば不適合、後半で読めば §4.3 に出所があるので適合。Codex は後半で読んだ（15 回で一度も出ていないので偶然の見落としではなく文面の問題）。書き手と検査者が同じ読み替えをした。

**Claude Code（Fable）の補足**: `CLAUDE.md` の想定値の項は由来を **2 種**（前のステージの実測・定数）、1.11 項目 3 は **3 種**（測る項を含む）と、同じ規定の中で数が違う。

### 1.2 目的

1. 想定値の式の入力の由来を、`CLAUDE.md` と 1.11 の両方で同じ **3 種**に固定し、入力ごとにどれかを名指しさせる
2. ロードマップ作成時の調査で数えた値の置き場を定める: 前提の表に**定数**として置き、いつ・何に・どの規則を当てて数えたかを典拠に書き、式からは前提の番号で参照する。最初のステージのように前のステージが無い場合はこれを使う
3. 1.11 項目 3 の判定を「由来が辿れるか」から「3 種のいずれかが名指しされているか」に変える。出所が辿れることだけでは適合とせず、3 種の名指しと種別ごとの出所の要件（前のステージの実測は出所のステージ、測る項は測るステージ、定数は典拠）の両方を要する。3 種以外のラベルは値が正しく出所が辿れても不適合

規定を作った理由（update-009）は feat-024 の「予備目視 30 件からの推測」を式の入力から排除することだった。「調査」というラベルは数えた値と印象からの推測を区別できないので、ラベルではなく「前提の表の定数（典拠つき）」という置き場で区別する。

### 1.3 採らなかった案と不採用の理由

| 案 | 不採用の理由 |
|---|---|
| 由来に 4 種目「調査で実測した値」を足す | 「調査」の中で数えた値と印象からの推測を分ける文言が要り、feat-024 と同じラベルで推測が通る経路が残る。既存の「定数」に典拠つきで収める方が閉じた列挙を保てる |
| 1.11 項目 3 だけを直す（`CLAUDE.md` は変えない） | Opus の指摘どおり、検査を厳しくするだけでは書き手が置き場に困り、同じことが起きる。置き場（`CLAUDE.md`）と検査（1.11）を対で直す |
| `CLAUDE.md` だけを直す | 1.11 の不適合の例示が根拠の有無で書かれたままだと、Codex は引き続き「辿れれば適合」と読む |
| feat-025 の `roadmap.md` を本案件で直す | 元案件側で扱う規定。本案件の完了後、右ペインの Opus がユーザーの指示で 98・414 を前提の定数に置く（規定の改訂に関係なく必要） |
