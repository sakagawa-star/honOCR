# feat-014 要求仕様書: Q&A コラム見出しの「？」アイコン分離8件の修正

## 1. プロジェクト概要

### 何を作るのか

『プログラミングのための確率統計』の既存の修正定義ファイル **6件**
（`{BASE2}/ocr/fixes/chap01.json`・`chap02.json`・`chap03.json`・`chap04.json`・
`chap05.json`・`chap06.json`。すべて既存ファイルへの**追記**であり新規作成はない）に
修正を計8件追記し、`apply_fixes.py`（feat-010）で既存成果物に適用したうえで、
`build_final.py`（feat-012）で `final/chap01`〜`final/chap06` のうち該当6章を再構築する。

**リポジトリ内のコード（`scripts/`）とテストコード（`tests/test_*.py`）は一切変更しない。**
本案件で作成・更新する成果物は次の3つに限られる。

1. リポジトリ外の修正定義ファイル6件への追記
2. それを適用したリポジトリ外の既存成果物（該当6章の `{NORM_NN}/` と `{FINAL_NN}/`）
3. リポジトリ内の案件ドキュメント（`docs/issues/feat-014-column-heading-icon/`）、
   `docs/BACKLOG.md` / `docs/CHANGELOG.md` / `docs/PROJECT_KNOWLEDGE.md` の完了処理、および
   テスト結果の記録 `tests/results/feat-014_test_result.txt`（新規作成。
   CLAUDE.md「テスト」のルールで必須）

**`CLAUDE.md` は更新しない**（update-003 で確定した非対称ルール: CLAUDE.md 本体の変更は
update 案件でのみ行う）。`docs/PROJECT_KNOWLEDGE.md` の更新内容は機能設計書 §11 で定める。

### なぜ作るのか

本書の Q&A コラム見出しは、原本では「**？アイコン ＋ 通し番号 ＋ 質問文**」という体裁で
組まれている。MinerU の layout 解析はこの ？アイコンを見出しテキストから切り離し、
独立した画像ブロック（`type: "image"`）として出力することがあり、その結果 Markdown 上に
アイコンだけを切り出した画像参照行 `![](images/{64桁hex}.jpg)` が現れる。

この現象が 6章8件発生している（案件 README.md §2。原本 TIF で8件すべて確認済み）。
内訳は次の2型である。

- **A 型3件**: 見出しテキストに「?」が無く、アイコンが画像としてのみ存在する（**欠落**）
- **B 型5件**: 見出しテキストに「?」があり、加えて画像にもアイコンが出ている（**重複**）

A 型は原本にある情報が Markdown から失われており、B 型は原本に1個しかないアイコンが
2つの表現に二重化している。いずれも本プロジェクトのゴール「入力への忠実な OCR」に反するため、
修正する。

### 誰が使うのか

本プロジェクトのユーザー。成果物（`{BASE2}/ocr/final/chapNN/chapNN_gray300.md`）を
LLM に読ませて学習に用いる。

### どこで使うのか

`docs/TECH_STACK.md` に定義された既存環境（Ubuntu 24 系 / Python 3.12.3 / uv）。
新規のライブラリ・モデル・ネットワークアクセスは追加しない。

## 3. 機能要求一覧

### FR-001: 修正定義ファイル6件への修正追記

- **機能名**: `{BASE2}/ocr/fixes/chap01.json`〜`chap06.json` への修正計8件の追記
- **概要**: 8件の分離を `fixes/template.json` の書式に従って定義し、各ファイルの
  `fixes` 配列の**末尾に追記**する
- **入力**: 案件 README.md §2 で確定した対象8件
- **出力**: 修正定義ファイル6件（いずれも既存ファイルの更新。UTF-8・JSON）
- **受け入れ基準**:
  1. `fixes/README.md`・`fixes/template.json` の書式に従い、`id` / `reason` / `old` / `new` の
     4キーをすべて文字列で持つ fix が追加され、追記後の `fixes` 配列の要素数が
     次表のとおりになる

     | ファイル | 既存 | 追加 | 追記後 |
     |---|---|---|---|
     | `chap01.json` | 1 | 1 | 2 |
     | `chap02.json` | 2 | 2 | 4 |
     | `chap03.json` | 5 | 1 | 6 |
     | `chap04.json` | 1 | 1 | 2 |
     | `chap05.json` | 1 | 2 | 3 |
     | `chap06.json` | 5 | 1 | 6 |
     | **合計** | **15** | **8** | **23** |

  2. 追加する fix の `id` は次の8つとする（章内の既存 ID の続き番号）:
     `chap01-002`・`chap02-003`・`chap02-004`・`chap03-006`・`chap04-002`・
     `chap05-002`・`chap05-003`・`chap06-006`
  3. 既存15件の `id` / `reason` / `old` / `new` を1文字も変更しない
  4. `apply_fixes.py` の `validate_fixes` が6ファイルすべてでエラーを1件も出さない
  5. 適用**前**の各 `{NORM_NN}/chapNN_gray300.md` において、新規8件それぞれの
     `count(old) == 1` である
  6. 適用**後**の各 `{NORM_NN}/chapNN_gray300.md` において、**当該ファイルの全 fix**
     （既存＋新規、計23件）について `count(old) == 0` かつ `count(new) == 1` である（最終不変条件）
  7. 各 `reason` に、(a) 対象が Q&A コラム見出しの ？アイコンであること、(b) 原本 TIF 名と
     原本で確認した事実、(c) A 型か B 型か、を日本語で記述する
  8. ファイルはリポジトリに置かず、コミットもしない（feat-010 の運用）

### FR-002: アイコン画像行の削除（8件）

- **機能名**: md からのアイコン画像行の削除
- **概要**: 案件 README.md §2 の8箇所について、アイコンだけを切り出した画像参照行と、
  それに続く空行1行を削除する
- **入力**: 各 `{NORM_NN}/chapNN_gray300.md`（適用前）
- **出力**: 同（適用後）
- **受け入れ基準**:
  1. 適用後の md に、対象8件の画像ファイル名（案件 README.md §2.2 の64桁 hex）を
     含む行が**1つも存在しない**（各章で `count("{64桁hex}") == 0`）
  2. 各章の md 内の画像参照行数（`![](images/` で始まる行）が次表のとおり減る

     | 章 | 適用前 | 適用後 | 減少 |
     |---|---|---|---|
     | chap01 | 22 | 21 | 1 |
     | chap02 | 23 | 21 | 2 |
     | chap03 | 48 | 47 | 1 |
     | chap04 | 92 | 91 | 1 |
     | chap05 | 76 | 74 | 2 |
     | chap06 | 17 | 16 | 1 |

  3. 件数はすべて Python の `str.count()` による**出現回数**で数える。
     `apply_fixes.py` の不変条件と同じ数え方であり、行数ではない。**`grep -c` を使わない**
     （画像参照行数の計数は行単位の集計であり、`str.split("\n")` した各行に対する
     `str.startswith("![](images/")` の判定で数える）

### FR-003: A 型3件の見出しへの「? 」の補完

- **機能名**: 見出しテキストに欠落した「?」の補完
- **概要**: A 型3件の見出し行の先頭に、半角 `?` と半角空白1つを補う
- **入力**: 各 `{NORM_NN}/chapNN_gray300.md`（適用前）
- **出力**: 同（適用後）
- **受け入れ基準**:
  1. 適用後の md に、次の3行がそれぞれ**ちょうど1回**出現する

     ```
     ## ? 1.2 そんなにたくさん会場を用意しなくても 18 会場で十分なのでは？
     ```

     ```
     ## ? 2.6 むずかしすぎてもうだめです……
     ```

     ```
     ## ? 5.2 なぜそんなふうにまとめて書けるのかわかりません。
     ```

  2. 適用後の md に、補完前の見出し行（`## 1.2 そんなにたくさん…` / `## 2.6 むずかしすぎて…` /
     `## 5.2 なぜそんなふうに…`）が**1つも存在しない**
  3. 補うのは**半角 `?` ＋ 半角空白1つ**である（全角「？」ではない。
     既存の Q&A コラム見出し44件と同じ表記。案件 README.md §4）
  4. B 型5件の見出し行は**1文字も変更しない**
  5. 確率統計 final 全10章の md における Q&A コラム見出し（`?` を持つもの）の
     表記別件数が、適用後に次のとおりになる。計数は各章の md を行に分割し、
     正規表現 `^## (\?)([ 　]*)([0-9A-C]+\.[0-9]+)(?=[ 　])` に一致する行を
     第2グループ（`?` と番号の間の区切り）の値で分類して数える

     | `?` と番号の間の区切り | 適用前 | 適用後 |
     |---|---|---|
     | 半角空白1つ（`## ? N.M`） | 44 | 47 |
     | 区切りなし（`## ?N.M`） | 8 | 8 |
     | 全角空白（`## ?　N.M`） | 0 | 0 |
     | **合計** | **52** | **55** |

     増える3件は A 型3件であり、いずれも「半角空白1つ」に分類される。
     この計数は `## 2.1 各県の土地利用` のような通常の節見出し（`?` を持たない）を
     含まない

  6. 基準1に挙げた補完後の3行と、基準2に挙げた補完前の3行は、いずれも
     **行全体との完全一致**で数える（`str.split("\n")` した各行との `==` 比較）。
     部分一致で数えると、補完後の行は補完前の行を部分文字列として含まないため
     問題ないが、逆に節見出しとの取り違えを招くため用いない

## 5. 制約条件

- **MinerU を再実行しない**。OCR 結果は同一入力に対して変わらず、10章で約35分の実行コストに
  見合わない（feat-013 ADR-3・feat-015 ADR-4・feat-016 ADR-2・feat-017 ADR-4・
  feat-019 ADR-3 と同じ判断）
- **`normalize_punct.py` を再実行しない**。feat-013 で適用済みであり、本案件は字形正規化
  テーブルを変更しないため結果は変わらない
- **`final/` を直接編集しない**。final は `run-NN-normalized/` からのコピーであり、コピー元を
  更新しないと次回の final 再構築で変更が失われる（feat-013 の既存方針）
- **`content_list.json` を修正しない**。MinerU のスキーマを維持する既存ポリシー（feat-010）。
  結果として md と json でアイコンブロックの有無が食い違うが、これは feat-013 §6.1・
  feat-015・feat-016 §8・feat-017 design.md §8・feat-019 design.md §8 で許容済みの既知事項である
- **`images/` のアイコン画像ファイル8個を削除しない**。`build_final.py` の検証3が
  `content_list.json` の `img_path` 集合と `images/` の**完全一致**を要求するため、
  `content_list.json` を無改変にする以上、画像実体も残す必要がある（機能設計書 §8・ADR-3）
- **既存の Q&A コラム見出しの表記ゆれ（`## ?N.M` 8件）を統一しない**（スコープ外。§7）
- **`CLAUDE.md` を変更しない**（update-003 の非対称ルール）
- 修正定義ファイルの実体は**コミット禁止**（書籍本文を含むため）
- 本案件は**コード変更を含まない**。作業中にコード変更が必要と判明した場合は中断して報告する
