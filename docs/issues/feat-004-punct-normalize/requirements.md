# feat-004 要求仕様書: 句読点正規化の後処理と再判定

## 1. プロジェクト概要

- **何を作るのか**: MinerU 出力（Markdown・JSON）内の句読点「、」「。」を原本のスタイル「，」「．」へ置換する CLI スクリプトと、正規化後の出力に対する本文品質の再判定
- **なぜ作るのか**: feat-003 の品質判定で、句読点スタイルの系統的な揺れが原因で本文項目が不合格（7/10）となり No-Go だったため。この単一原因を後処理で除去し、フェーズ4（全章の本処理）へ進めるかを決め直す
- **誰が使うのか**: 本リポジトリの開発者（ユーザーおよび Claude Code）
- **どこで使うのか**: ローカルマシン（feat-001 の uv 環境。GPU 不要）

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 正規化 | ファイル内容中の「、」(U+3001) を「，」(U+FF0C) へ、「。」(U+3002) を「．」(U+FF0E) へ置換すること。それ以外の変更は行わない |
| run-02 出力 | feat-003 で生成した MinerU 出力（`.../out/ocr/mineru-trial/run-02/chap-01_gray300/hybrid_auto/` 配下） |
| 再判定 | feat-003 の criteria と同一のサンプル・判定規則・合格ラインで、正規化後の出力に対して本文品質（項目B）を判定し直すこと |
| criteria 文書 | `experiments/renorm-quality/criteria.md`。実行前に Codex レビューで収束させ固定する（criteria lock） |

機能設計書・コード内でも上記と同じ用語を使う。

## 3. 機能要求一覧

### FR-001: 句読点正規化スクリプト

- **機能名**: 句読点正規化スクリプト
- **概要**: 入力ファイル（1個以上）の内容を正規化し、指定ディレクトリへ同名で出力する CLI
- **入力**: テキストファイルのパス列（UTF-8。Markdown / JSON を想定）、出力ディレクトリ（`-o`）
- **出力**: 出力ディレクトリ内の正規化済みファイル（入力と同じベース名）。標準出力へファイルごとの置換件数
- **受け入れ基準**: (1) 出力ファイルで「、」「。」の出現数が 0 になり、置換件数分だけ「，」「．」が増える、(2) 置換対象以外のバイト列が変化しない、(3) 入力ファイルは変更されない

### FR-002: 入力検証とエラー処理

- **機能名**: 入力検証とエラー処理
- **概要**: 不正入力の事前検出と、出力の意図しない上書きの防止（feat-002 と同じ方針）
- **入力**: 存在しないファイルパス、UTF-8 としてデコードできないファイル、既存の出力ファイル
- **出力**: 標準エラーへのメッセージ（対象パスを含む）と終了コード 1
- **受け入れ基準**: (1) 存在しないファイル指定で終了コード 1、(2) UTF-8 でないファイル指定で変換開始前に終了コード 1、(3) 出力先に同名ファイルが既存かつ `--overwrite` 未指定で終了コード 1 かつ既存ファイル不変、(4) `--overwrite` 指定時は上書き成功

### FR-003: 自動テスト

- **機能名**: 自動テスト
- **概要**: 合成テキストで FR-001・FR-002 を検証する pytest テスト
- **入力**: なし（`uv run pytest -v` の実行）
- **出力**: `tests/test_normalize_punct.py`、`tests/results/feat-004_test_result.txt`
- **受け入れ基準**: `uv run pytest -v` が全件 PASS（既存16件を含む）し、出力が結果ファイルに保存されている

### FR-004: 再判定

- **機能名**: 再判定
- **概要**: run-02 出力の Markdown と content list JSON を正規化し、criteria 文書に従って本文品質を再判定して Go/No-Go を決める
- **入力**: 正規化後の Markdown・content list JSON、原本ページ画像、feat-003 の判定記録（同一サンプルの特定に使用）
- **出力**: 実験ログ（`experiments/renorm-quality/experiment_log.md`。予測・実測・照合・判定表・Go/No-Go）
- **受け入れ基準**: criteria 文書のすべての判定項目について実測値が記録され、Go/No-Go が事前定義どおりに決定されている（事後解釈をしない）

## 4. 非機能要求

- **パフォーマンス**: 正規化は run-02 出力（Markdown 約0.3MB・JSON 数MB）に対し10秒以内
- **対応環境**: feat-001 の uv 環境。GPU・ネットワークアクセス不要
- **信頼性**: 入力ファイルへの書き込みを行わない。書き込み途中の失敗で既存の出力ファイルを破損しない
- **セキュリティ**: 該当なし

## 5. 制約条件

- **使用必須**: uv、Python 標準ライブラリのみ（新規ライブラリの追加はしない。テストは既存の pytest を使う）
- **使用禁止**: 入出力パスのハードコード（argparse で受け取る）
- **実験プロトコル**: CLAUDE.md「実験・検証の進め方」を厳守（criteria lock → 直前予測 → 照合 → 事後解釈禁止）
- **スコープ外**: 句読点以外の OCR 誤り訂正（異体字「乘」を含む）、MinerU の再実行、chap-00 の処理、フェーズ4本処理
- **テストデータ**: run-02 出力は git 管理外・リポジトリ外
