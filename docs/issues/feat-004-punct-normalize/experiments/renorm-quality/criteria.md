## 2. 判定項目・合格ライン

### 項目B′: 正規化後の日本語本文の再現性（再測定）

- **サンプル**: feat-003 の項目B と**同一の10段落**（feat-003 実験ログの判定表に記録済み。P1〜P10）。サンプルの取り直しはしない
- **対象データ**: 正規化後の Markdown / content list JSON（run-02 出力を FR-001 のスクリプトで正規化したもの）
- **判定規則**: feat-003 criteria.md 項目B と同一（段落の単位、対応付け、無視する差分、誤りカウント規則、段落あたり誤り2文字以下で合格）。**10段落すべてを原本と突き合わせて再評価し、残っている誤りを種類を問わずすべて数える**（句読点以外の誤りも判定対象。feat-003 で不合格だった段落についても全誤りを数え直す）
- **合格ライン**: 合格 **9/10 以上**（feat-003 と同一）
- **既知の残存誤り（feat-003 判定時に記録済み。予測の参考情報であり、判定はこの表に依存せず再評価で行う）**: P5 = 半角「;」→全角「；」1文字、P9 = 「ようやく」→「よやく」1文字脱落。P1・P7・P8・P10 の句読点置換は正規化で解消される見込み

### 項目A・C の扱い（引き継ぎ）

- 正規化の置換対象は「、」「。」の2文字のみであり、項目A（数式）・項目C（ブロック順序）の判定内容に影響しない
- 引き継ぎの妥当性確認は、再判定の前に次の**機械確認アルゴリズム**で行う（対象: 正規化した2ファイルそれぞれ）:
  1. 正規化前後のファイルを UTF-8 でデコードし、コードポイント列の**長さが等しい**ことを確認する
  2. 各位置 i について、「前後で同一」「前が「、」(U+3001) かつ後が「，」(U+FF0C)」「前が「。」(U+3002) かつ後が「．」(U+FF0E)」のいずれかであることを確認する
  3. 上記以外の差分が1箇所でもある場合、長さが異なる場合、出力ファイルが欠落している場合は**引き継ぎ禁止**とし、実験を中断して報告する（A・C の再測定に切り替えるかは中断後に別途決める）
- 確認に合格した場合、項目A = 19/20 合格・項目C = 5/5 合格（feat-003 の結果）をそのまま引き継ぐ

### 総合 Go/No-Go

- 項目B′ が合格ライン以上 → **Go**（項目A・C は引き継ぎで合格済みのため）
- 項目B′ が合格ライン未満 → **No-Go**（さらなる対策の検討は別案件）
