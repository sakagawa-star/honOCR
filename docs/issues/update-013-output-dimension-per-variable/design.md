## 6. 設計判断の記録

| # | 判断 | 理由 |
|---|---|---|
| 1 | 次元を「変数ごとの成分の数」で定義し、独立／従属を廃止する（T2・R1〜R3） | README §5 判断 A・B。「式で決まるものは次元に数えない」という読みが、測定値を最終出力に格上げする経路になった |
| 2 | 「ステージの出力は最終出力の式の入力であって変数ではない」を規定と検査項目の両方に書く（T2・R2） | 三者が同じ取り違えをした。定義だけでは止まらず、否定形で書く |
| 3 | 式と次元の整合を検査項目 7 として加え、ステージ表の次元の式にも同旨を書く（T3・R5） | ユーザーの目的 (2)。S5 の入力 3 成分から式で出るのは 1 と 2 であり、この検査があれば 10 や 3 は通らなかった |
| 4 | 「決める項」を残し「このステージの出力が最終出力の式のどの入力になるか」に定義し直す（T4） | README §5 判断 E。リネージの記入欄として要る。「成分」の語を外し、入力・出力だけで書く |
| 5 | 例（推定件数 1 次元と区間 2 次元、3 個の測定値）を規定と検査項目に入れる | 抽象的な定義だけでは同じ誤りが再発した。ユーザーの定義の例（スカラー 1・行列 9・「1 次元と 2 次元」）をそのまま使う |
| 6 | 項目 7 の重要度を中とする | 項目 1（次元の接続）と同じ階層の検査。項目 3・5（高）は想定値の導出と要求の翻訳で、再検討の成立に直結する |
| 7 | 右辺・左辺、インターフェース等の語を使わない | README §1.4。入力と出力だけで書く（ユーザー 2026-09-09） |
