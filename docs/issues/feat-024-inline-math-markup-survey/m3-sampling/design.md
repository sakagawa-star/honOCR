## 10. 設計判断の記録（ADR）

### ADR-M3-1: 層ごとに**異なる乱数シード**を使う

- **採用**: 層 `G` = 20260908 / 層 `L` = 20260918 / 層 `C` = 20260928
- **却下**: 3 層で同一のシードを使う
- **理由**: 同一シードでも各層の抽出は当該母集団上で一様であり推定に支障は無いが、
  `random.Random(seed).sample` は同じ乱数列から添字を選ぶため、**層間で選ばれる位置のパターンが揃う**。
  層ごとに独立に引かれたことを明示するため、シードを分ける。値は本書で固定し、実行後に変更しない

### ADR-M3-2: 新規スクリプトを書かず、**既存 CLI の反復実行と標準コマンドの集計**で済ませる

- **採用**: `sample_candidates.py` と `locate_candidates.py` を層ごとに実行し、集計は `awk` 等で行う
- **却下**: 3 層をまとめて処理する新しいスクリプトを書く／集計スクリプトを新設する
- **理由**: 段3 の決める項は `n_i` と抽出の無作為性であり、**新しい手段は不要**である。
  手段を足せば `../roadmap.md` §5 の規則により**その手段の単体疎通の段が先に必要**になり、段が増える。
  集計は使い捨ての数え上げであり、再利用しないコードを増やさない

### ADR-M3-3: 標本 TSV と逆引き結果 TSV を**層ごとに分ける**（1 ファイルに統合しない）

- **採用**: 層ごとに 2 ファイル（合計 6 ファイル）
- **却下**: 3 層を 1 ファイルに統合する
- **理由**: `locate_candidates.py` は 1 入力 1 出力であり、統合には新しい手段（結合スクリプト）が要る（ADR-M3-2 と同じ理由）。
  段4 は 3 ファイルを順に読めばよく、統合の必要が無い

### ADR-M3-4: 実行の順序を**母集団の小さい層から**（`G` → `L` → `C`）とする

- **採用**: `G`（291）→ `L`（1,408）→ `C`（2,925）
- **却下**: 任意の順序
- **理由**: 順序を固定しないと、層ごとの予測をどの順で書くかが実行者の判断になる（`docs/DESIGN_STANDARD.md` 2.2 実装判断ゼロの原則）。
  小さい層から行えば、想定外の事象が最初の層で早く現れる
