## 1.1 プロジェクト概要

- **何を作るのか**: 母集団（4,624 件）から**層ごとに 50 件**を再現可能な無作為抽出で確定し、
  各標本について原本ページ（content_list のブロック、またはページ）を逆引きした一覧を作る
- **なぜ作るのか**: 段4（原本との突合）が判定する対象を確定するため。
  本段が決めるのは `n_i`（＝最終出力の独立成分 `n'_i` の上限）と抽出の無作為性である（`../roadmap.md` §5）
- **誰が使うのか**: 段4 の突合の実施者（Claude Code）
- **どこで使うのか**: 本リポジトリの uv 環境（`uv run`）。GPU・ネットワークを使わない

**新規の実装は無い**（手段は M1・M2・M2-1 で用意済み。`design.md` §1.2）。本マイルストーンは**実行と記録**である。

## 1.2 用語定義

`../roadmap.md` §1.2、`../survey_notes.md` §2、`../m2-1-means-smoke/requirements.md` §1.2 の用語を継承する。本書で新たに使うもののみ挙げる。

| 用語 | 定義 |
|---|---|
| **標本 TSV** | 層ごとに抽出した 50 行を、候補 TSV と同じ 7 列で書き出したもの（層ごとに 1 ファイル） |
| **逆引き結果 TSV** | 標本 TSV の 7 列に `stage`・`block_index`・`page_idx`・`reason` を加えた 11 列（層ごとに 1 ファイル） |
| **`stage`** | 逆引きの到達段階。`block`（ブロックを一意に特定）/ `page`（ページのみ特定）/ `none`（特定できず） |
| **逆引きの成功** | `stage` が `block` または `page` であること |

## 1.3 機能要求一覧

### FR-M3-001: 層別標本の抽出（Must）

- **機能名**: 層ごとに 50 件を再現可能な無作為抽出で確定する
- **概要**: 母集団（候補 TSV の `location != table`）から、層 `G`・`L`・`C` それぞれ 50 件を、記録した乱数シードで抽出する
- **入力**: 候補 TSV（`{BASE2}/ocr/collation/feat-024_candidates.tsv`）、層、件数、乱数シード
- **出力**: 層ごとの標本 TSV（3 ファイル）
- **受け入れ基準**:
  1. 3 層それぞれについて、ヘッダ 1 行＋**データ 50 行**の標本 TSV が出力されること
  2. 全 150 行が、`(chapter, offset)` で候補 TSV の行と一致し、`kind` が当該層、`location` が `table` でないこと
  3. 150 行に `(chapter, offset)` の重複が無いこと
  4. 同じシードでの再実行が、3 層ともバイト一致すること
  5. 抽出件数・再現性・層別の所在の内訳が、`../roadmap.md` §6 の段3 の想定値と照合され `experiment_log.md` に記録されていること

### FR-M3-002: 原本ページの逆引き（Must）

- **機能名**: 標本の各行について content_list のブロックまたはページを特定する
- **概要**: 既存 `locate_candidates.py --input-sample` を層ごとに実行し、逆引き結果 TSV を得る。**既存スクリプトを変更しない**
- **入力**: 候補 TSV（章内候補列の構築に使う）、`{BASE2}/ocr/final`、層ごとの標本 TSV
- **出力**: 層ごとの逆引き結果 TSV（3 ファイル）
- **受け入れ基準**:
  1. 3 層それぞれについて、ヘッダ 1 行＋**データ 50 行**の逆引き結果 TSV が出力されること
  2. 各行の**先頭 7 列**が、対応する標本 TSV の行と完全に一致すること
  3. `stage` がすべて `block` / `page` / `none` のいずれかであり、`block` または `page` の行は `page_idx` が 0 以上であること
  4. `locate_candidates.py` を変更していないこと（`git diff` が空であること）
  5. 逆引きの成功率が、`../roadmap.md` §6 の段3 の想定値と照合され `experiment_log.md` に記録されていること

### FR-M3-003: 逆引き結果の集計（Must）

- **機能名**: 段4 に渡す前に、逆引きの到達段階と失敗理由を集計する
- **概要**: 層別・`stage` 別・`reason` 別・`location` 別の件数を数え、記録する
- **入力**: 3 つの逆引き結果 TSV
- **出力**: 集計結果（`experiment_log.md` に表として記録する）
- **受け入れ基準**:
  1. 層別・`stage` 別の件数（合計 150）が記録されていること
  2. `stage = none` の件について `reason` 別の件数が記録されていること
  3. 標本に含まれる `location = footnote` の件数が層別・合計で記録され、`../roadmap.md` §6 の段3 の想定値と照合されていること

### FR-M3-004: 予測の記録（Must）

- **機能名**: 実行単位ごとに、その実行の直前に予測を記録する
- **概要**: `../m2-1-means-smoke/experiment_log.md` の**是正4〜6** に従い、層（＝段3 の処理単位）ごとに、その層の実行の直前に予測を `experiment_log.md` へ記録し、**その時点でコミット**してから実行する
- **入力**: `../roadmap.md` §6 の段3 の想定する項目
- **出力**: `experiment_log.md` の層ごとの予測節と、その時点の git コミット
- **受け入れ基準**:
  1. **3 層それぞれについて、予測 → 実行 → 照合の順で記録されていること**（3 層分の予測をまとめて先に書かないこと）
  2. 各層の予測が、当該層の実行の**前**にコミットされていること（コミットのハッシュが `experiment_log.md` に記録されていること）
  3. 予測項目が `../roadmap.md` §6 の段3 の想定する項目の枠の中にあること。枠の外の量を書く場合は「参考（判定に使わない）」と明示されていること
  4. **案件状態が実態に遅れずに更新されていること**（是正7）。次の 4 時点それぞれで、`design.md` 手順 A-6 の表のとおりに記載が更新・確認されていること
     - (a) **M3 の人レビュー承認の直後（各層の実行より前）**: `README.md` のマイルストーン一覧と実施記録、`../roadmap.md` §7 の状態欄が、いずれも「実施中」に**更新**されていること
     - (b) **各層の照合の記録の直後**: `README.md` の実施記録に当該層の行が**追加**されていること。かつ `../roadmap.md` §7 の M3 の状態欄が実態どおり「実施中」である（値を変えない）ことが**確認**されていること
     - (c) **3 層の集計と検証が終わった直後（手動テストより前）**: `README.md` のマイルストーン一覧が「**実施中（手動テスト・承認待ち）**」に**更新**され、実施記録に集計と自動検証の行が**追加**されていること。かつ `../roadmap.md` §7 の状態欄が実態どおり「実施中」である（値を変えない）ことが**確認**されていること。**この時点で「完了」と書いていないこと**
     - (d) **ユーザーの手動テストと承認の直後**: `README.md` のマイルストーン一覧・実施記録と `../roadmap.md` §7 の状態欄が、いずれも「完了」に**更新**されていること（`CLAUDE.md`「機能追加フロー」ステップ7）
