## 結果（[AGENTS.md適用] マーカーあり）

### 高

1. **重複する `block_index` / `page_idx` により、切り出し手順が実行不能であり、受け入れ基準とも矛盾する**
   - M3 の実測には同一ブロックの標本が複数ある（`block` は 106 件に対し一意な `(chapter, block_index)` は **97**、
     `stage = page` も 30 件に対し一意なページは **27**）
   - `design.md:117` は章内の対象ブロックをそのまま複数 `--index` で渡すため同じ index が含まれるが、
     **`crop_blocks.py` は重複 index をエラーとして終了する**（`scripts/crop_blocks.py:89`）
   - さらに設計は同一ページの画像共有を許す一方、要求は「136 件すべてに 1 枚ずつ」「標本とファイル名が 1 対 1」としている（`requirements.md:46`）
   - 修正案: 対象を `(chapter, block_index)` と `(chapter, page_idx)` ごとに一意化して渡す。
     受け入れ基準は「成功した 136 標本すべてが既存の画像を参照できる」とし、共有画像を許す対応関係へ変更する。
     実測に基づく画像数は **block 97 枚＋page 27 枚＝124 枚**。`judgments.tsv` の各標本行で共有する画像パスを記録すれば追跡可能性も保てる

2. **`判定不能` の理由コード 4 種は、当該箇所を一意に特定できないケースを分類できない**
   - 手順は `context` を手掛かりに画像中の該当箇所を特定するが（`design.md:185`）、
     **同じ短い `context` がページ内に複数ある場合の規則が無い**
   - このケースは 4 コードのいずれでもなく、現行設計では中断になる（`design.md:220`）
   - 修正案: 実行前に重複 `context` で一意化する手順を定めるか、`ambiguous_match` のような理由コードを追加する

3. **M2-1 の是正5（実データ実行を Claude Code 本体に限定）が明文化されていない**
   - M4 は予測記録時のコミットだけをサブエージェントへ委任すると書いているが（`design.md:79`）、
     **実データの切り出し・画像閲覧・判定を本体が行い、サブエージェントには実行させない禁止事項が無い**
   - 修正案: §3.1 に「実データの切り出し・閲覧・判定・照合は Claude Code 本体が 1 層ずつ実行し、サブエージェントには委任しない」と明記する
