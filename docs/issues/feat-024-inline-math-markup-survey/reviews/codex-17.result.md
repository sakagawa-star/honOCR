## C（全文ゲート）の指摘 — 高3件

### 高-1: `locate_one` が再帰・循環しうる設計だった

`locate_one` の仕様は `(stage, block_index, page_idx)` を返す形で、
**2段階目の近傍探索で同じ二段階関数を再帰呼び出し**する構造だった。
直接一致しない候補が続くと**再帰・循環しうる**うえ、必須出力列 `reason` も生成できない。

**対応**: 関数を分離した。

- `find_block`: **1段階目のみ・非再帰**。`(block_index, page_idx, key_kind)` または `None` を返す
- `locate_candidate`: 統括。`(stage, block_index, page_idx, reason)` を返す。
  **2段階目の近傍探索でも `find_block` だけを呼び、自分自身を呼ばない**

擬似コードと docstring の両方に明記した。

### 高-2: `not_covered` の理由の記録先と形式が未定義

理由を記録する要求に対し、出力 TSV に理由列がなく、`experiment_log.md` にも
16件ごとの記録場所・形式が定義されていなかった。
**M5 へ引き渡すべき「本手法で検出できない型」の根拠が残らない。**

**対応**: 出力 TSV に `not_covered_reason` 列を追加し、分類を `no_symbol` / `table_only` に固定。
機械判定の規則を擬似コードで定め、分類別件数を `experiment_log.md` に記録して M5 に引き渡すことを
要求・設計・完了判定に明記した。

### 高-3: 存在しない受け入れ基準への参照

「FR-M2-003 受け入れ基準5」への参照が2箇所あったが、その基準が存在しなかった。

**原因**: **Claude Code が受け入れ基準 2-b・2-c を挿入する置換で、元の基準3〜6 を誤って削除していた。**

**対応**: 基準3（所在別の内訳）・4（`none` の `reason` 別件数）・5（再現性）・
6（合格ラインを緩めない）を**復元**し、参照先も整合させた。

**全文ゲートが無ければ、criteria lock の受け入れ基準が4つ欠けたまま固定されるところだった。**
対話段階の B×4 では検出されず、`/new` 後の全文確認で見つかっている。

## C 後の B1 の指摘 — 高1件（高-2 が未解消・新たな矛盾）

`table_only` を `not_covered` とする要件に対し、設計の `status` 定義は
「候補が1件以上なら `covered`」のままだった。**table 内だけに候補がある行が
`covered` と `not_covered` の両方になりうる。** 加えて `other` の扱いが
要求（TSV に記録）と設計（ログのみ）で食い違っていた。

**対応**: `covered` を「**母集団の候補（`location != table`）が1件以上**」と定義し直し、
判定を擬似コードの3分岐に固定。**到達不能な `other` を要求・設計の両方から削除**した。

## C 後の B2 — 収束

**高・中とも 0 件。** codex の講評:

> covered は母集団候補（location != table）の有無で判定され、no_symbol / table_only の二分類と
> TSV・実験ログの記録先も requirements/design/完了判定で一致しています。
> 三分岐は網羅的で、other の残存参照もありません。**criteria lock は収束です。**
