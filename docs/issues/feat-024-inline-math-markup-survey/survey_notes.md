## 3. 候補の定義（実証済み）

**走査対象は成果物 md の全文**である（§4 の理由により content_list ではない）。
md 全文を1つの文字列として読み、次の順で処理する。**行単位では処理しない**
（除外領域が複数行にまたがるため）。

**手順1: 複数行の除外領域をマスクする。**
次の2つの正規表現を、この順で `re.MULTILINE | re.DOTALL` で適用し、
マッチ範囲を**同じ長さの `\x00`** に置き換える。

| # | 正規表現 | 対象 |
|---|---|---|
| 1 | `^```.*?^```` | コードブロック（行頭のフェンス対）|
| 2 | `^\$\$.*?^\$\$` | 数式ブロック（行頭の `$$` 対）|

**適用順をこの順に固定する**（コードブロックの中に `$$` が現れても数式ブロックと誤認しないため）。

**手順2: 画像参照をマスクする。** `!\[[^\]]*\]\([^)]*\)` にマッチする範囲を `\x00` にする。

**手順3: インライン数式を確定してマスクする。**
`\$[^$\n]+\$` で走査し（非重複・左から）、マッチ範囲を**候補C** とする。
マッチ範囲を `\x00` に置き換えた文字列を**マスク文字列**とする。
**マスク文字列の長さは md 全文と等しく、オフセットは md のものと一致する。**

**手順4: 候補G を拾う。**
マスク文字列を1文字ずつ走査し、コードポイントが **U+0370〜U+03FF**（Greek and Coptic）に
入る文字を候補G とする。

**手順5: 候補L を拾う。**
マスク文字列を1文字ずつ走査し、位置 `i` の文字 `c` が次の3条件をすべて満たすとき候補L とする。

1. `c` が半角ラテン英字（`A`〜`Z` または `a`〜`z`）である
2. **左隣接が日本語文字**: `i-1 >= 0` かつ、`s[i-1]` が日本語文字であるか、
   または `s[i-1]` が空白文字（`str.isspace()` が真）かつ `i-2 >= 0` かつ `s[i-2]` が日本語文字
3. **右隣接が日本語文字**: `i+1 < len(s)` かつ、`s[i+1]` が日本語文字であるか、
   または `s[i+1]` が空白文字かつ `i+2 < len(s)` かつ `s[i+2]` が日本語文字

**日本語文字の定義**: コードポイントが U+3041〜U+309F（ひらがな）、U+30A0〜U+30FF（カタカナ）、
U+4E00〜U+9FFF（CJK 統合漢字）のいずれかに入るか、
文字が `、`(U+3001) `。`(U+3002) `，`(U+FF0C) `．`(U+FF0E) `・`(U+30FB) `「`(U+300C)
`」`(U+300D) `（`(U+FF08) `）`(U+FF09) のいずれかである。

**空白を1文字だけ挟むことを許す理由**: 本文が「確率変数 X の期待値」のように
記号の前後に半角アキを入れて組まれているため。**空白2文字以上は挟まない。**

**候補L の前後条件の目的**: 英単語（`Python`・`deviation` 等）と、原本でも立体で組まれる
連続英字を除外すること。

**手順6: 所在（`location`）を決める。** 候補の `offset` が属する**行**を求め、
その行の先頭（`str.strip()` 後）で判定する。

| 値 | 条件 |
|---|---|
| `table` | 行が `|` で始まる（GFM パイプテーブルの行）|
| `footnote` | 行が `>` で始まる（`insert_footnotes.py` が挿入した blockquote）|
| `body` | 上記以外 |

### 3.1 1文字走査版と正規表現版の一致（実測）

候補L の定義は、正規表現
`(?<=[ぁ-ゟ゠-ヿ一-鿿、。，．・「」（）])\s?([A-Za-z])\s?(?=[ぁ-ゟ゠-ヿ一-鿿、。，．・「」（）])`
とも書けるが、正規表現版は**非重複マッチ**であるため隣接候補を取りこぼす可能性が規則上残る。

**content_list を走査した予備調査では、両者の結果が完全一致した**（1,314 件・位置集合も一致）。
それでも実装は**1文字走査版を正とする**（規則上の懸念を残さないため）。

### 3.2 候補に該当しない記号（実測）

| 確認項目 | 結果 |
|---|---|
| 拡張ギリシャ（U+1F00〜U+1FFF） | **0 件**（`[Ͱ-Ͽ]` = U+0370〜U+03FF で足りる） |
| マイクロ記号 `µ`・`Å`・`Ω`（U+00B5 等の互換文字） | **0 件** |
| 数学英数記号（U+1D400〜U+1D7FF） | **0 件** |
| 奇数個の `$` を含む text ブロック | **0 件** |
| 改行を含む text ブロック | 98 件（インライン数式は改行をまたがない） |

## 4. 母集団の source を md とする根拠（実証済み）

当初は `content_list.json`（`type=text`）を走査する設計だったが、次の2点の実測により
**成果物 md を母集団の source とする**ことが確定した。

### 4.1 content_list には md 限定の修正が反映されていない

`apply_fixes.py` は md のみを対象とする（既存ポリシー。`docs/PROJECT_KNOWLEDGE.md`）。
そのため content_list には feat-014（3件）・feat-020（19件）・feat-022（4件）・feat-023（2件）の
修正が入っておらず、**md では修正済みの箇所を欠落として数えてしまう**。

**実測**: content_list のブロック全文が md に存在しない候補は 24 件（G 2 / L 9 / C 13）。
うち候補周辺の文脈も md に無いもの（＝ md 側で修正された可能性が高いもの）は 7 件（G 2 / L 1 / C 4）。

### 4.2 md にしか無い候補が 810 件（17%）ある

`insert_footnotes.py`（feat-009）が md にのみ挿入する脚注と、
`html_table_to_md.py`（feat-008）が変換した表は、content_list に同じ形で存在しない。

**実測**: md にのみ現れる候補は **810 件**（G 74 / L 98 / C 638）。
要因の内訳は脚注 395・表 219・fixes 9・未分類 187 であった
（この分類は行頭記号による粗い判定であり、未分類の多くは content_list のブロック境界と
md の行境界のずれに由来する。md を source にすればこの分類自体が不要になる）。

### 4.3 結論

本案件の問いは「**現行の md に**どれだけ欠落があるか」である。
**母集団は md、原本ページの特定は content_list 経由**と役割を分ける。

## 7. 原本ページの逆引き（実証済みの手法と実測値）

md は原本ページの情報を持たない。候補の位置から、`bbox`・`page_idx` を持つ
content_list のブロックを逆引きする必要がある。

**正規化関数**: `norm(s)` = `s` から正規表現 `[\s#>|*\\_`\-:]+` にマッチする文字を**すべて除去**した
文字列。md のマークアップ記号（`##`・`>`・`|`・`*`・`\`・`_`・`` ` ``・`-`・`:`）と空白・改行を
落とすことで、md と content_list の表記差を吸収する。

### 7.1 予備実測（無作為 60 件／章 × 10章 = 554 件）

`norm` した前後10文字のキーで content_list のブロックを引いた結果:

| 所在 | 成功 | 失敗 | 成功率 |
|---|---|---|---|
| `body` | 457 | 43 | **91.4%** |
| `footnote` | 28 | 9 | **75.7%** |
| `table` | 0 | 17 | **0%** |

- **`table` が 0% なのは原理的**である。表は `html_table_to_md.py` が content_list の
  `table_body`（HTML 文字列）から変換したもので、**content_list に同じ形のテキストブロックが
  存在しない**
- **`footnote` が低いのは `insert_footnotes.py` の仕様による**。脚注は
  「断片除去 → bbox 読み順ソート → 番号プレフィックス結合」で**複数ブロックを結合して**
  md に挿入されるため、単一ブロックへの部分一致が成立しにくい

### 7.2 キー長を変えた場合の実測

| キー | 一意一致 | 複数一致 | 縮退で一致 | 不一致 |
|---|---|---|---|---|
| 前後10文字 | 421 | 5 | 59 | 69 |
| 前後30文字 | 237 | — | 248 | 69 |

前後10文字の方が一意一致が多い。**キーを短くすると一致件数が増えて曖昧性が上がり、
長くすると一致しにくくなる**というトレードオフがある。

### 7.3 実証された制約

- **md の文字オフセットと content_list の `block_index` は同一の座標系ではない。**
  `insert_footnotes.py` は content_list の読み順とは別の位置に脚注を挿入し、
  `html_table_to_md.py` は表を別形式に変換し、`apply_fixes.py` は md のみを書き換えるため、
  両者の順序は一致しない。**「md 上の位置が近いブロック」という選び方は定義できない**

## 8. 候補規則で拾えない数学記号（参考値）

数式マークアップ外に現れる、候補G・候補L のいずれにも該当しない数学記号の件数。

**対象の文字クラス**: U+2190〜U+22FF（矢印・数学演算子）、U+2A00〜U+2AFF（補助数学演算子）。

**実測（content_list 基準・2026-09-06）**: **269 件**
（`→` 187 / `∑` 15 / `≡` 11 / `≤` 10 / `≥` 8 / `∫` 7 / `∞` 4 / `∶` 3 / `≈` 3 / `√` 2 / `∵` 2 / `∅` 2 / 他）。

**269 件のうち 187 件（69%）が `→`** であり、本文の説明（「A → B」の遷移）にも正当に使われる。
ギリシャ文字・ラテン変数とは性質が異なり、同じ判定規則を適用できない。
**md 基準での数え直しは未実施**であり、**本案件では数え直さない**
（`roadmap.md` §9 の保留リストの方針。M5 の報告では上記の content_list 基準の値を
典拠つきの参考値として示し、基準の違いを明記する）。

## 9. 統計手法（式と算出済みの値）

### 9.1 区間推定の式

**Wilson score interval**（95%、z = 1.959964）を用いる。

```
中心 = (p̂ + z²/(2n')) / (1 + z²/n')
半幅 = z/(1 + z²/n') × sqrt( p̂(1−p̂)/n' + z²/(4n'²) )   ※ n' = 有効標本数
有限母集団修正 = sqrt( (N − n') / (N − 1) )
半幅 ← 半幅 × 有限母集団修正
```

**Wald 法（p̂ ± z√(p̂(1−p̂)/n)）は用いない**——p̂ が 0 や 1 に近いときに区間が破綻するため。
本調査は p̂ が 0 に近くなる可能性が十分にある。

### 9.2 必要標本数の算出結果（2026-09-06 算出）

最も不利な p̂ = 0.5 のとき、上式の半幅（有限母集団修正込み）が **0.15 以下**になる
最小の有効標本数:

| 層 | N | 必要な有効標本数 |
|---|---|---|
| 層G | 291 | **34** |
| 層L | 1,408 | **38** |
| 層C | 2,925 | **39** |

## 11. 本手法で原理的に測れないもの

1. **数式ブロック（`$$…$$`）内の劣化**
2. **GFM パイプテーブル内の候補 158 件**（逆引きが原理的にできない。§7.1）
