## 2. 機能の全体像

`scan_plain_math.py` は次の3段で動く。

```
1. 引数を解析する（§7）
2. 入力 md を1つずつ読み、候補を抽出する（§4）
3. 全結果を規定の順序でソートして TSV を書き出す（§3）
```

**判定（欠落かどうか）は行わない。** 本 CLI は原本を参照しない。

## 3. データフローと出力形式

### 3.1 データフロー

| 段階 | データ | 型・形式 |
|---|---|---|
| 入力 | 成果物 md（1個以上） | UTF-8 テキスト。改行は LF |
| 中間1 | マスク文字列 | `str`（**md 全文と同じ長さ**。除外領域が `\x00` に置き換わる） |
| 中間2 | 行開始オフセットの配列 | `list[int]`（`bisect` で行番号を引く） |
| 中間3 | 候補のレコード | `dict`（キーは §3.2 の列名） |
| 出力 | 候補の一覧 | TSV（UTF-8・LF 改行・ヘッダ行あり） |

### 3.2 出力 TSV の仕様

ヘッダ行（固定・この順序。タブ区切り）:

```
chapter	line	offset	kind	location	symbol	context
```

| 列 | 型 | 内容 |
|---|---|---|
| `chapter` | str | **入力 md のパスの親ディレクトリ名**（例: `{BASE2}/ocr/final/chap05/chap05_gray300.md` → `chap05`） |
| `line` | int | md の行番号（**1 始まり**） |
| `offset` | int | md 全文における文字オフセット（**0 始まり**）。候補の同定と後続マイルストーンの逆引きのキー |
| `kind` | str | `G` / `L` / `C` |
| `location` | str | `body` / `footnote` / `table` |
| `symbol` | str | 候補の文字（候補C はインライン数式の全文、`$` を含む） |
| `context` | str | `md[max(0, offset-15) : offset + len(symbol) + 15]` |

**`symbol` と `context` のサニタイズ**（NFR-M1-005）: タブ（`\t`）・改行（`\n`）・
復帰（`\r`）を**半角スペース1文字**に置換する。**それ以外の変換は行わない**
（引用符で囲まない・バックスラッシュエスケープをしない）。

**行の並び順**: `chapter` 昇順 → `offset` 昇順 → `kind` 昇順（文字列比較で `C` < `G` < `L`）。
**入力ファイルが複数指定された場合も、全体をこの順序でソートしてから出力する**
（入力順に依存しない決定的な出力にするため。FR-M1-001 受け入れ基準5）。

## 4. 処理ロジック

### 4.1 候補の抽出（FR-M1-002）

**`../survey_notes.md` §3 の手順1〜6 に厳密に従う。** 実装上の要点は次のとおり。

**手順1（複数行の除外領域のマスク）**: 次の2つの正規表現を**この順で**適用する。

| # | パターン | フラグ |
|---|---|---|
| 1 | `^```.*?^```” の形（開始と終了がいずれも行頭のフェンス）| `re.MULTILINE \| re.DOTALL` |
| 2 | `^\$\$.*?^\$\$` | `re.MULTILINE \| re.DOTALL` |

マッチ範囲を**同じ長さの `\x00`** に置き換える（`lambda m: "\x00" * len(m.group())`）。
**適用順を入れ替えてはならない**——コードブロックの中に行頭 `$$` があるとき、
先に数式ブロックを処理すると誤ったマスクになる（T-06 で検証する）。

**手順2（画像参照のマスク）**: `!\[[^\]]*\]\([^)]*\)` を同様に `\x00` に置き換える。

**手順3（インライン数式）**: `\$[^$\n]+\$` で走査し（`re.finditer`。非重複・左から）、
各マッチを**候補C** として記録する（`offset` はマッチ開始位置、`symbol` はマッチ全文）。
そのうえでマッチ範囲を `\x00` に置き換え、これを**マスク文字列**とする。

**手順4・5（候補G・候補L）**: マスク文字列を**1文字ずつ**走査する。
判定条件は `../survey_notes.md` §3 手順4・5 のとおり。
**正規表現版を使わない**（同 §3.1 の理由）。

**不変条件**: マスク文字列の長さは md 全文と等しい。したがって
**マスク文字列上のインデックスは md 全文のオフセットとしてそのまま使える**。

### 4.2 行番号の算出

候補ごとに `md[:offset].count("\n") + 1` を計算すると走査全体で O(N²) になる。
**改行位置から行開始オフセットの配列を1度だけ作り、`bisect.bisect_right` で引く**。

```python
# 意図の伝達用（そのままコピーして使うものではない）
starts = [0] + [i + 1 for i, ch in enumerate(md) if ch == "\n"]
line = bisect.bisect_right(starts, offset)   # 1 始まりの行番号になる
```

### 4.3 所在の分類（FR-M1-003）

候補の `offset` が属する行を `starts` から求め、その行の文字列を取り出して
`str.strip()` した先頭で判定する。

| 判定順 | 条件 | 値 |
|---|---|---|
| 1 | 行が `\|` で始まる | `table` |
| 2 | 行が `>` で始まる | `footnote` |
| 3 | それ以外 | `body` |

**判定は元の md（マスク前）の行に対して行う**（マスク後は `\x00` が並び、行頭記号が消える）。

### 4.4 処理時間（NFR-M1-003）

全10章で約 928KB。正規表現4回と1文字走査1回、`bisect` による行番号算出で、
**60 秒以内**に収まる。ループはすべて `for` による有限反復であり `while` を使わない。

### 4.5 決定性（NFR-M1-002）

- 出力順は §3.2 の並び順で完全に決まる（同一キーの候補は存在しない。§9.3 の排他性検査で確認する）
- 乱数・時刻・環境変数・辞書の反復順に依存しない
- 入力ファイルは**引数に与えられた順に読み**、最後に全体をソートする（glob の展開順に依存しない）

## 5. エラーハンドリング（FR-M1-004）

| 事象 | 検出方法 | 動作 |
|---|---|---|
| 入力ファイルが存在しない | `Path.is_file()` が偽 | 標準エラーへ `md not found: {path}`、**終了コード 1** |
| UTF-8 として読めない | `UnicodeDecodeError` | 標準エラーへ `md unreadable: {path} ({exc})`、**終了コード 1** |
| 出力先の親ディレクトリが存在しない | `Path(out).parent.is_dir()` が偽 | 標準エラーへ `output dir not found: {dir}`、**終了コード 1** |
| 出力先が既に存在し `--overwrite` 未指定 | `Path(out).exists()` が真 | 標準エラーへ `output exists (use --overwrite): {path}`、**終了コード 1**。**既存ファイルを開かない・書き込まない** |
| 候補が 0 件 | 結果リストが空 | **エラーにしない**。ヘッダ行のみを出力し**終了コード 0** |

**エラーは最初の1件で停止する**（部分的な出力に意味がないため）。

### 5.1 出力の原子性（`--out` 指定時）

**出力ファイルへの書き込みは、全入力の走査が成功した後に行う。**
さらに、書き込みそのものが途中で失敗しても**既存ファイルを破損・部分更新しない**よう、
次の手順で行う。

```
1. 出力先と同じディレクトリに一時ファイルを作る
   （tempfile.mkstemp(dir=出力先の親ディレクトリ, prefix=".{出力先のファイル名}.", suffix=".tmp")）
   ※ 同一ディレクトリに作るのは、os.replace が同一ファイルシステム内でのみ原子的なため
2. 一時ファイルに TSV の全内容を書き、close する
3. os.replace(一時ファイル, 出力先) で置換する（同一ファイルシステム内では原子的）
4. 2 または 3 で例外が発生した場合:
   - 一時ファイルが残っていれば削除する（削除自体が失敗しても無視する）
   - 標準エラーへ `write failed: {出力先} ({exc})` を出力し、終了コード 1 で終わる
   - 出力先の既存ファイルは 3 が成功するまで変更されないため、破損しない
```

**`--overwrite` の有無で手順を変えない**（`--overwrite` は既存ファイルの上書きを
許可するかどうかの判定に使うだけで、書き込み方法には影響しない）。

**`--out` を指定しない場合**（標準出力）は本手順の対象外である
（標準出力にはファイルの破損という概念がないため）。

## 6. 境界条件（FR-M1-004）

| 入力 | 振る舞い |
|---|---|
| 空の md（0 バイト） | ヘッダ行のみ出力・終了コード 0 |
| 閉じていないコードフェンス・`$$` | 正規表現が対を要求するためマッチせず**マスクされない**。その領域の文字が候補になりうる。**この検査は M2 の担当**（`../roadmap.md` M2 の完了条件(1)）であり、本 CLI はエラーにしない |
| `$` が奇数個の行 | `\$[^$\n]+\$` にマッチしない `$` は残る。`$` 自体は候補G・候補L のいずれにも該当しないため候補にならない |
| 改行をまたぐ `$…$` | インライン数式の正規表現は `\n` にマッチしないため**数式と見なさない**（T-08） |
| 候補が md の先頭・末尾 | `context` のスライスは `max(0, ...)` と Python のスライスで安全に処理される。候補L は左右の隣接条件により先頭・末尾では成立しない（T-12） |
| 同一ファイルを複数回指定 | 重複した行がそのまま出力される（**呼び出し側の責任**。CLI は重複を除去しない） |
| 入力が1個だけ | 正常に動作する（`nargs="+"` の下限） |
| 書き込み中にディスク容量不足・権限変更が起きた | §5.1 の手順4 により**既存の出力ファイルは変更されない**。一時ファイルを削除し、終了コード 1 |
| 一時ファイルの削除に失敗した | **無視する**（既に置換の失敗を報告しているため、削除の失敗を重ねて報告しない）。終了コード 1 は変えない |

## 11. 設計判断の記録（ADR）

### ADR-M1-1: 候補抽出 CLI を `scripts/` に置き、テストを付ける（プロダクトコードの判定）

- **採用**: `scripts/scan_plain_math.py` として置き、`tests/test_scan_plain_math.py` を書く
- **却下**: マイルストーンフォルダ（`m1-scan-cli/`）配下に置く
- **判定**: `CLAUDE.md`「ドキュメント作成ルール」の判定基準「**その案件が終わった後も使うか**」に
  照らし、本 CLI を**プロダクトコード**と判定した。同ルールはプロダクトコードを `scripts/` 配下に、
  そのテストを `tests/` 配下に置くと定めており、**判定と理由を当該 `design.md` の ADR に記録する**
  ことを求めている（本項がその記録である）
- **理由**: 「数式マークアップ外の数学記号を洗い出す」処理は**他の書籍（PRML）にもそのまま使える**。
  本案件の M2 以降でも候補 TSV の再生成に使い、案件の完了後も残る。
  feat-021 が同種の汎用 CLI `crop_blocks.py` を `scripts/` に新設したのと同じ判断である。
  一方、本案件の M3・M5 で作るスクリプト（標本抽出・逆引き・原本ページ切り出し・推定）は
  この調査のためだけのものであり、**ジョブスクリプト・実験コード**としてマイルストーンフォルダ配下に置く
- **経緯**: 本 ADR の初版は「粒度表の『スクリプト本体』はジョブスクリプト・実験コードを指す」という
  解釈で `scripts/` を選んでいたが、Codex レビューで「**規程に根拠がない**」と高で指摘された。
  規程側の文言が箇所によって割れていたため、**update-007** で `CLAUDE.md` を明確化し、
  本 ADR はその規程に基づく判定として書き直した

### ADR-M1-2: 候補の定義を本書に再掲せず `../survey_notes.md` §3 を正とする

- **採用**: 定義は補助文書を参照し、本書には実装上の詳細（適用順・データ構造・出力形式）を書く
- **却下**: 定義の全文を design.md にも書く
- **理由**: `CLAUDE.md` の粒度表は「情報の所在を1つの文書に限定し、他の文書は参照する」ことを
  原則とする。定義を二重に持つと、片方だけ直したときに実装が分岐する。
  実装者には必読文書として `../survey_notes.md` を指定する（§10 の委任時に明示する）

### ADR-M1-3: 候補L を1文字走査で実装し、正規表現版を使わない

- **採用**: `../survey_notes.md` §3 手順5 の条件を1文字ずつ判定する
- **却下**: 正規表現 `(?<=JP)\s?([A-Za-z])\s?(?=JP)` を使う
- **理由**: 正規表現版は**非重複マッチ**であるため、隣接する候補の一部を取りこぼす可能性が
  規則の上では残る。1文字走査版は各位置を独立に判定するため、この懸念が原理的に生じない。
  全10章では両者の結果が完全一致することを実測済みだが（同 §3.1）、
  実装を1つに固定するのは「実装判断ゼロの原則」（`docs/DESIGN_STANDARD.md` §2.2）による

### ADR-M1-4: 候補 TSV を `{BASE2}/ocr/collation/` に出力する

- **採用**: リポジトリ外（`{BASE2}/ocr/collation/feat-024_candidates.tsv`）
- **却下**: リポジトリ内（`m1-scan-cli/` 配下）に置き `.gitignore` で除外する
- **理由**: `context` 列は**書籍本文の断片**であり、`../roadmap.md` 前提12-b の
  「書籍本文と原本画像はリポジトリに置かない」に反する。`.gitignore` による除外は
  `git add -f` で容易に破れ、公開リポジトリでは危険である。feat-021 が詳細記録を
  `{BASE2}/ocr/collation/` に置いた前例と揃える

### ADR-M1-5: `csv` モジュールを使わず自前でサニタイズする

- **採用**: タブ・改行を半角スペースに置換して素朴に結合する
- **却下**: `csv.writer(delimiter="\t", quoting=...)` を使う
- **理由**: `csv` は値にタブや改行が含まれるとき**引用符で囲みエスケープする**ため、
  出力が `awk -F'\t'` や `diff` で扱いにくくなる（§9.3 の確認手順が破綻する）。
  本 CLI の値に含まれうる制御文字はタブ・改行・復帰のみであり、
  これらを空白に潰せば列構造は壊れない（T-17 で検証する）

### ADR-M1-7: 出力を一時ファイル経由の原子的置換にする

- **採用**: 同一ディレクトリの一時ファイルに書き、`os.replace` で置換する（§5.1）
- **却下**: 出力先を直接開いて書く（全入力の走査が成功した後に1度だけ書く）
- **理由**: 走査が成功しても、**書き込みそのものが途中で失敗しうる**（ディスク容量不足・
  権限変更・シグナル）。出力先を直接開くと、`--overwrite` 時に**既存の候補 TSV を
  部分更新した状態で残す**。候補 TSV は母集団の確定値そのものであり、
  壊れたものを正常な出力と誤認すると M2 以降の推定がすべて無効になる。
  `os.replace` は同一ファイルシステム内で原子的であり、置換が成功するまで既存ファイルは変わらない
  （一時ファイルを同一ディレクトリに作るのはこのためである）

### ADR-M1-6: `experiment_log.md` を作らない

- **採用**: 本マイルストーンでは作らない
- **却下**: 全マイルストーンで一律に作る
- **理由**: `CLAUDE.md`「実験・検証の進め方」は「通常の実装・自動テスト」を対象外としている。
  M1 の判定はすべて**既知の期待値（確定値）との一致**であり、未知の量を測る実験ではない。
  予測に当たるものは `../survey_notes.md` §5 として既に文書化・レビュー済みである
