## 1.1 プロジェクト概要

### 何を作るのか

『プログラミングのための確率統計』の成果物 Markdown（`{BASE2}/ocr/final/chapNN/chapNN_gray300.md`）を
入力に、**数式マークアップの外にある数学記号らしき文字**と**インライン数式**を機械的に列挙して
TSV に出力する CLI（`scripts/scan_plain_math.py`）と、そのテストを作る。

### なぜ作るのか（解決したい課題）

本案件は「原本では数式として組まれている記号が md で数式マークアップを失っている量」を
標本推定で測る。**推定の母集団を確定するには、まず候補を漏れなく機械的に列挙する必要がある。**
列挙が手作業では再現できず、後続のマイルストーン（標本抽出・推定）が検証不能になる。

### 誰が使うのか（ユーザー像）

- **本マイルストーンの実行者**: Claude Code（M2 以降で候補 TSV を入力に使う）
- **将来の利用者**: 他の書籍（PRML）で同じ調査を行う場合の実行者。CLI は書籍に依存しない

### どこで使うのか（実行環境の概要）

Ubuntu（Linux 6.14）、Python 3.12、uv 管理の既存プロジェクト環境。GPU 不要・ネットワーク不要。
入力データ（`{BASE2}` 配下）は**リポジトリ外**にある。

## 1.3 機能要求一覧

### FR-M1-001: 候補抽出 CLI（`scripts/scan_plain_math.py`）の新設

**機能名**: 成果物 md からの候補抽出

**概要**: 1個以上の md を入力に、`../survey_notes.md` §3 の定義で候補G・候補L・候補C を抽出し、
1行1候補の TSV を出力する。**判定（欠落かどうか）は行わない。**

**入力**:
- 位置引数: 成果物 md のパス（**1個以上**）
- オプション: 出力先パス、抽出する種別の指定、既存ファイルの上書き許可

**出力**: TSV（UTF-8・LF 改行・ヘッダ行あり）。各行は候補1件を表し、
章名・行番号・md 全文における文字オフセット・種別・所在・該当文字列・前後の文脈を持つ。

**受け入れ基準**:

1. **確定値との一致**: 全10章（`{BASE2}/ocr/final/chap00〜09/*_gray300.md`）を入力したとき、
   出力 TSV の件数が次のすべてで `../survey_notes.md` §5 の表と**完全一致**する
   - 種別別: 候補G **291**、候補L **1,408**、候補C **3,083**（うち所在 `table` の 158 を含む）
   - 所在別: `body` **4,229**、`footnote` **395**、`table` **158**
   - 章別 × 種別別: §5 の表の各セル（10章 × 4列）
2. **母集団の合計**: 所在が `table` 以外の候補が **4,624** 件である
   （層G 291 / 層L 1,408 / 層C 2,925）
3. **層の排他性**: `(章名, オフセット)` の組が、種別の異なる候補どうしで**衝突しない**
   （衝突 0 件）
4. **決定性**: 同じ入力に対する2回の実行の出力が**バイト同一**である
5. **入力順非依存**: 入力ファイルの指定順を逆にしても、出力が**バイト同一**である
6. **テスト**: `uv run pytest -v` が全件成功する（既存 236 件 ＋ 本マイルストーンで追加する
   `tests/test_scan_plain_math.py` の24件 = **260 passed**、失敗 0）

---

### FR-M1-002: 抽出範囲の限定

**機能名**: 除外領域のマスク

**概要**: 数式ブロック（行頭 `$$` の対）・コードブロック（行頭フェンスの対）・画像参照の**内側**からは
候補を抽出しない。インライン数式の内側からは候補G・候補L を抽出しない
（インライン数式そのものは候補C として抽出する）。

**入力**: md 全文（1つの文字列として扱う。**行単位で処理しない**）

**出力**: 上記の領域に属する文字が候補として出力されないこと

**受け入れ基準**:

1. 数式ブロックの内側にあるギリシャ文字・単独ラテン英字が候補として出力されない
2. コードブロックの内側にある同上が候補として出力されない
3. **コードブロックの中に行頭 `$$` があっても数式ブロックと誤認しない**
   （マスクの適用順の検証）
4. 画像参照 `![...](...)` の内側の文字列が候補として出力されない
5. インライン数式の内側のギリシャ文字が候補G として出力されない
6. **改行をまたぐ `$…$` をインライン数式と見なさない**

---

### FR-M1-003: 所在の分類

**機能名**: 候補の所在（`body` / `footnote` / `table`）の判定

**概要**: 各候補に、それが属する行の種類を付与する。判定は候補のオフセットが属する行の
先頭文字（前後の空白を除く）で行う。

**受け入れ基準**:

1. `|` で始まる行の候補が `table` と判定される
2. `>` で始まる行の候補が `footnote` と判定される
3. 上記以外の行の候補が `body` と判定される
4. 全10章での所在別件数が FR-M1-001 受け入れ基準1 の値と一致する

---

### FR-M1-004: 異常系と境界条件の扱い

**機能名**: エラー処理

**概要**: 入力・出力に関する異常を検出したとき、部分的な出力を残さずエラーとして停止する。

**受け入れ基準**:

1. 入力ファイルが存在しないとき、標準エラーにメッセージを出力し**終了コード 1** で停止する
2. 入力が UTF-8 として読めないとき、同上
3. 出力先の親ディレクトリが存在しないとき、同上
4. 出力先のファイルが既に存在し上書きが許可されていないとき、同上。かつ
   **既存ファイルの内容が変更されない**
5. 候補が 0 件のとき、**エラーにせず**ヘッダ行のみの TSV を出力し**終了コード 0** で終わる
6. 空の md を入力したとき、同上

## 1.4 非機能要求

### NFR-M1-001: データ不変性（最重要）

**`{BASE2}` の既存データ**（`dewarping/`・`ocr/final/`・`ocr/fixes/`・`ocr/mineru-full/`）を
**一切変更しない**（`../roadmap.md` 前提13）。本 CLI は入力 md を読み取るのみで書き込まない。

**検証**: 本マイルストーンの作業前後で上記4ディレクトリ配下の全ファイルの SHA-256 を取得して
比較し、**差分が無いこと**（`diff` が無出力）を示す。

### NFR-M1-002: 再現可能性

同じ入力に対して常に同じ出力を返す（FR-M1-001 受け入れ基準4・5）。
乱数・時刻・環境変数・ファイルシステムの列挙順に依存しない。

### NFR-M1-003: 処理時間

全10章（合計約 928KB）の走査を **60 秒以内**に完了する。

### NFR-M1-004: 対応環境

Python 3.12 / uv 管理の既存環境で動作する。**新規ライブラリを追加しない**
（標準ライブラリのみを使う。Pillow を含む既存依存も import しない）。

### NFR-M1-005: 可読性の担保

出力 TSV の文脈列に含まれるタブ・改行を半角スペースに置換し、**TSV の列構造が壊れない**ようにする。

---

## 1.5 制約条件

1. **書籍本文をリポジトリに置かない**（`../roadmap.md` 前提12-b）。
   候補 TSV は文脈列に書籍本文の断片を含むため、**`{BASE2}/ocr/collation/` 配下に出力する**。
   本マイルストーンで作成する文書にも書籍本文を転記しない
2. **`{BASE2}` の既存データを変更しない**（NFR-M1-001）
3. **新規ライブラリを追加しない**（NFR-M1-004）
4. **OCR を再実行しない**。MinerU を起動しない
5. **md を修正しない**。`apply_fixes.py`・`build_final.py` を実行しない
6. CLI は特定の書籍に依存しない（章名は入力パスの親ディレクトリ名から取る）
7. コーディング規約は `CLAUDE.md`「コーディング規約」に従う
   （関数は snake_case、定数は UPPER_SNAKE_CASE、型ヒントを付ける、
   入出力パスは argparse で受け取る）

## 1.6 優先順位

### MoSCoW

| 要求 | 区分 | 理由 |
|---|---|---|
| FR-M1-001 候補抽出 CLI | **Must** | 母集団の確定に必須 |
| FR-M1-002 抽出範囲の限定 | **Must** | 除外を誤ると母集団が壊れ、以降の推定がすべて無効になる |
| FR-M1-003 所在の分類 | **Must** | `table` を母集団から除く判断に必要（`../roadmap.md` 前提6） |
| FR-M1-004 異常系と境界条件 | **Must** | 部分出力を母集団と誤認すると検出できない誤りになる |
| NFR-M1-001 データ不変性 | **Must** | 成果物の破壊は取り返しがつかない |
| NFR-M1-002 再現可能性 | **Must** | 再現できない母集団からの推定は検証できない |
| NFR-M1-003 処理時間 | **Should** | 60 秒を超えても作業は成立するが、反復に支障が出る |
| NFR-M1-005 可読性の担保 | **Must** | TSV が壊れると後続マイルストーンが読めない |

### MVP の範囲

FR-M1-001〜004 と NFR-M1-001・002・004・005 を満たすこと。
