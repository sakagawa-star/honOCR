## 1. 目標

『プログラミングのための確率統計』の OCR 成果物（`{BASE2}/ocr/final/chap00〜09/`）について、
**原本で数式として組まれている記号が Markdown 上で数式マークアップ（`$…$`）を失っている量**を、
**機械的な候補抽出と標本抽出による母比率推定**で測定し、報告書にまとめる。

**本案件は影響範囲を測る調査であり、md の修正は一切行わない。**
修正するかどうか・どの範囲を修正するかは、本案件の報告を見てユーザーが判断する（後続案件）。
feat-021 と同じ形である。

### 1.1 答える問い

| ID | 問い | 出力する量 |
|---|---|---|
| **Q1** | 数式マークアップ**外**に平文で置かれた**ギリシャ文字（候補G）および日本語に挟まれた単独の半角ラテン英字（候補L）**のうち、原本では数式組版であるもの（＝**欠落**）は何件あるか | 層G・層L それぞれの欠落率と信頼区間、推定件数とその区間 |
| **Q2** | **インライン数式（`$…$`）の内側**にあるもののうち、原本の書体情報（太字・ハット・上下線）が失われているもの（＝**劣化**）は何件あるか | 層C の劣化率と信頼区間、推定件数とその区間 |
| **Q3** | その規模は修正案件を起こすに値するか | **本案件では答えない**（ユーザー判断。§2 の前提4） |

**Q1 と Q2 は合算しない**（測っている対象が異なるため）。

- **母集団の確定値**（md 基準・2026-09-06 実測）: 層G 291 / 層L 1,408 / 層C 2,925 = **4,624**。
  GFM パイプテーブル内の 158 件は母集団外（`survey_notes.md` §5）
- **逆引きの1段階目の成功率**は所在によって大きく異なり、表では成立しない（同 §7.1）
- **feat-021 の `D4` 残件は 16 件**（同 §1.2）
- **候補規則で拾えない数学記号**が別に存在する（同 §8）
- **既存の CLI**: `scripts/crop_blocks.py`（feat-021。原本 TIF のブロック切り出し）が使える
- **M2 の実測**（2026-09-07。詳細は `m2-population-check/experiment_log.md`）:
  - 除外領域の対の閉じ検査は**全10章で合格**
  - `D4` 16件の被覆は `covered` 7 / `not_covered` 9 / 見出し行の特定不能 **0**
  - **逆引きの成功率は 93.3%**（検査標本 60 件。M2 の受け入れ基準を上回った）
  - **逆引き結果の正しさを確かめる手段に不備があり、M2 は No-Go となった**（確認に用いた
    「候補の前後の文脈」が md 上で要素の境界をまたぐため、content_list のブロック単位の
    テキストに収まらない件がある）

## 4. 分割の根拠

`CLAUDE.md`「マイルストーン分割」の4種類の境界を列挙し、併合の3条件で判定した。

### 4.1 境界の列挙

| 種類 | 該当 | 内容 |
|---|---|---|
| **1. 生成物の境界** | **該当（3箇所）** | (a) 候補の全量（母集団の確定に使う）。(b) 標本＋逆引き結果（切り出しの入力になる）。(c) 判定の一覧（推定の入力になる）。いずれも**そのステージ単独で実行して出力を確認できる** |
| **2. 判断の境界** | **該当（2箇所）** | (a) **逆引きが実用に足るか**（成功率と結果の正しさ）——満たさなければ標本抽出に進まず逆引きの手順または検証手段を見直す（前提11・14）。(b) **判定不能の比率が受け入れ基準の上限以内か**——超えれば推定に進まず、突合の手順・判定規則の欠陥として原因を特定する（前提12）。いずれも判断の結果で後段の設計内容が変わる |
| **3. 新規コンポーネントの境界** | **該当（3箇所）** | (a) 候補抽出 CLI（テスト付きでリポジトリに置く）。(b) 逆引きと原本ページ切り出しのスクリプト群。(c) 推定のスクリプト |
| **4. 環境の境界** | **該当しない** | 既存の uv 環境で動く。新規ライブラリ・新規ジョブ基盤・新規外部ツールを導入しない（前提13） |

### 4.2 併合の判定

併合の3条件（判断の境界を含まない／各作業が単独では検証可能な出力を生成できない／
共通の完了条件が同一の1回の実行で初めて満たされる）を、隣り合うマイルストーン候補ごとに判定した。

| 併合候補 | 条件1（判断の境界を含まない） | 条件2（単独では出力を検証できない） | 条件3（同一の1回の実行で完了） | 判定 |
|---|---|---|---|---|
| M1 ＋ M2 | **満たさない**（M2 が判断の境界(a)） | — | — | **分ける** |
| M2 ＋ M3 | **満たさない**（M2 が判断の境界(a)） | — | — | **分ける** |
| M3 ＋ M4 | **満たさない**（M4 が判断の境界(b)） | — | — | **分ける** |
| M4 ＋ M5 | **満たさない**（M4 が判断の境界(b)） | — | — | **分ける** |

**いずれの併合候補も条件1 を満たさないため、5マイルストーンに分ける。**
なお条件1 を満たす組合せは無いが、M3・M4 はそれぞれ単独で検証可能な出力
（標本＋逆引き結果、判定の一覧）を生成するため、条件2 の観点でも併合できない。

### M2: 母集団の検証と逆引き可能性の判定（判断の境界(a)）

| 項目 | 内容 |
|---|---|
| **目的** | 母集団が信用できること（除外領域の対が閉じている・feat-021 の `D4` をどれだけ被覆するか）を確かめ、**標本抽出に進んでよいか**を逆引きの**成功率**と**結果の正しさ**で判定する |
| **依存** | M1（候補の全量）。前提9・10・11・14 |
| **入力と出力の概要** | 入力: M1 の TSV、`{BASE2}/ocr/final/chap00〜09/` の md と content_list、**原本 TIF**（`{BASE2}/dewarping/chapNN/out/`。逆引き結果の正しさを原本で確かめるため。前提14）。出力: 検査の結果・逆引き成功率・正しさの検証結果を記録した `experiment_log.md`、**逆引き結果の検証に用いた原本の切り出し画像**（`{BASE2}/ocr/collation/` 配下。前提12-b） |
| **開始条件** | M1 が完了していること（ステップ7 の承認と `README.md` への記録） |
| **完了条件** | (1) 除外領域の対の閉じ検査が全10章で合格すること。(2) feat-021 の `D4` 16件のうち母集団に含まれる件数と、含まれない件の理由が記録されていること。(3) 無作為抽出した候補に対する逆引きの成功率が算出され、`experiment_log.md` に予測と実測の照合が記録されていること。(4) **逆引きに成功した件の正しさの検証**（機械による検査と、原本の切り出し画像による目視確認）が実施され、その結果が `experiment_log.md` に記録されていること |
| **判断結果ごとの次の行き先** | **成功率と正しさの検証がともに M2 の受け入れ基準を満たす → M3 に進む**。**いずれかを満たさない → M3 に進まず中断し、「ロードマップの改訂（再計画）」の表に従って戻る場所を選ぶ**（原因が逆引き手順にあれば当該 `design.md`、目的・完了条件にあれば当該 `requirements.md`、前提・分割・順序にあれば `roadmap.md` の改訂とステップ3 のやり直し） |

**この判断を独立させる理由**: 逆引きに失敗した候補は原本ページを開けず「判定不能」になる。
判定不能が多いと推定そのものが成り立たないため、**標本を採って突合する前に**
逆引きが実用に足ることを確かめる。
**成功率だけでなく正しさも見る理由**: 逆引きが誤ったページを指していても成功率には現れず、
M4 の突合で**原本に無い記号を探すか、別の記号を対象と取り違える**ことになる。

| **判断結果ごとの次の行き先** | **Go（次の2つをともに満たす）→ M5 に進む**: (i) 判定不能の比率が層ごとに M4 の受け入れ基準の上限以内であること、(ii) 層ごとの有効標本数が推定に必要な数（`survey_notes.md` §9.2）以上であること。**No-Go(1): (i) を満たさない層がある → M5 に進まず、突合の手順または判定規則に問題があるとみなして原因を特定する**（`CLAUDE.md`「実験・検証の進め方」手順3）。**No-Go(2): (i) は満たすが (ii) を満たさない層がある → M5 に進まず、M3 の標本設計が前提12 を満たしていなかったもの（標本設計の不適合）として扱う。** いずれの No-Go でも、原因が手順・目的・前提のどこにあるかで影響範囲が変わるため「ロードマップの改訂（再計画）」の表に従って戻る場所を選び、**完了済みマイルストーンの文書と記録は変更せず、必要な作業は枝番のマイルストーン（例: `M4-1`）として挿入する** |

**完了条件に「基準を満たすこと」を入れない理由**: 満たさない場合に M4 が完了できず、
次のマイルストーン（再計画で挿入する枝番）の開始条件（前のマイルストーンの完了）を満たせなくなる。
