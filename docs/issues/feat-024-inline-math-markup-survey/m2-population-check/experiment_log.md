## 検査2: `D4` 16件の被覆（FR-M2-002）

### 予測（2026-09-07・実行前に記録）

**予測の根拠**:

- `D4` は feat-021 が「原本と md で**数式の状態が一致しない**」と判定した件である。
  その多くは `collation_summary.md` §4 で「**数式が平文**（原本 N 個・md 0 個）」と記録されており、
  **平文になっているなら候補G または候補L として母集団に含まれる**はずである
- 一部は「数式範囲が原本 M 個・md N 個（M > N）」であり、**md にもインライン数式がある**。
  この場合は候補C として母集団に含まれる
- したがって **`covered` が多数**を占めると予測する
- ただし `../survey_notes.md` §11 の「原本では数式なのに md で文字ごと消えている箇所」に
  当たる件があれば `no_symbol` になる

| 項目 | 予測 |
|---|---|
| `covered` | **14 件** |
| `not_covered` | **2 件**（内訳: `no_symbol` 2 / `table_only` 0） |
| `heading_not_found` | **0 件**（feat-020 により全74件が見出し行になっているため） |

**`table_only` を 0 と予測する根拠**: Q&A 見出しは `## ? N.M …` の見出し行であり、
GFM パイプテーブルの行（`|` 始まり）ではない。所在は `body` になるはずである。

**この予測が外れる場合**に考えられること:

- `heading_not_found` が1件以上 → feat-020 の成果（全74件が見出し行）という前提が崩れている
  → **検査3 に進まず中断する**（`requirements.md` FR-M2-002 受け入れ基準1）
- `not_covered` が予測より多い → 「本手法で検出できない型」が想定より多い（M5 の報告に影響する）

**乖離の原因（特定済み・重要な発見）**:

予測は「`D4` の多くは原本の数式が md で**平文**になっているのだから、平文なら候補G または
候補L として母集団に含まれるはず」という前提に立っていた。**この前提が誤っていた。**

`not_covered` の9件を確認したところ、見出し行には数学記号が平文で存在する。
にもかかわらず候補にならないのは、**候補L の定義が「前後が日本語文字（空白1つまで許容）」を
要求している**ためである（`../survey_notes.md` §3 手順5）。
Q&A 見出しの質問文では、数学記号が次の文字に囲まれることが多い。

| 記号を囲む文字 | 日本語文字か |
|---|---|
| 半角括弧 `(` `)` `[` `]`（関数適用・区間の記法） | **いいえ** |
| 半角カンマ `,`（引数の区切り） | **いいえ** |
| 半角等号 `=`（条件の記述） | **いいえ** |
| 直前の見出し番号の数字 | **いいえ** |

**候補L の前後条件は、英単語（`Python`・`deviation` 等）と原本でも立体で組まれる連続英字を
除外するために設けたものである**（同 §3）。その副作用として、
**括弧・カンマ・等号・数字に囲まれた平文の数学表現を検出できない。**

**この発見の位置づけ**:

- **母集団の定義は変えない。** 候補の定義は criteria lock 済みであり、検査2 は
  「`D4` 16件が母集団にどれだけ含まれるか」を**測る**ことが目的で、`covered` の件数に
  合格ラインは設けていない（`requirements.md` FR-M2-002 受け入れ基準4）。**検査2 は所定どおり完了している**
- **`not_covered` 9件は「本手法で検出できない型」の実測値**であり、**M5 の報告に引き渡す**
  （`design.md` §5.5）。`../survey_notes.md` §11 に**第5項として加えるべき知見**である
- **本案件の推定値の解釈に影響する。** Q1 の推定は「**候補G・候補L で検出できる範囲**の欠落」であって
  「md における数式マークアップ欠落の総量」ではない。この限定は `../roadmap.md` §1.1 と
  `../survey_notes.md` §11 に既に明記されているが、**その限定がどれだけ効いているかの実測値が
  本検査で得られた**（16件中 9件、56%）

**次フェーズへの影響**: なし。検査3 に進む。

`footnote` の2段階目込みの成功率が 1段階目の 75.7% より高いことは見込める。
**この点は M3 の標本（130 件）に `footnote` が含まれたときに実地で確かめられる**
（M4 の突合で `footnote` の候補が判定不能になる率として現れる）。
**M4 の判定不能率の上限（層ごとに 10%）が、この不確かさに対する歯止めになる。**

**乖離2: `search_exhausted` が 0 件だったこと**

密に存在するため、200 件の打ち切りに達する事態が起きなかった。**想定より良い結果**である。

**乖離3: `block_key30` が 0 件だったこと**

### NG 1件（#3）の原因（特定済み）

**逆引きの結果そのものは正しい。確認方法が目的に合っていなかった。**

| 確認内容 | 結果 |
|---|---|
| 逆引きに使ったキー（前後10文字）が `block_index=177` の `text` に含まれるか | **含まれる（True）** |
| `context` 列（前後**15**文字）が同ブロックの `text` に含まれるか | **含まれない（False）** |

原因は、**`context` が md 上で直前の数式ブロック（`$$`）をまたいでいた**ことである。
`context` は M1 が md から機械的に切り出した「候補の前後15文字」であり、
候補がブロックの先頭付近にあると**前の要素（数式ブロック・見出し等）の文字を含む**。
一方 content_list のブロックの `text` は要素ごとに分かれているため、
**`context` 全体がひとつのブロックに収まらないことがある。**

`design.md` §7.7 は確認の方法を「候補の `context` に対応する文字列が含まれること」と
記述しており、**「対応する文字列」が `context` 全体なのか逆引きに使ったキーなのかを
定めていなかった**。実施にあたり `context` 全体の包含で判定したため、
**逆引きが正しい件を NG と判定した。**

### 判定への影響（未確定・ユーザーの判断を仰ぐ）

`requirements.md` FR-M2-003 受け入れ基準2-b は
「**確認した件のうち1件でも含まれていなければ（中略）成功率が 90% 以上でも Go にしない**」と
定めている。**文言どおりに適用すると No-Go である。**

一方で、NG の原因は逆引きの欠陥ではなく**確認手段の記述の不備**であり、
確認手段を「逆引きに使ったキーが含まれるか」に改めれば 6件すべて OK になる。

`CLAUDE.md`「実験・検証の進め方」手順4（事後解釈の禁止）に抵触する。

## 判定（FR-M2-005）

### 結論: **No-Go**（2026-09-07）

| 判定条件（`requirements.md` FR-M2-003） | 実測 | 充足 |
|---|---|---|
| 逆引き成功率が 90% 以上 | **93.3%**（56/60） | **満たす** |
| 抜き取り確認（各 stage `min(3, 件数)` 件）に全件合格 | **6件中 1件 NG** | **満たさない** |

`requirements.md` FR-M2-003 受け入れ基準2-b は
「**確認した件のうち1件でも含まれていなければ（中略）成功率が 90% 以上でも Go にしない**」と
定めている。**文言どおり No-Go とする。**

### No-Go の性質（重要）

**逆引きの手順に欠陥があったのではなく、その正しさを確かめる「確認手段」の記述に不備があった。**

- NG になった1件は、逆引きが**正しいブロックを指していた**（キーはブロックに含まれる）
- `context`（前後15文字）が md 上で直前の数式ブロックをまたいでいたため、
  ブロック単位の `text` に収まらず False になった
- `design.md` §7.7 は確認対象を「候補の `context` に**対応する文字列**」としか書いておらず、
  それが `context` 全体か逆引きに使ったキーかを定めていなかった

### 事後解釈をしなかった理由

確認手段を「逆引きに使ったキーが含まれること」に読み替えれば 6件すべて OK になる。
しかし**それは criteria lock 済みの受け入れ基準を実測後に変更すること**であり、
`CLAUDE.md`「実験・検証の進め方」手順4（事後解釈の禁止）に抵触する。
**実測を見てから基準の解釈を選べる状態そのものが、基準の不備である。**
