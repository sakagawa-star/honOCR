## 1.0 第2版の改訂（2026-09-07）

### 改訂の理由

第1版で M2 を実施した結果、検査1・2 は合格し、逆引きの成功率は **93.3%**（合格ライン 90%）に達したが、
**逆引き結果の正しさを確かめる「抜き取り確認」の定義に不備があり、No-Go となった**
（`experiment_log.md`）。確認の対象を「候補の `context`（前後15文字）に対応する文字列」とだけ定めており、
**`context` が md 上で要素の境界（数式ブロック等）をまたぐと、content_list のブロック単位のテキストに
収まらない**ことを考慮していなかった。逆引きが正しい件を NG と判定した。

さらに、検証手段を設計し直すにあたり実データを調べた結果、**md と content_list の対応だけでは
決着しない型が実在する**ことが判明した（原本の図キャプションのように、md には行があるが content_list に
対応するテキストを持たない要素がある）。このため**原本ページの画像による確認**を併用する方針を
ユーザーが決定し、`../roadmap.md` を第2版に改訂した（前提14・M2 の入力に原本 TIF を追加）。

### 第2版で変わること

| 項目 | 第1版 | 第2版 |
|---|---|---|
| 逆引きの正しさの確認 | FR-M2-003 受け入れ基準2-b・2-c（**目視6件**。`context` の包含で判定） | **FR-M2-006（検査4）として独立**。**4-A: 逆引きに成功した全件の機械検査**（md の論理行を単位とする）＋ **4-B: 原本の切り出し画像による目視確認** |
| 原本 TIF | 開かない（範囲外） | **検査4-B で開く**（読み取りのみ。`../roadmap.md` M2 の入力） |
| 検査1・2・3 | 実施 | **再実施しない**（第1版の実測が有効。`experiment_log.md` に予測・実測・照合を記録済みで、検査3 の再現性も確認済み） |

**検査1・2・3 の判定基準（FR-M2-001・002・003）は第1版から一切変更しない。**
実測後に基準を変更しないという規律（`CLAUDE.md`「実験・検証の進め方」手順4）に従う。

### 実データを先に見たことの開示と、それが判定の設計に与える帰結

第1版の失敗が「**文書レビューだけでは分からない、確認手段と対象の不整合**」であったため、
第2版では規則を確定する前に実データを見ている。**見た範囲は次の2つである。**

| # | 先に見たもの | 範囲 |
|---|---|---|
| 1 | **4-A の規則を第1版の逆引き結果（56件）に当てた予備確認** | **全件**（Claude Code・2026-09-07） |
| 2 | **原本ページ画像を1枚** | chap06 `page_idx=8`（`--margin 1000` でページ全体を切り出せることの確認） |

**帰結（判定の設計）**: 1 により **4-A の結果は実行前におおむね既知である**。
既知の結果を予測して再実行しても、**現象についての事前検証にはならない**。
したがって次のように設計する。

- **4-A は「測定」と「4-B の対象選定」に用い、それ自体を Go / No-Go の合否条件にしない**
  （`CLAUDE.md`「実験・検証の進め方」手順1 の「基準を測ることがゴールの実験」に当たる）。
  4-A の予測と照合は、**規則どおりに実装されたかの確認**として行う（この位置づけを明記して記録する）
- **判定の根拠は 4-B（原本画像による目視）に置く。** 原本は md・content_list のいずれとも独立した基準であり、
  **上記2 の1枚を除いて未観測**である。2 に当たる件が 4-B の対象に選ばれた場合は、
  **先に見たことを記録に明記したうえで、他の件と同じ基準で確認する**

**この設計は、実測を見てから基準を緩めたものではない**（4-A は実行前から合否条件に用いない）。

## 1.1 プロジェクト概要

### 何を作るのか

M1 が確定した母集団（4,624 候補）について、次の4つを確かめる。

1. **除外領域の対が閉じているか**（母集団に不正な候補が混入していないか）
2. **feat-021 が `D4`（数式の不一致）と判定した Q&A 見出し16件が母集団にどれだけ含まれるか**
3. **原本ページの逆引きが実用に足る成功率を持つか**
4. **逆引きの結果が正しいか**（特定したブロック・推定したページに、候補が本当に存在するか）

**3 と 4 の両方が、標本抽出に進んでよいかの判断になる。**
成果物は、検査用のスクリプトと、予測・実測・照合を記録した `experiment_log.md`、
および検査4-B で用いた原本の切り出し画像（リポジトリ外）である。

### なぜ作るのか（解決したい課題）

**逆引きに失敗した候補は原本の該当ページを開けず「判定不能」になる。**
判定不能が多いと母比率の推定そのものが成り立たない。
`../survey_notes.md` §7.1 の予備実測では、1段階目の逆引きの成功率は所在によって大きく異なり
（`body` 91.4% / `footnote` 75.7% / `table` 0%）、2段階目を含めた成功率は**未実測**である。

**130件の標本を採って突合する前に、逆引きが実用に足ることを確かめる**（`../roadmap.md` 前提11）。
あわせて、母集団そのものが信用できること（1・2）を確認する。

**成功率だけでは足りない理由**: 逆引きが**誤ったページ・ブロックを指していても成功率には現れない**。
誤った逆引きのまま M4 に進むと、原本に無い記号を探すか、**別の記号を対象と取り違えて判定する**
ことになり、推定の土台が崩れる。したがって成功率（検査3）と正しさ（検査4）を別に測る。

### 誰が使うのか（ユーザー像）

- **実行者**: Claude Code 本体（検査の実施と判定）
- **結果の読み手**: ユーザー（M3 に進むか、ロードマップを改訂するかの判断材料）

### どこで使うのか（実行環境の概要）

Ubuntu（Linux 6.14）、Python 3.12、uv 管理の既存プロジェクト環境。GPU 不要・ネットワーク不要。
入力（M1 の候補 TSV・成果物 md・content_list）はいずれも**リポジトリ外**（`{BASE2}` 配下）にある。

## 1.2 用語定義

`../survey_notes.md` §2 の定義に従う。本書で新たに定義する用語は次のとおり。

| 用語 | 定義 |
|---|---|
| **候補 TSV** | M1 が出力した `{BASE2}/ocr/collation/feat-024_candidates.tsv`（4,782行＋ヘッダ） |
| **母集団** | 候補 TSV のうち `location` が `table` 以外の 4,624 件（`../roadmap.md` 前提6） |
| **除外領域** | 数式ブロック（行頭 `$$` の対）・コードブロック（行頭フェンスの対）・画像参照（`../survey_notes.md` §3 手順1・2） |
| **逆引き** | 候補の md 上の位置から、`bbox`・`page_idx` を持つ content_list のブロック、または原本ページを特定すること |
| **逆引きの段階** | `block`（content_list のブロックを一意に特定）/ `page`（**前後の近傍候補から推定したページが一致**）/ `none`（特定不能、または前後の推定が不一致） |
| **逆引き成功** | 逆引きの段階が `block` または `page` であること（`none` 以外） |
| **ページ推定の一致検証** | 対象候補の前方向と後方向の双方から近傍候補を探し、**両方向で得た `page_idx` が一致する**ことを確認すること |
| **章内候補列** | 同じ章の候補（`table` を含む）を `offset` 昇順に並べたもの。逆引きの2段階目はこの列を走査する |
| **検査標本** | 検査3 のために母集団から無作為抽出する候補の集合。**M3 で採る標本とは別物**であり、突合には使わない |
| **論理行** | md を改行（`\n`）で分割した1行。**行頭 `$$` の数式ブロックや行頭フェンスのコードブロックは行の内側に現れない**ため、論理行は要素の境界をまたがない |
| **行キー** | 候補を含む論理行に `norm()`（`design.md` §7.2 の正規化）を適用した文字列。**検査4-A の照合の単位**である |
| **一意対応行** | 行キーの長さが **6 文字以上**で、その章の content_list のブロックのうち**ちょうど1件**の `norm(text)` に部分文字列として含まれる論理行。そのブロックの `page_idx` を「その行のページ」とする |
| **積極的な食い違い** | 検査4-A で、逆引きが示したブロック・ページと、行キーから独立に得られたブロック・ページが**異なる**こと（決着しない `undetermined` とは区別する） |
| **原本ページ画像** | `scripts/crop_blocks.py`（feat-021）で原本 TIF から切り出した PNG。検査4-B で用いる |

## 1.3 機能要求一覧

### FR-M2-001: 検査1 — 除外領域の対が閉じているか

**機能名**: 除外領域の対の検査

**第2版での扱い**: **第1版で実施済み・合格**（`experiment_log.md`）。**第2版では再実施しない。**
以下の判定基準は第1版から変更していない（記録の参照先として残す）。

**概要**: 各章の md について、コードフェンス（行頭 ```` ``` ````）と数式ブロックの区切り（行頭 `$$`）の
出現回数を数え、**対が閉じている**ことを確認する。

**なぜ必要か**: `../m1-scan-cli/design.md` §6 のとおり、対が閉じていない領域は
**マスクされず、内側の文字が候補になる**。奇数であれば母集団に不正な候補が混入している。

**入力**: `{BASE2}/ocr/final/chapNN/chapNN_gray300.md`（全10章）

**出力**: 章ごとの出現回数（コードフェンス・`$$` の各行数）と偶奇の判定

**受け入れ基準**:

1. 全10章について、行頭コードフェンスの出現回数が**偶数**である
2. 全10章について、行頭 `$$` の出現回数が**偶数**である
3. 章ごとの実測値が `experiment_log.md` に記録されている
4. **1 または 2 を満たさない章がある場合、M3 に進まず原因を特定する**（`../roadmap.md` M2 の完了条件は
   「検査が全10章で合格すること」であり、不合格のまま先に進まない）

### FR-M2-002: 検査2 — feat-021 の `D4` 16件の被覆

**機能名**: `D4` 16件が母集団に含まれるかの確認

**第2版での扱い**: **第1版で実施済み・合格**（`covered` 7 / `not_covered` 9 / `heading_not_found` 0）。
**第2版では再実施しない。** 以下の判定基準は第1版から変更していない。

**概要**: feat-021 が `D4`（数式の不一致）と判定した Q&A 見出し18件のうち、
feat-023 で解消した2件を除く**16件**について、その見出し行に属する候補が母集団に含まれるかを調べる。

**対象の16件**（`../survey_notes.md` §1.2）:

| 章 | 番号 |
|---|---|
| chap02 | 2.1 / 2.4 / 2.7 / 2.12 |
| chap03 | 3.3 |
| chap04 | 4.5 / 4.8 |
| chap05 | 5.1 / 5.6 |
| chap07 | 7.1 / 7.3 / 7.4 |
| chap08 | 8.4 / 8.7 |
| chap09 | A.2 / B.1 |

**入力**: 候補 TSV、`{BASE2}/ocr/final/chapNN/chapNN_gray300.md`（全10章）

**出力**: 16件それぞれについて、見出し行の行番号・その行に属する候補の件数と種別・母集団に含まれるか

**受け入れ基準**:

1. **16件すべてについて、md 上の見出し行が特定できている（`heading_not_found` が 0 件）**。
   feat-020 により**全74件が `## ? N.M …` の見出し行になっている**ため（`../survey_notes.md` §1.2）、
   特定できない件があることは**前提が崩れていることを意味する**。
   **1件でもあれば検査3 に進まず中断し、原因を特定して報告する**（`../roadmap.md` の改訂に進むか
   どうかはユーザーの判断を仰ぐ）。これは検査1 の不合格と同じ扱いである
2. 16件それぞれについて、母集団に含まれるか（含まれる場合は候補の件数と種別）が記録されている
3. **`not_covered` の件について、次の分類のいずれかが記録されている**（原本を見ずに md の状態から
   機械的に判定する。原本 TIF は開かない）

   | 分類 | 意味 |
   |---|---|
   | `no_symbol` | その見出し行に候補が1件も無い（数式マークアップも平文の数学記号も md に現れない） |
   | `table_only` | 候補はあるが所在がすべて `table` である（母集団外のため `not_covered` になった） |

   **この2値で網羅的である**（`design.md` §5.3 の3分岐による）。
   分類は**検査2 の出力 TSV の `not_covered_reason` 列**に記録し、
   **分類別の件数を `experiment_log.md` に記録する**（M5 の報告に引き渡すため）。
   **`covered` / `not_covered` の判定は母集団の候補（`location != table`）の有無で行う**
   （`table` の候補は `covered` に数えない）

4. **`covered` の件数に合格ラインを設けない。** 16件すべてが母集団に含まれる必要はなく、
   **含まれない件数（`not_covered`）は「本手法で検出できない型」の実測値として M5 の報告に載せる**
   （`../roadmap.md` §1.1 Q3 の性格。未知の量を既知のように扱わない）。
   **合格ラインを設けないのは `not_covered` の件数だけであり、`heading_not_found` は 1 の合格条件である**

### FR-M2-003: 検査3 — 逆引きの成功率（判断の境界）

**機能名**: 逆引き可能性の判定

**第2版での扱い**: **第1版で実施済み**（成功率 **93.3%** = 56/60。`block` 50 / `page` 6 / `none` 4）。
**第2版では再実施しない**（再現性も確認済み。同じシードでの再実行がバイト同一）。
以下の判定基準は第1版から変更していない。**第1版にあった受け入れ基準 2-b・2-c（抜き取り確認）は
FR-M2-006（検査4）に移し、内容を全面的に作り直した。**

**概要**: 母集団から**無作為抽出した検査標本**について逆引きを行い、成功率を測定する。
**この結果は、検査4 とあわせて M3 に進んでよいかの判断になる。**

**検査標本の設計（実行前に固定する。criteria lock の対象）**:

| 項目 | 値 |
|---|---|
| **標本サイズ** | **60 件** |
| **抽出方法** | 母集団（`location != table` の 4,624 件）からの**単純無作為抽出（非復元）** |
| **乱数シード** | **20260907**（固定） |
| **層別** | **行わない**（母集団全体から一様に抽出する） |
| **並び順** | 母集団を `chapter` 昇順 → `offset` 昇順にソートしたものを抽出母体とする |

**標本サイズを 60 件とする根拠**: 合格ライン 90% を判定するための最小限の精度を確保する。
真の成功率が 90% のとき、60 件の標本で観測される成功数は二項分布 B(60, 0.9) に従い、
標準偏差は約 2.3 件（3.9 ポイント）である。**合否の境界を大きく誤る確率が低く、
かつ M3 の標本 130 件に対して十分小さい**（検査に時間をかけすぎない）。
`../survey_notes.md` §7.1 の予備実測も章ごとに 60 件を用いており、実測値と比較できる。

**検査標本は M3 の標本とは別物である。** 突合には使わず、逆引きが成功したかどうかだけを見る。
**乱数シードを M3（別途 M3 の `requirements.md` で定める）と別にする**のは、
検査標本と本番の標本が重なることによる偏りを避けるためである。

**入力**: 候補 TSV、`{BASE2}/ocr/final/chapNN/chapNN_gray300_content_list.json`（全10章）

**出力**: 検査標本 60 件それぞれの逆引きの段階（`block` / `page` / `none`）と、成功率

**`page` を成功に数える条件（実行前に固定する）**: `page` は近傍候補からの**推定**であり、
対象候補が本当にそのページにあることをスクリプトは検証しない。誤った推定を成功として
数えないため、次を満たす場合に限り `page` とする。

1. 対象候補の**前方向と後方向の双方**から近傍候補を探し、**両方向で得た `page_idx` が一致**すること
2. 一方向のみの結果を採ってよいのは、**もう一方の方向に候補が1件も存在しない場合に限る**
   （＝対象候補が**章内候補列の先頭または末尾**である場合。構造上、一致検証ができない）。
   **この条件は「その方向の候補数が 0 であること」を明示的に検査して判定する**
3. **両方向で得た `page_idx` が一致しない場合は `none` とする**（成功に数えない）
4. **その方向に候補が存在するのに、探索の打ち切り（`design.md` §7.2 の上限）までに
   逆引きできる候補が見つからなかった場合は `none` とする**（成功に数えない）。
   打ち切りは「章の端である」ことを意味しないため、2 の条件を満たさない

**受け入れ基準**:

1. **逆引き成功率（`block` と `page` の合計 ÷ 60）が 90% 以上である**
   （= `none` が **6 件以下**）
2. 段階別の件数（`block` / `page` / `none`）と、`none` の内訳
   （**近傍候補が見つからなかった件数**と**前後の推定が不一致だった件数**）が記録されている
3. **所在別（`body` / `footnote`）の内訳**が記録されている
   （`../survey_notes.md` §7.1 の予備実測と比較できるようにするため）
4. `none` になった件について、`reason`（`page_mismatch` / `search_exhausted` / `no_neighbor`）ごとの
   件数が記録されている
5. **再現性**: 同じ乱数シード（20260907）で検査標本の抽出を再実行すると、**同じ60件が得られる**
   （`design.md` §6.2 の `diff` が無出力）
6. **1 を満たさない場合、合格ラインを緩めない。** M3 に進まず、
   「満たさなかった事実」と「逆引き手順の見直し案」を報告し、
   `../roadmap.md` の改訂（再計画）に進むかどうかはユーザーの判断を仰ぐ
   （**逆引き結果の正しさの判定は FR-M2-006 で定める**）

### FR-M2-006: 検査4 — 逆引き結果の正しさの検証（判断の境界）

**機能名**: 逆引き結果の検証

**概要**: 検査3 で逆引きに成功した全件（`stage != none`。第1版の実測では **56 件**）について、
**逆引きが指したブロック・ページに候補が本当に存在するか**を検証する。
検証は次の2段構えとし、**両方に合格して初めて検査4 に合格**とする。

| 段 | 名称 | 対象 | 手段 | 判定における役割 |
|---|---|---|---|---|
| **4-A** | 機械検査 | **逆引きに成功した全件** | 候補を含む**論理行**を単位に、md と content_list の対応を機械的に照合する（`design.md` §7A） | **測定と 4-B の対象選定**（**合否条件にしない**。§1.0） |
| **4-B** | 目視確認 | **4-A で決まる件**（下記） | **原本 TIF の切り出し画像**で、候補の記号がその位置に実在することを目視する | **合否の判定** |

**なぜ2段構えにするのか**: 4-A は全件を機械的に見られるが、**md と content_list という
2つの成果物の対応**を見ているにすぎない。両者に共通する誤り（同じ OCR 実行に由来する
ページ割り当ての誤り等）は 4-A では捉えられない。4-B は**原本という外部の基準**に照らすが、
目視のため少数しか見られない。**4-A で全件を分類して疑わしい件を洗い出し、
それを 4-B で原本に照らす**——網羅性（4-A）と基準の独立性（4-B）を組み合わせる。

**合否を 4-B に置く理由**: 原本は md・content_list のいずれとも独立した基準であり、
「候補が本当にそこにあるか」を決着させられる唯一の材料である。
また 4-A の結果は規則の予備確認によりおおむね既知であり（§1.0）、合否条件に使えない。

**4-A が逆引きの再実行にならない理由**: 逆引きは候補の**前後10文字（必要なら30文字）のキー**で
ブロックを探す。4-A は**論理行の全体**を単位とし、行が一意に対応づかない場合は**前後の一意対応行**で
ページを挟み込む。**照合の単位も、決着のつけ方も異なる**ため、逆引きが誤っていれば食い違いが現れる。

**入力**: 検査3 の出力 TSV（`{BASE2}/ocr/collation/feat-024_m2_locate_sample.tsv`）、
成果物 md と content_list（全10章）、**原本 TIF**（`{BASE2}/dewarping/chapNN/out/`。4-B のみ）

**出力**: 4-A の分類を付した TSV（`{BASE2}/ocr/collation/` 配下）、
4-B の切り出し画像（同）、`experiment_log.md` への記録

---

#### 4-A: 機械検査（全件）

**判定区分**（1件につき1つ。定義と手順は `design.md` §7A.2）:

| 区分 | 対象の stage | 意味 | 扱い |
|---|---|---|---|
| `line_in_block` | `block` | 行キーが、逆引きが特定したブロックの `norm(text)` に含まれる | **合格** |
| `block_fragment` | `block` | 逆引きが特定したブロックの `norm(text)`（6文字以上）が行キーに含まれる（MinerU が1行を複数ブロックに分断した既知の型。`docs/PROJECT_KNOWLEDGE.md` feat-015） | **合格** |
| `line_unique_page` | `page` | 候補の論理行が**一意対応行**であり、そのページが逆引きの推定ページと一致する | **合格** |
| `neighbor_bracket` | `page` | 候補の論理行が一意対応行でないとき、**前後それぞれ最も近い一意対応行**の両方のページが推定ページと一致する | **合格** |
| `block_mismatch` | `block` | 上のいずれにも当たらない（行キーとブロックのテキストが互いに含み合わない） | **要確認**（積極的な食い違い） |
| `page_mismatch_line` | `page` | 候補の論理行が一意対応行だが、そのページが推定ページと**異なる** | **要確認**（積極的な食い違い） |
| `neighbor_mismatch` | `page` | 前後の一意対応行が見つかったが、いずれかのページが推定ページと**異なる** | **要確認**（積極的な食い違い） |
| `undetermined` | 両方 | 行キーが短い（6文字未満）、前後の走査上限内に一意対応行が無い等で**機械的に決着しない** | **要確認**（未決着） |

**「要確認」の扱い**: **4-A の段階では合否を決めない。要確認の件は全件を 4-B の対象に加え、
原本で決着させる**（4-B の対象(i)）。**4-A の区分そのものは Go / No-Go の条件にしない**（§1.0）。

**受け入れ基準**:

1. **逆引きに成功した全件に、上の区分のいずれかが付いている**（未分類ゼロ）
2. 区分別の件数が `experiment_log.md` に記録されている
3. **要確認（積極的な食い違い3区分 ＋ `undetermined`）の件が、4-B の対象(i) として全件挙がっている**
4. **要確認の件数によって作業を止める条件を設けない。** 件数にかかわらず**全件を 4-B で確認し、
   判定には 4-B の結果だけを使う**（4-A の結果で M3 への進行を止めない。§1.0 の帰結）
5. **再現性**: 同じ入力に対する再実行が同一の出力になる（乱数・時刻に依存しない）
6. **4-A の結果を Go / No-Go の合否条件にしない**（§1.0 の帰結）。
   4-A の予測と照合は、**規則どおりに実装されたかの確認**として行い、
   その位置づけを `experiment_log.md` に明記する

#### 4-B: 原本画像による目視確認

**対象**（この2つの和集合。**乱数を使わない**）:

| # | 対象 |
|---|---|
| **(i)** | 4-A で**要確認**になった件（`block_mismatch` / `page_mismatch_line` / `neighbor_mismatch` / `undetermined`）の**全件** |
| **(ii)** | 4-A の**合格区分**（`line_in_block` / `block_fragment` / `line_unique_page` / `neighbor_bracket`）の件から、`stage` ごとに **`min(3, その stage の合格件数)` 件**を下記の規則で選んだもの |

**(ii) の並べ替えの規則**（この順に並べ、先頭から採る）:

| stage | 規則 |
|---|---|
| `block` | `reason` の優先順（**`block_key30` → `block_key10`**）→ `chapter` 昇順 → `offset` 昇順 |
| `page` | `reason` の優先順（**`page_head` → `page_tail` → `page_both`**）→ `chapter` 昇順 → `offset` 昇順 |

**優先順の根拠**（第1版から変更なし）: `page_head` / `page_tail` は前後の一致検証が原理的にできない件、
`block_key30` はキーを広げて初めて一意一致を得た件であり、**いずれも誤りやすい側**である。

**確認の方法**（手順とコマンドは `design.md` §7A.3）:

| stage | 切り出す範囲 | 確認すること |
|---|---|---|
| `block` | 逆引きが特定した**ブロックの領域**（`--index {block_index}`） | **候補の論理行に対応する行**がその領域の中にあり、その行の中に候補の記号がある |
| `page` | 推定した**ページ全体**（`--margin 1000`） | **候補の論理行に対応する行**がそのページの中にあり、その行の中に候補の記号がある |

**確認の単位は「記号」ではなく「候補の論理行」である。** 記号だけを探すと、
**同じ記号が同一ページ内の別の場所に現れている場合に、別の出現を見て OK と判定してしまう**。
候補の論理行（記号とその前後の語句）を原本の紙面上で同定し、**その行の中に記号があること**を確認する。

**同定の基準**: OCR の誤読により md の文言と原本の文言が細部で異なることがあるため、
**文字単位の完全一致は求めず、「同じ行であると同定できるか」で判断する**。
次のいずれかに当たる場合は **NG** とする。

- 原本のページ（またはブロック）の中に、候補の論理行に対応する行を**見つけられない**
- 対応しうる行が**複数あり、候補の出現を一つに決められない**（同一の文言が複数箇所にある場合）
- 行は同定できたが、**その行の中に候補の記号が無い**

**受け入れ基準**:

1. **対象の全件について、候補の記号が原本の該当箇所に存在することを確認できている**。
   **1 件でも確認できなければ検査4 は不合格**とし、成功率が合格ラインを満たしていても **Go にしない**
2. **監査可能性**: 確認した各件の **`chapter`・`offset`・`stage`・`reason`・4-A の区分・
   切り出し画像のファイル名・確認結果** が `experiment_log.md` に記録されている。
   **確認結果は次の4値のいずれかとする**: `OK`（行を同定でき、その行に候補の記号がある）/
   `NG-not_found`（対応する行を見つけられない）/ `NG-ambiguous`（対応しうる行が複数あり一意に決められない）/
   `NG-no_symbol`（行は同定できたが、その行に候補の記号が無い）。**`OK` 以外はすべて不合格である**。
   **記録が無い、または記録された件が (i)(ii) の規則と一致しない場合は、4-B を満たしたとみなさない**。
   **書籍本文は記録しない**（§1.5 制約1）
3. **判定の範囲を超えない**: 4-B で確かめるのは**候補がそこに存在すること**だけであり、
   **その記号が原本で数式として組まれているか（欠落かどうか）は判定しない**（それは M4 の作業である）
4. 切り出し画像は `{BASE2}/ocr/collation/` 配下に置き、**リポジトリに置かない**（§1.5 制約1）。
   **同じ `(chapter, stage, --index の値)` の対象が複数あるときは、画像を1枚だけ生成し、
   各件の記録から同じファイル名を参照する**（`design.md` §7A.4 手順3）。
   **`stage` が異なれば切り出す範囲が異なるため、同じ `index` でも別の画像を生成する**
5. **設計時に先に見た1枚（chap06 `page_idx=8`。§1.0）に当たる件が対象に含まれた場合は、
   そのことを記録に明記したうえで、他の件と同じ基準で確認する**（除外も特別扱いもしない）
6. **要確認の件（対象(i)）については、確認結果に加えて「4-A が要確認とした原因」
   （逆引きの誤りか、検査規則の限界か）を記録する**

参考: 第1版で実施した3つの検査は合計 10 分以内という基準で、実測はこれを満たした。

### NFR-M2-004: 対応環境

Python 3.12 / uv 管理の既存環境で動作する。**新規ライブラリを追加しない。**

- 本マイルストーンで**新設するスクリプトは標準ライブラリのみ**を使う（Pillow を import しない）
- **原本画像の切り出しは既存の `scripts/crop_blocks.py`（feat-021）をそのまま実行する**。
  同スクリプトは既存依存の Pillow を使う。**`scripts/` 配下のコードは変更しない**
