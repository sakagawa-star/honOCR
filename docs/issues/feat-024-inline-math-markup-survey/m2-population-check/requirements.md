- **案件 / マイルストーン**: feat-024 / **M2**（`docs/issues/feat-024-inline-math-markup-survey/m2-population-check/`）
- **作成日**: 2026-09-07

## 1.1 プロジェクト概要

### 何を作るのか

M1 が確定した母集団（4,624 候補）について、次の3つを確かめる。

1. **除外領域の対が閉じているか**（母集団に不正な候補が混入していないか）
2. **feat-021 が `D4`（数式の不一致）と判定した Q&A 見出し16件が母集団にどれだけ含まれるか**
3. **原本ページの逆引きが実用に足る成功率を持つか** ← **標本抽出に進んでよいかの判断**

成果物は、検査用のスクリプトと、予測・実測・照合を記録した `experiment_log.md` である。

### なぜ作るのか（解決したい課題）

**逆引きに失敗した候補は原本の該当ページを開けず「判定不能」になる。**
判定不能が多いと母比率の推定そのものが成り立たない。
`../survey_notes.md` §7.1 の予備実測では、1段階目の逆引きの成功率は所在によって大きく異なり
（`body` 91.4% / `footnote` 75.7% / `table` 0%）、2段階目を含めた成功率は**未実測**である。

**130件の標本を採って突合する前に、逆引きが実用に足ることを確かめる**（`../roadmap.md` 前提11）。
あわせて、母集団そのものが信用できること（1・2）を確認する。

### 誰が使うのか（ユーザー像）

- **実行者**: Claude Code 本体（検査の実施と判定）
- **結果の読み手**: ユーザー（M3 に進むか、ロードマップを改訂するかの判断材料）

### どこで使うのか（実行環境の概要）

Ubuntu（Linux 6.14）、Python 3.12、uv 管理の既存プロジェクト環境。GPU 不要・ネットワーク不要。
入力（M1 の候補 TSV・成果物 md・content_list）はいずれも**リポジトリ外**（`{BASE2}` 配下）にある。

## 1.2 用語定義

`../survey_notes.md` §2 の定義に従う。本書で新たに定義する用語は次のとおり。

| 用語 | 定義 |
|---|---|
| **候補 TSV** | M1 が出力した `{BASE2}/ocr/collation/feat-024_candidates.tsv`（4,782行＋ヘッダ） |
| **母集団** | 候補 TSV のうち `location` が `table` 以外の 4,624 件（`../roadmap.md` 前提6） |
| **除外領域** | 数式ブロック（行頭 `$$` の対）・コードブロック（行頭フェンスの対）・画像参照（`../survey_notes.md` §3 手順1・2） |
| **逆引き** | 候補の md 上の位置から、`bbox`・`page_idx` を持つ content_list のブロック、または原本ページを特定すること |
| **逆引きの段階** | `block`（content_list のブロックを一意に特定）/ `page`（**前後の近傍候補から推定したページが一致**）/ `none`（特定不能、または前後の推定が不一致） |
| **逆引き成功** | 逆引きの段階が `block` または `page` であること（`none` 以外） |
| **ページ推定の一致検証** | 対象候補の前方向と後方向の双方から近傍候補を探し、**両方向で得た `page_idx` が一致する**ことを確認すること |
| **章内候補列** | 同じ章の候補（`table` を含む）を `offset` 昇順に並べたもの。逆引きの2段階目はこの列を走査する |
| **検査標本** | 検査3 のために母集団から無作為抽出する候補の集合。**M3 で採る標本とは別物**であり、突合には使わない |

## 1.3 機能要求一覧

### FR-M2-001: 検査1 — 除外領域の対が閉じているか

**機能名**: 除外領域の対の検査

**概要**: 各章の md について、コードフェンス（行頭 ```` ``` ````）と数式ブロックの区切り（行頭 `$$`）の
出現回数を数え、**対が閉じている**ことを確認する。

**なぜ必要か**: `../m1-scan-cli/design.md` §6 のとおり、対が閉じていない領域は
**マスクされず、内側の文字が候補になる**。奇数であれば母集団に不正な候補が混入している。

**入力**: `{BASE2}/ocr/final/chapNN/chapNN_gray300.md`（全10章）

**出力**: 章ごとの出現回数（コードフェンス・`$$` の各行数）と偶奇の判定

**受け入れ基準**:

1. 全10章について、行頭コードフェンスの出現回数が**偶数**である
2. 全10章について、行頭 `$$` の出現回数が**偶数**である
3. 章ごとの実測値が `experiment_log.md` に記録されている
4. **1 または 2 を満たさない章がある場合、M3 に進まず原因を特定する**（`../roadmap.md` M2 の完了条件は
   「検査が全10章で合格すること」であり、不合格のまま先に進まない）

### FR-M2-002: 検査2 — feat-021 の `D4` 16件の被覆

**機能名**: `D4` 16件が母集団に含まれるかの確認

**概要**: feat-021 が `D4`（数式の不一致）と判定した Q&A 見出し18件のうち、
feat-023 で解消した2件を除く**16件**について、その見出し行に属する候補が母集団に含まれるかを調べる。

**対象の16件**（`../survey_notes.md` §1.2）:

| 章 | 番号 |
|---|---|
| chap02 | 2.1 / 2.4 / 2.7 / 2.12 |
| chap03 | 3.3 |
| chap04 | 4.5 / 4.8 |
| chap05 | 5.1 / 5.6 |
| chap07 | 7.1 / 7.3 / 7.4 |
| chap08 | 8.4 / 8.7 |
| chap09 | A.2 / B.1 |

**入力**: 候補 TSV、`{BASE2}/ocr/final/chapNN/chapNN_gray300.md`（全10章）

**出力**: 16件それぞれについて、見出し行の行番号・その行に属する候補の件数と種別・母集団に含まれるか

**受け入れ基準**:

1. **16件すべてについて、md 上の見出し行が特定できている（`heading_not_found` が 0 件）**。
   feat-020 により**全74件が `## ? N.M …` の見出し行になっている**ため（`../survey_notes.md` §1.2）、
   特定できない件があることは**前提が崩れていることを意味する**。
   **1件でもあれば検査3 に進まず中断し、原因を特定して報告する**（`../roadmap.md` の改訂に進むか
   どうかはユーザーの判断を仰ぐ）。これは検査1 の不合格と同じ扱いである
2. 16件それぞれについて、母集団に含まれるか（含まれる場合は候補の件数と種別）が記録されている
3. **`not_covered` の件について、次の分類のいずれかが記録されている**（原本を見ずに md の状態から
   機械的に判定する。原本 TIF は開かない）

   | 分類 | 意味 |
   |---|---|
   | `no_symbol` | その見出し行に候補が1件も無い（数式マークアップも平文の数学記号も md に現れない） |
   | `table_only` | 候補はあるが所在がすべて `table` である（母集団外のため `not_covered` になった） |

   **この2値で網羅的である**（`design.md` §5.3 の3分岐による）。
   分類は**検査2 の出力 TSV の `not_covered_reason` 列**に記録し、
   **分類別の件数を `experiment_log.md` に記録する**（M5 の報告に引き渡すため）。
   **`covered` / `not_covered` の判定は母集団の候補（`location != table`）の有無で行う**
   （`table` の候補は `covered` に数えない）

4. **`covered` の件数に合格ラインを設けない。** 16件すべてが母集団に含まれる必要はなく、
   **含まれない件数（`not_covered`）は「本手法で検出できない型」の実測値として M5 の報告に載せる**
   （`../roadmap.md` §1.1 Q3 の性格。未知の量を既知のように扱わない）。
   **合格ラインを設けないのは `not_covered` の件数だけであり、`heading_not_found` は 1 の合格条件である**

### FR-M2-003: 検査3 — 逆引きの成功率（判断の境界）

**機能名**: 逆引き可能性の判定

**概要**: 母集団から**無作為抽出した検査標本**について逆引きを行い、成功率を測定する。
**この結果が M3 に進んでよいかの判断になる。**

**検査標本の設計（実行前に固定する。criteria lock の対象）**:

| 項目 | 値 |
|---|---|
| **標本サイズ** | **60 件** |
| **抽出方法** | 母集団（`location != table` の 4,624 件）からの**単純無作為抽出（非復元）** |
| **乱数シード** | **20260907**（固定） |
| **層別** | **行わない**（母集団全体から一様に抽出する） |
| **並び順** | 母集団を `chapter` 昇順 → `offset` 昇順にソートしたものを抽出母体とする |

**標本サイズを 60 件とする根拠**: 合格ライン 90% を判定するための最小限の精度を確保する。
真の成功率が 90% のとき、60 件の標本で観測される成功数は二項分布 B(60, 0.9) に従い、
標準偏差は約 2.3 件（3.9 ポイント）である。**合否の境界を大きく誤る確率が低く、
かつ M3 の標本 130 件に対して十分小さい**（検査に時間をかけすぎない）。
`../survey_notes.md` §7.1 の予備実測も章ごとに 60 件を用いており、実測値と比較できる。

**検査標本は M3 の標本とは別物である。** 突合には使わず、逆引きが成功したかどうかだけを見る。
**乱数シードを M3（別途 M3 の `requirements.md` で定める）と別にする**のは、
検査標本と本番の標本が重なることによる偏りを避けるためである。

**入力**: 候補 TSV、`{BASE2}/ocr/final/chapNN/chapNN_gray300_content_list.json`（全10章）

**出力**: 検査標本 60 件それぞれの逆引きの段階（`block` / `page` / `none`）と、成功率

**`page` を成功に数える条件（実行前に固定する）**: `page` は近傍候補からの**推定**であり、
対象候補が本当にそのページにあることをスクリプトは検証しない。誤った推定を成功として
数えないため、次を満たす場合に限り `page` とする。

1. 対象候補の**前方向と後方向の双方**から近傍候補を探し、**両方向で得た `page_idx` が一致**すること
2. 一方向のみの結果を採ってよいのは、**もう一方の方向に候補が1件も存在しない場合に限る**
   （＝対象候補が**章内候補列の先頭または末尾**である場合。構造上、一致検証ができない）。
   **この条件は「その方向の候補数が 0 であること」を明示的に検査して判定する**
3. **両方向で得た `page_idx` が一致しない場合は `none` とする**（成功に数えない）
4. **その方向に候補が存在するのに、探索の打ち切り（`design.md` §7.2 の上限）までに
   逆引きできる候補が見つからなかった場合は `none` とする**（成功に数えない）。
   打ち切りは「章の端である」ことを意味しないため、2 の条件を満たさない

**受け入れ基準**:

1. **逆引き成功率（`block` と `page` の合計 ÷ 60）が 90% 以上である**
   （= `none` が **6 件以下**）
2. 段階別の件数（`block` / `page` / `none`）と、`none` の内訳
   （**近傍候補が見つからなかった件数**と**前後の推定が不一致だった件数**）が記録されている
2-b. **抜き取り確認**: `stage=block` と `stage=page` のそれぞれについて、
   **`min(3, その stage の件数)` 件**を**下記の決定的な規則**で選び、
   **候補の文脈に対応する文字列が、特定したブロック（`block`）または推定ページの
   content_list のブロック群（`page`）に含まれること**を目視で確認する。
   **乱数を使わない**（同じ逆引き結果からは常に同じ件が選ばれる）。

   | stage | 並べ替えの規則（この順で並べ、先頭から採る） |
   |---|---|
   | `page` | `reason` の優先順（**`page_head` → `page_tail` → `page_both`**）→ `chapter` 昇順 → `offset` 昇順 |
   | `block` | `reason` の優先順（**`block_key30` → `block_key10`**）→ `chapter` 昇順 → `offset` 昇順 |

   **優先順の根拠**: `page_head` / `page_tail` は前後の一致検証が原理的にできない件であり、
   `block_key30` はキーを広げて初めて一意一致を得た件である。**いずれも誤りやすい側**であるため、
   件数が少ないときに優先して確認する。

   **件数が 0 の stage は確認対象なしとし、Go の判定に影響させない**
   （例: 60件すべてが `block` で特定できた場合、`page` の確認は行わない）。
   **確認した件のうち1件でも含まれていなければ、逆引きの手順に欠陥があるとみなし、
   成功率が 90% 以上でも Go にしない**（`design.md` §7.7・§8.3）。
   原本 TIF は開かない（`requirements.md` §1.7 範囲外4）
2-c. **抜き取り確認の監査可能性**: 2-b で選んだ各件の **`chapter`・`offset`・`stage`・`reason`**と
   **確認結果（含まれていたか）**を `experiment_log.md` に記録する。
   これにより、**2-b の決定的な選択規則が実際に守られたかを事後に検証できる**
   （記録が無い、または記録された件が選択規則の順序と一致しない場合は、
   2-b を満たしたとみなさない）。**書籍本文は記録しない**（§1.5 制約1）
3. **所在別（`body` / `footnote`）の内訳**が記録されている
   （`../survey_notes.md` §7.1 の予備実測と比較できるようにするため）
4. `none` になった件について、`reason`（`page_mismatch` / `search_exhausted` / `no_neighbor`）ごとの
   件数が記録されている
5. **再現性**: 同じ乱数シード（20260907）で検査標本の抽出を再実行すると、**同じ60件が得られる**
   （`design.md` §6.2 の `diff` が無出力）
6. **1 または 2-b を満たさない場合、合格ラインを緩めない。** M3 に進まず、
   「満たさなかった事実」と「逆引き手順の見直し案」を報告し、
   `../roadmap.md` の改訂（再計画）に進むかどうかはユーザーの判断を仰ぐ

### FR-M2-004: 予測と実測の照合

**機能名**: `experiment_log.md` への記録

**概要**: `CLAUDE.md`「実験・検証の進め方」の手順2・3 に従い、
**各検査の実行直前に予測を数値で記録し、実行後に実測と照合する。**

**予測する項目の枠**（本書で事前定義する。値は実行直前に確定する）:

| 検査 | 予測する項目 |
|---|---|
| 検査1 | 章ごとのコードフェンスの出現回数・`$$` の出現回数（いずれも偶数か） |
| 検査2 | 16件のうち母集団に含まれる件数、含まれない件の内訳（種別ごと） |
| 検査3 | 逆引きの段階別件数（`block` / `page` / `none`）、`none` の内訳（前後不一致／探索打ち切り／候補なし）、`page` の内訳（前後一致／章の端）、成功率、所在別の内訳 |

**受け入れ基準**:

1. 3つの検査それぞれについて、**実行前の予測**が `experiment_log.md` に数値で記録されている
2. 実行後に実測が記録され、**予測との照合**（一致／乖離と、乖離した場合の原因）が記録されている
3. 予測を書かずに実行した検査がない

## 1.4 非機能要求

### NFR-M2-001: データ不変性（最重要）

**`{BASE2}` の既存データ**（`dewarping/`・`ocr/final/`・`ocr/fixes/`・`ocr/mineru-full/`）を
**一切変更しない**（`../roadmap.md` 前提13）。本マイルストーンは読み取りのみを行う。

**検証**: 作業の前後で上記4ディレクトリ配下の全ファイル（3,551 件）の SHA-256 を取得して比較し、
**差分が無いこと**（`diff` が無出力）を示す。

### NFR-M2-002: 再現可能性

検査標本の抽出は**乱数シードを固定**し、同じシードで何度実行しても同じ標本が得られること
（FR-M2-003 受け入れ基準5）。検査スクリプトは乱数・時刻・環境変数に依存しない。

### NFR-M2-003: 処理時間

3つの検査の合計が **10 分以内**に完了する。
（逆引きは content_list の全ブロックとの文字列照合を伴うため、検査1・2 より時間がかかる）

### NFR-M2-004: 対応環境

Python 3.12 / uv 管理の既存環境で動作する。**新規ライブラリを追加しない**
（標準ライブラリのみ。Pillow を含む既存依存も import しない）。

## 1.5 制約条件

1. **書籍本文をリポジトリに置かない**（`../roadmap.md` 前提12-b）。
   検査の出力に候補の文脈（書籍本文の断片）を含める場合は `{BASE2}/ocr/collation/` 配下に置く。
   **`experiment_log.md`（リポジトリ内）には件数と判定のみを書き、書籍本文を転記しない**
2. **`{BASE2}` の既存データを変更しない**（NFR-M2-001）
3. **新規ライブラリを追加しない**（NFR-M2-004）
4. **md を修正しない。** 検査で不一致が見つかっても修正しない（本案件は調査案件）
5. **合格ラインを事後に変更しない**（`CLAUDE.md`「実験・検証の進め方」手順4）
6. コーディング規約は `CLAUDE.md`「コーディング規約」に従う
