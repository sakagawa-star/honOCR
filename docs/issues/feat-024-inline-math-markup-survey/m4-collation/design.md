### 4.1 対象の抽出（**重複を必ず一意化する**）

**同じブロック・同じページに複数の標本がある。**（3 層の実測: `stage = block` は標本 106 件に対し
一意な `(chapter, block_index)` は **97**、`stage = page` は標本 30 件に対し一意な `(chapter, page_idx)` は **27**。）
`crop_blocks.py` は `--index` の重複をエラーとして終了する（`scripts/crop_blocks.py` の検査 4-0）ため、
**対象は必ず一意化してから CLI に渡す**（ADR-M4-6）。

```
# stage=block の対象（chapter, block_index）を一意化
awk -F'\t' 'NR>1 && $8=="block"{print $1"\t"$9}' {BASE2}/ocr/collation/feat-024_m3_located_{L}.tsv | sort -u
# stage=page の対象（chapter, page_idx）を一意化
awk -F'\t' 'NR>1 && $8=="page"{print $1"\t"$10}' {BASE2}/ocr/collation/feat-024_m3_located_{L}.tsv | sort -u
```

**層をまたいで同じブロック・ページが選ばれることもある**（層ごとに切り出すため、
`--overwrite` を付けて同じ画像を作り直してよい。内容は同一である）。

`stage = none` の件は**切り出さない**（FR-M4-001 受け入れ基準3）。

**標本と画像の対応は多対 1 である**（複数の標本が同じ画像を参照してよい）。
判定 TSV の各行に、参照した画像のパスを記録することで追跡可能性を保つ（§7.1）。

### 4.2 `stage = block` の切り出し

章ごとに、その章の対象ブロック番号をすべて `--index` に並べて 1 回で実行する。

```
uv run python scripts/crop_blocks.py \
  "{BASE2}/ocr/final/{chapter}/{chapter}_gray300_content_list.json" \
  "{BASE2}/dewarping/{chapter}/out" \
  -o "{BASE2}/ocr/collation/feat-024_m4_crops/block" \
  --index {block_index} [--index {block_index} ...] \
```

  幅 1,500 ピクセルに縮小する。**判定に必要な行の前後が入る**（feat-021 の実績）
- 出力ファイル名は `{chapter}_gray300_content_list_b{block_index}_p{page_idx}.png`（`crop_blocks.py` の規約）

```
uv run python scripts/crop_blocks.py \
```

## 6. 判定規則（FR-M4-002。**実測の途中で変えない**）

### 6.1 1 件の判定手順

1. 逆引き結果 TSV の当該行から `chapter`・`offset`・`symbol`・`context`・`stage`・`block_index`・`page_idx` を読む
2. 対応する切り出し画像（§4 の命名規約）を開く
3. `context`（候補の前後 15 文字）を手がかりに、画像中の**当該箇所**を特定する。
   **`context` に一致する箇所が画像内に複数あり、`context` の前後をさらに広げても
   （md の当該 `offset` 周辺を読み直しても）1 か所に絞れない場合は、
   ラベルを `判定不能`（理由 `ambiguous_match`）とし、推測で 1 か所を選ばない**
4. 層に応じて §6.2 または §6.3 の規則を適用し、ラベルを 1 つ選ぶ
5. §7 の様式で記録する

### 6.2 層G・層L の規則（`欠落` / `正当`）

md では**数式マークアップの外**にある記号について、**原本の組版**を見る。

| 原本の状態 | ラベル |
|---|---|
| その記号が**イタリック体**（変数の数式組版）で組まれている | **`欠落`** |
| その記号が**立体**（本文と同じ書体）で組まれており、本文の語・記号として使われている（「付録 A」「A 県」等） | **`正当`** |
| その記号が**数式ブロック・数式の一部**として組まれている（前後の記号と一体の数式） | **`欠落`** |
| 上記のいずれとも決められない | **`判定不能`**（§6.4） |

**イタリック体か立体かの判別が付かない場合は `判定不能`（理由 `illegible`）とし、推測でラベルを付けない。**

### 6.3 層C の規則（`劣化` / `正当`）

md では `$…$` の**内側**にある数式について、**書体情報**のみを比較する（内容の誤りは範囲外）。

| 比較する情報 | 判定 |
|---|---|
| 原本で**太字**（ベクトル）の記号が、md では太字でない（`\boldsymbol` 等が無い） | **`劣化`** |
| 原本で**ハット**（`^`）・**バー**（上線）・**チルダ**が付く記号に、md では付いていない | **`劣化`** |
| 原本の**下線**・**上下の装飾**が md に無い | **`劣化`** |
| 上記の書体情報が原本と md で一致している | **`正当`** |
| 原本の当該数式を確認できない | **`判定不能`**（§6.4） |

**添字・演算子・数値の誤りは判定に使わない**（`../roadmap.md` §8-4。範囲外）。

### 6.4 `判定不能` の理由コード（5 種。これ以外を作らない）

| コード | 条件 |
|---|---|
| `no_page` | `stage = none`（原本ページが特定できていない） |
| `not_in_crop` | 切り出し画像に `context` の該当箇所が写っていない（ページの取り違え・領域のずれ） |
| `illegible` | 画像が不鮮明で、書体（イタリック／立体、太字の有無等）を判別できない |
| `symbol_absent` | 画像の該当箇所に、md の候補に対応する記号が見当たらない（原本に無い、または md 側の混入） |
| `ambiguous_match` | `context`（前後 15 文字）に一致する箇所が**画像内に複数**あり、どれが当該の候補かを一意に決められない |

## 7. 記録の様式

### 7.1 判定 TSV（`m4-collation/judgments.tsv`。**書籍本文を含まない**）

**全 150 標本を収める単一ファイル**である。**層ごとに 50 行を追記する**（層G で新規作成しヘッダ＋50 行、

## 11. 設計判断の記録（ADR）

### ADR-M4-1: `stage = page` は**当該ページの最小 `block_index`** を `--index` に与え、`--margin 1000` で切り出す

- **採用**: 上記（§4.3）
- **却下**: `crop_blocks.py` にページ指定のオプションを追加する／ページ全体を切り出す新しいスクリプトを書く
- **理由**: 既存 CLI の引数だけでページ全体が得られることを M2 で実データ確認済みであり、**手段を増やさない**
  （手段を足せば `../roadmap.md` §5 の規則によりその手段の単体疎通の段が先に必要になる）。
  最小 `block_index` の取得は `python -c` のワンライナー（§4.3 に全文を記載）で行い、**ファイルを作らない**

### ADR-M4-2: 切り出し画像を `block/` と `page/` の**2 ディレクトリに分ける**

- **採用**: 上記
- **却下**: 1 つのディレクトリに出力する
- **理由**: `crop_blocks.py` のファイル名は `{stem}_b{index}_p{page}.png` で、
  `stage = page` の件は「そのページの最小 `block_index`」を使うため、**`stage = block` の件と同名になりうる**。
  同名になると余白の異なる画像が上書きされ、判定の対象が変わる（M2 の設計レビューで検出された型の誤り）

### ADR-M4-3: ラベルを 4 値に固定し、`判定不能` に理由コードを付ける

- **採用**: `欠落` / `劣化` / `正当` / `判定不能`（＋ 4 種の理由コード）
- **却下**: 「疑わしい」「要再確認」等の中間ラベルを設ける
- **理由**: `k_i` と `n'_i` は 4 値の計数で決まる（`../roadmap.md` §1.2）。中間ラベルを作ると計数が定義できない。
  理由コードは、判定不能率が想定を超えたときに原因を段別に切り分けるために要る

### ADR-M4-4: 実行単位を**1 層**とし、切り出しと判定を同じ単位に含める

- **採用**: 層ごとに「予測 → 切り出し → 判定」
- **却下**: 切り出しと判定を別の実行単位にする／150 件を 1 単位にする
- **理由**: 段4 の処理単位は 1 標本だが、予測は層ごとの計数（`k_i`・`n'_i`・判定不能率）に対して立てる。
  切り出しは機械的で、画像を**見る**のは判定の段階であるから、**層の開始前に予測を書けば、
  予測が実測に引きずられることはない**。150 件を 1 単位にすると、最初の層の結果を次の予測に使えない

### ADR-M4-5: 詳細記録は `{BASE2}`、判定 TSV はリポジトリに置く

- **採用**: §2 の表のとおり
- **却下**: 詳細記録もリポジトリに置く／判定 TSV に `context` 列を残す
- **理由**: 判定の根拠には原本の記述と md の本文が要る（NFR-M4-004）が、
  **書籍本文をリポジトリに置かない**（`../roadmap.md` 前提12-b）。
  段5 が必要とするのは計数であり、`(chapter, offset, kind)` と `label` があれば足りる

### ADR-M4-6: 切り出しの対象を**一意化**し、標本と画像の対応を**多対 1** とする

- **採用**: `(chapter, block_index)` と `(chapter, page_idx)` で `sort -u` してから `--index` に渡す。
  複数の標本が同じ画像を参照してよい
- **却下**: 標本ごとに 1 枚の画像を作る（標本と画像を 1 対 1 にする）
- **理由**: `crop_blocks.py` は `--index` の重複をエラーとして終了する（検査 4-0）。
  また同じブロックに複数の候補が含まれるのは自然であり（3 層の実測で `block` 106 標本 → 97 ブロック、
  `page` 30 標本 → 27 ページ）、同じ領域の画像を重複して作る意味が無い。
  追跡可能性は、判定 TSV の各標本行に参照した画像のパスを記録することで保たれる
