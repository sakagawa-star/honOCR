# feat-025 M1 要求仕様書: 抽出 CLI の単体疎通

- **マイルストーン**: M1（ステージ S1）
- **作成日**: 2026-09-09
- **関連**: `../roadmap.md`（§6 抽出規則 / §7 ステージ表 / §8 の S1 / §9 の M1）

## 1.1 プロジェクト概要

- **何を作るのか**: 成果物 Markdown から「数式マークアップの外側にあるギリシャ文字・数学記号」を 1 文字 1 件の**候補レコード**として抽出する CLI を作り、1 章（chap01）に通して動作を確認する
- **なぜ作るのか**: feat-025 の母集団（`roadmap.md` §2.1 の測定値 `N`）を機械的に確定させるため。本マイルストーンはその CLI が動くことだけを確かめる**手段の単体疎通**であり、`N` を決めるのは M2 である
- **誰が使うのか**: Claude Code（M2 で全10章に適用する）。および後続案件で同じ抽出を行う者
- **どこで使うのか**: honOCR リポジトリのローカル環境（Python 3.12、`uv run`）。GPU 不要、ネットワーク不要

## 1.2 用語定義

本マイルストーンの文書・コードで同じ語を使う。

| 用語 | 定義 |
|---|---|
| **数式マークアップ** | Markdown 中の `$$…$$`（ブロック）および `$…$`（インライン）。範囲の厳密な定義は `roadmap.md` §6 |
| **候補** | 数式マークアップの**外側**にある、`roadmap.md` §6 の対象文字集合に属する 1 文字。1 文字を 1 件と数える |
| **候補レコード** | 候補 1 件を表すデータ。章名・md 内の開始位置・該当文字・前後の文脈からなる。その成分数は候補ごとに可変で、`roadmap.md` §5 の `c_i` = `8 + min(40, o) + min(40, L − 1 − o)`（`o` = 開始位置、`L` = ファイルの文字数。`c_i ≤ 88`）に従う |
| **抽出規則** | 候補を決める規則。`roadmap.md` §6 に定義があり、本マイルストーンはそれを実装する |
| **章名** | `chap00`〜`chap09` の 6 文字。入力ファイルの親ディレクトリ名から取る |
| **マスク** | 数式マークアップの範囲を、**同じ文字数**の代替文字で置き換えること（文字位置を保つため） |

## 1.3 機能要求一覧

### FR-001 数式マークアップ範囲の除外

- **概要**: 入力 Markdown のうち、数式マークアップに一致する範囲を候補の探索対象から外す
- **入力**: Markdown のテキスト（UTF-8）
- **出力**: 数式マークアップの範囲を除外した探索対象
- **受け入れ基準**:
  - [ ] `$$…$$` に囲まれた範囲（改行をまたぐものを含む）の中の文字が候補にならない
  - [ ] `$…$` に囲まれた範囲（改行をまたがない）の中の文字が候補にならない
  - [ ] 除外の対象範囲が `roadmap.md` §6 の定義と一致する
  - [ ] 除外の処理が**文字位置を変えない**（FR-003 の開始位置が元の Markdown 上の位置と一致する）

### FR-002 候補文字の抽出

- **概要**: 除外後の探索対象から、対象文字集合に属する文字を 1 文字 1 件として集める
- **入力**: FR-001 の探索対象
- **出力**: 候補の開始位置の列
- **受け入れ基準**:
  - [ ] 対象文字集合が `roadmap.md` §6 の「文字集合（対象）」と一致する（ギリシャ文字ブロックと、列挙された数学記号）
  - [ ] `roadmap.md` §6 の「文字集合（対象外・保留）」の文字が候補にならない
  - [ ] 同じ入力に対して常に同じ結果を返す（乱数・外部状態・順序依存を含まない）

### FR-003 候補レコードの生成

- **概要**: 候補 1 件ごとに、章名・開始位置・該当文字・前後の文脈を持つレコードを作る
- **入力**: 入力ファイルのパスと、FR-002 の候補の開始位置
- **出力**: 候補レコード
- **受け入れ基準**:
  - [ ] 章名が入力ファイルの親ディレクトリ名と一致する
  - [ ] 開始位置が、元の Markdown の先頭からの文字数（0 始まり）と一致する
  - [ ] 該当文字が、その位置の 1 文字と一致する
  - [ ] 前後の文脈が、それぞれ該当文字の直前・直後の**最大 40 文字**である（`roadmap.md` §5 の `c_i` の定義。`min(40, ·)` の上限が 40）
  - [ ] ファイルの先頭・末尾付近で 40 文字に満たない場合、取れるだけの文字数になる（不足分を埋めない）。**このとき候補レコードの成分数は `c_i` < 88 になる**（`roadmap.md` §5。確率統計の全10章では該当する候補が 0 件であることが実測されており、本案件では全件 `c_i` = 88 になる）

### FR-004 候補レコードのファイル出力

- **概要**: 候補レコードを 1 件 1 行の JSON（JSONL）としてファイルに書き出す
- **入力**: FR-003 の候補レコードの列と、出力先のパス
- **出力**: JSONL ファイル
- **受け入れ基準**:
  - [ ] 1 行が 1 件の候補レコードで、JSON として読み戻せる
  - [ ] 改行・タブ・引用符を含む文脈が、書き出しと読み戻しで同一の文字列になる
  - [ ] 候補が 0 件のとき、0 バイトのファイルを出力する（エラーにしない）
  - [ ] 出力の順序が、入力ファイルの指定順、かつファイル内では開始位置の昇順である

### FR-005 CLI としての実行

- **概要**: コマンドラインから入力ファイルと出力先を指定して実行できる
- **入力**: コマンドライン引数（入力 Markdown のパス 1 個以上、出力先のパス）
- **出力**: 終了コード（**正常終了は 0 / 引数の形式・必須引数の誤りは 2 / その他の運用エラーは 1**）と、標準エラー出力への処理結果
- **受け入れ基準**:
  - [ ] **入力ファイルを 2 個以上指定できる**（M2 で全10章を 1 回で処理するため）
  - [ ] 入出力のパスをハードコードせず、すべて引数で受け取る（`CLAUDE.md`「コーディング規約」）
  - [ ] 処理したファイルごとの件数と合計件数が標準エラー出力に出る
  - [ ] 入力ファイルが存在しないとき、そのパスを標準エラー出力に示して終了コード 1 で終わる（一部だけ処理した結果を出力しない）
  - [ ] **必須引数が無い等、引数の形式が誤っているとき、使い方を表示して終了コード 2 で終わる**（`argparse` の標準の挙動。運用エラーの 1 と区別する）

### FR-006 出力先の保護

- **概要**: 既存ファイルを意図せず上書きしない
- **入力**: 出力先のパスと、上書きの可否を指定する引数
- **出力**: 上書きの実行、または拒否
- **受け入れ基準**:
  - [ ] 出力先が既に存在し、上書きを指定していないとき、書き込まずに終了コード 1 で終わる
  - [ ] 上書きを指定したときは既存ファイルを置き換える
  - [ ] 出力先の親ディレクトリが存在しないとき、作成してから書き込む

### FR-007 chap01 での動作確認（本マイルストーンの実行）

- **概要**: 完成した CLI を chap01 の Markdown に通し、候補レコードが出力されることを確認する
- **入力**: `{BASE2}/ocr/final/chap01/chap01_gray300.md`
- **出力**: 候補レコードの JSONL ファイルと、その件数
- **受け入れ基準**:
  - [ ] CLI が終了コード 0 で終わる
  - [ ] 出力された JSONL の**件数が `roadmap.md` §8 の S1 の想定値と幅の範囲に収まる**（判定の閾値は `roadmap.md` を参照する。本書には再掲も追加もしない）
  - [ ] 予測と実測の照合が `experiment_log.md` に記録されている
