## 1.4 各機能の詳細設計

### 1.4.1 数式マークアップ範囲のマスク（FR-001）

#### データフロー

- 入力: `md` … `str`（UTF-8 で読んだ Markdown の全文）
- 出力: `masked` … `str`（`md` と**同じ長さ**の文字列。数式マークアップの範囲が `\x00` に置き換わったもの）

#### 処理ロジック

```
MATH_RE = re.compile(r"\$\$.*?\$\$|\$[^$\n]*?\$", re.DOTALL)
MASK_CHAR = "\x00"

def mask_math(md):
    return MATH_RE.sub(lambda m: MASK_CHAR * len(m.group(0)), md)
```

（上のコードは意図の伝達のためのもので、そのまま貼るためのものではない。）

正規表現の意味を分解して示す。

| 部分 | 意味 |
|---|---|
| `\$\$.*?\$\$` | ブロック数式。`re.DOTALL` により `.` が改行にも一致するため、**改行をまたぐ**。非貪欲 `*?` で最短一致 |
| `\|` | 交替。**左が優先**されるため、`$$` は `$…$` より先に一致する |
| `\$[^$\n]*?\$` | インライン数式。文字クラスに `\n` を含めないため、**改行をまたがない**。`$` も含めないため入れ子にならない |

置換で**同じ文字数**の `\x00` を入れるため、`masked` の各位置は `md` の同じ位置に対応する（FR-001 の「文字位置を変えない」）。

#### エラーハンドリング

| 想定される事象 | 検出方法 | 処理 |
|---|---|---|
| `md` に `\x00` が元から含まれる | 検出しない | 対処不要。`\x00` は §1.4.2 の対象文字集合に属さないため候補にならず、結果に影響しない |
| 対応の取れない `$` が 1 個ある | 検出しない | 正規表現が一致しないため、その `$` の周辺はマスクされず探索対象に残る。これは `roadmap.md` §6 の定義（「一致する範囲を除いた部分」）どおりの振る舞いである |

#### 境界条件

| 入力 | 振る舞い |
|---|---|
| 空文字列 | 空文字列を返す |
| 数式マークアップを含まない | 入力と同一の文字列を返す |
| 全体が `$$…$$` 1 個 | 全体が `\x00` になる |
| `$$` が奇数個 | 左から順に 2 個ずつ対にして一致する。余った 1 個は一致しない |

### 1.4.2 候補文字の抽出（FR-002）

#### データフロー

- 入力: `masked` … `str`（§1.4.1 の出力）
- 出力: `offsets` … `list[int]`（候補の開始位置。**昇順**）

#### 対象文字集合（`roadmap.md` §6 の転記）

```
GREEK_LOW  = 0x0370
GREEK_HIGH = 0x03FF
MATH_SYMBOLS = "≤≥≠≈≡∝∈∉⊂⊆⊃⊇∪∩∑∏∫√∞±∀∃¬∧∨∂∇⋯∼≪≫∅"    # 32 文字
```

判定は「コードポイントが `GREEK_LOW` 以上 `GREEK_HIGH` 以下」**または**「`MATH_SYMBOLS` に含まれる」。`roadmap.md` §6 の「文字集合（対象外・保留）」（`… → ← ↔ ⇒ ⇔ × ÷ ·`）は `MATH_SYMBOLS` に**含めない**。

#### 処理ロジック

```
def find_offsets(masked):
    return [i for i, ch in enumerate(masked) if is_candidate_char(ch)]
```

先頭から末尾へ 1 文字ずつ走査するため、結果は開始位置の昇順になる（FR-004 の順序の要件）。乱数・外部状態・順序依存を含まないため、同じ入力に同じ結果を返す（NFR-004）。

#### 境界条件

| 入力 | 振る舞い |
|---|---|
| 空文字列 | 空リストを返す |
| 候補が 1 件も無い | 空リストを返す |
| 全文字が候補 | 全位置のリストを返す |

### 1.4.3 候補レコードの生成（FR-003）

#### データフロー

- 入力: `md` … `str`（**マスク前**の原文）、`chapter` … `str`、`offset` … `int`
- 出力: `record` … `dict`（下記 5 キー）

| キー | 型 | 内容 | 値域 |
|---|---|---|---|
| `chapter` | `str` | 章名 | 入力ファイルの**親ディレクトリ名**（ADR-5） |
| `offset` | `int` | 元の Markdown の先頭からの文字数 | 0 以上、`len(md)` 未満 |
| `char` | `str` | 該当文字 | 1 文字。`md[offset]` と一致 |
| `before` | `str` | 直前の文脈 | 0〜40 文字。`md[max(0, offset-40):offset]` |
| `after` | `str` | 直後の文脈 | 0〜40 文字。`md[offset+1:offset+41]` |

**文脈の長さの上限 40 は `roadmap.md` §5 の候補レコードの定義に由来する定数**であり、本設計で変えない。同節は候補レコードの成分数を候補ごとの可変値 `c_i` = `8 + min(40, o) + min(40, L − 1 − o)`（`o` = 開始位置、`L` = ファイルの文字数。`c_i ≤ 88`）と定めており、本設計の `CONTEXT_LEN` = 40 がその `min` の上限に当たる。

#### 処理ロジック

```
CONTEXT_LEN = 40

def make_record(md, chapter, offset):
    return {
        "chapter": chapter,
        "offset": offset,
        "char": md[offset],
        "before": md[max(0, offset - CONTEXT_LEN):offset],
        "after": md[offset + 1:offset + 1 + CONTEXT_LEN],
    }
```

**文脈はマスク前の `md` から切り出す**（マスク後の `masked` からではない）。文脈の中に数式マークアップが入っていてよく、そのまま原文を保つ。

#### 境界条件

| 入力 | 振る舞い |
|---|---|
| `offset` = 0 | `before` が空文字列（`max(0, -40)` = 0 のため） |
| `offset` = `len(md) - 1` | `after` が空文字列 |
| 前後が 40 文字未満 | 取れるだけの文字数になる。**不足分を埋めない**（FR-003 の受け入れ基準） |

このとき候補レコードの成分数 `c_i` は上限の 88 より少なくなる。`roadmap.md` §5 に、**確率統計の全10章では全 414 件の開始位置がいずれも 40 以上かつ「`L` − 41」以下である実測**（2026-09-08 計数・2026-09-09 再確認）が記載されており、本案件で扱う候補はすべて `c_i` = 88 になる。S1・S2 の出力の次元 `Σ c_i` が「件数 × 88」で計算できるのはこの実測による。本設計は不足分を埋めない仕様のままとする（埋めると原文に無い文字が文脈に混じり、M3・M4 の原本との突合で誤読の元になるため）。

### 1.4.4 候補レコードのファイル出力（FR-004・FR-006）

#### データフロー

- 入力: `records` … `list[dict]`、`out` … `Path`、`overwrite` … `bool`
- 出力: JSONL ファイル（1 行 1 レコード）

#### ファイル形式

1 行が 1 件の JSON オブジェクト。**`json.dumps(rec, ensure_ascii=False)` に改行を付けたもの**を連結する。

```
{"chapter": "chap01", "offset": 405, "char": "Ω", "before": "…", "after": "…"}
{"chapter": "chap01", "offset": 976, "char": "Ω", "before": "…", "after": "…"}
```

- `ensure_ascii=False`: 日本語・ギリシャ文字をそのまま出す（目視で読めるようにする）
- 文脈に含まれる改行・タブ・引用符は JSON のエスケープ（`\n`・`\t`・`\"`）で表現され、`json.loads` で元の文字列に戻る（FR-004 の受け入れ基準）
- 文字コードは UTF-8、改行コードは `\n`

#### 出力先の判定（FR-006）

**書き込みの前に**次の順で判定する。1 つでも該当したら書き込まずに終了コード 1 で終える。

1. `out` が存在し、`overwrite` が偽 → 標準エラー出力に `出力先が既に存在する: {out}（上書きするには --overwrite を付ける）` を出して終了
2. `out` が存在し、ディレクトリである → 標準エラー出力に `出力先がディレクトリである: {out}` を出して終了

判定を通ったら、`out` の親ディレクトリが存在しなければ `mkdir(parents=True, exist_ok=True)` で作る。

#### 原子的書き込み

同じディレクトリに一時ファイルを作って書き切ってから `os.replace` で置き換える（書き込み中に中断しても、中途半端な出力を残さない）。既存スクリプト `scripts/scan_plain_math.py` の `write_tsv_atomic` と同じ方式を、JSONL 用に書く。

#### 境界条件

| 入力 | 振る舞い |
|---|---|
| `records` が空 | **0 バイトのファイル**を出力し、終了コード 0 で終わる（エラーにしない。FR-004 の受け入れ基準） |

### 1.4.5 CLI としての実行（FR-005）

#### コマンド

```
uv run python scripts/extract_math_candidates.py <md> [<md> ...] -o <出力先> [--overwrite]
```

#### 引数

| 引数 | 型 | 必須 | 既定値 | 説明 |
|---|---|---|---|---|
| `md_files`（位置引数、`nargs="+"`） | `Path` | 必須 | なし | 入力 Markdown のパス。**1 個以上**。M2 では 10 個を渡す |
| `-o` / `--output` | `Path` | 必須 | なし | 出力先の JSONL のパス |
| `--overwrite` | フラグ | 任意 | 偽 | 出力先が存在するとき上書きする |

#### 終了コードの体系（FR-005）

| コード | 意味 | 出し方 |
|---|---|---|
| 0 | 正常終了 | `main` が 0 を返す |
| 1 | 運用エラー（入力ファイル不在・UTF-8 で読めない・出力先の保護に掛かった） | `main` が 1 を返す |
| 2 | 引数の形式・必須引数の誤り | `argparse` が自身で `SystemExit(2)` を送出する（下記の注記） |

**注記**: §1.7 のとおり `main` は終了コードを**返す**が、**引数の誤りの 1 経路だけは例外として現れる**——`argparse` は誤りを検出すると使い方を表示して `SystemExit(2)` を送出するため、`main` に戻ってこない。この挙動は変更しない（`ArgumentParser.error` を上書きして 1 に変換することはしない。Unix の慣行に合わせ、引数の誤りと運用エラーを区別するため）。テストでは `pytest.raises(SystemExit)` で捕捉して `.code` が 2 であることを確認する。

#### 処理手順

1. `parse_args` で引数を解析する
2. **すべての入力ファイルの存在と種類を先に確認する**（1 個目を処理する前に全件を確認する）。存在しない、またはディレクトリであるものが 1 つでもあれば、そのパスを標準エラー出力に示して終了コード 1 で終わる（**一部だけ処理した結果を出力しない**。FR-005 の受け入れ基準）
3. 出力先を §1.4.4 の「出力先の判定」で確認する。該当すれば終了コード 1 で終わる
4. 入力ファイルを**引数の指定順**に処理する。各ファイルについて:
   1. UTF-8 で全文を読む
   2. 親ディレクトリ名を章名とする
   3. `mask_math` → `find_offsets` → 各 `offset` に `make_record` を適用し、レコードを得る
   4. そのファイルの件数を標準エラー出力に出す（§1.8）
5. 全ファイルのレコードを連結し、`write_jsonl` で出力する
6. 合計件数を標準エラー出力に出し、終了コード 0 で終わる

#### エラーハンドリング

| 想定されるエラー | 検出方法 | 処理 | 終了コード |
|---|---|---|---|
| 入力ファイルが存在しない | 手順 2 の `Path.is_file()` | 標準エラー出力に `入力ファイルが存在しない: {path}` | 1 |
| 入力がディレクトリ | 手順 2 の `Path.is_file()` | 標準エラー出力に `入力がファイルではない: {path}` | 1 |
| UTF-8 として読めない | 手順 4-1 の `UnicodeDecodeError` | 標準エラー出力に `UTF-8 として読めない: {path}` | 1 |
| 出力先が存在（上書き指定なし） | §1.4.4 | 同節のメッセージ | 1 |
| 出力先がディレクトリ | §1.4.4 | 同節のメッセージ | 1 |
| 引数が足りない | `argparse` | `argparse` の標準の挙動（使い方を表示） | 2 |

例外を握りつぶさない。上表に無い例外は捕捉せず、そのまま送出する（想定外の事象を隠さないため）。

## 1.7 インターフェース定義

公開関数のシグネチャ。すべて `scripts/extract_math_candidates.py` に置く（1 モジュール・クラスなし）。

```python
def mask_math(md: str) -> str: ...
def is_candidate_char(ch: str) -> bool: ...
def find_offsets(masked: str) -> list[int]: ...
def make_record(md: str, chapter: str, offset: int) -> dict[str, object]: ...
```

## 2. 記述ルールへの適合

### 2.1 曖昧表現の排除

本設計書に「適切に」「必要に応じて」「等」を使っていない。定数（`CONTEXT_LEN` = 40、対象文字集合の 32 記号、マスク文字 `\x00`）、正規表現、終了コード、メッセージ文言をすべて具体値で示した。

### 2.2 実装判断ゼロの確認

次の点を明示したことで、2 通り以上の実装が考えられる箇所を無くした。

- 正規表現の交替の**順序**（`$$` が先）と `re.DOTALL` の有無
- マスクが**同じ文字数**の置換であること（削除ではない）
- 文脈を**マスク前の原文**から切り出すこと
- 章名を**親ディレクトリ名**から取ること（ADR-5）
- 入力の存在確認を**全件先に**行うこと（一部処理して出力しない）
- `main` が終了コードを**返す**こと（`sys.exit` を内部で呼ばない）

### 2.3 コード例の位置づけ

§1.4 のコード片は**意図の伝達**が目的であり、そのままコピーして使うものではない。

## 2.2 設計判断の記録（ADR）

### ADR-1: スクリプトを `scripts/` に置く（プロダクトコード）

- **採用**: `scripts/extract_math_candidates.py`、テストは `tests/test_extract_math_candidates.py`
- **却下**: マイルストーンフォルダ `m1-extract-smoke/` に置く
- **理由**: `CLAUDE.md`「ドキュメント作成ルール」の判定基準は「**その案件が終わった後も使うか**」である。本 CLI は M2（全10章）でも使い、feat-025 の完了後も同じ抽出を再現する必要がある（後続の修正案件が母集団を作り直す場合）。またマイルストーンフォルダ配下に置くと、`tests/` のテストが案件フォルダ配下のコードを import する構造になり、`CLAUDE.md`「テスト」節と噛み合わない（update-007 の README で同じ判断が記録されている）

### ADR-2: 新しいファイル名にし、`scripts/scan_plain_math.py` を変更しない

- **採用**: `extract_math_candidates.py` という新しい名前で作る。既存の `scripts/scan_plain_math.py` と `tests/test_scan_plain_math.py` は本マイルストーンで変更も削除もしない
- **却下 A**: `scan_plain_math.py` を feat-025 の仕様で上書きする
- **却下 B**: 既存ファイルを本マイルストーンで削除する
- **理由**: `roadmap.md` P10 のとおり feat-024 の成果物は引き継がない。同名で上書きすると、feat-024 の案件文書（`docs/issues/feat-024-…/`）が指すファイルの中身が別物になり、**記録として残す方針の feat-024 の文書と実体が食い違う**。別名にすれば「引き継がない」ことが物理的にも明確になる。削除は feat-024 の中止（feat-025 の完了処理）で扱うべき事項であり、本マイルストーンの範囲外（`requirements.md` §1.7）
- **名前の理由**: 抽出するものが「平文の数式」ではなく「§6 の規則による候補」であるため、`extract_math_candidates`（数式の候補を抽出する）とした

### ADR-3: 出力形式を JSONL にする

- **採用**: 1 行 1 レコードの JSON（JSONL）
- **却下**: TSV（feat-024 の `scan_plain_math.py` が採っていた形式）
- **理由**: 候補レコードの `before` / `after` に**改行・タブ・引用符が含まれうる**。TSV では区切り文字と衝突するため、独自のエスケープ（feat-024 は `_sanitize` で文字を置換していた）が要り、**原文が復元できなくなる**。M3・M4 で原本と突合するとき、文脈は原文のままである必要がある。JSON なら標準ライブラリのエスケープで往復でき、実装判断も入らない

### ADR-4: マスクは削除でなく同じ文字数の置換にする

- **採用**: 数式マークアップの範囲を同じ文字数の `\x00` に置き換える
- **却下**: 該当範囲を削除して探索する
- **理由**: `offset` は「元の Markdown の先頭からの文字数」でなければならない（FR-003）。削除すると位置がずれ、M2-1 以降の逆引きで原文の該当箇所を特定できなくなる

### ADR-5: 章名を入力ファイルの親ディレクトリ名から取る

- **採用**: `path.parent.name`（例: `…/final/chap01/chap01_gray300.md` → `chap01`）
- **却下 A**: ファイル名の先頭 6 文字から取る（`chap01_gray300.md` → `chap01`）
- **却下 B**: `--chapter` 引数で明示指定する
- **理由**: 成果物のディレクトリ構成 `final/chapNN/` は `build_final.py`（feat-012）が作るもので安定している。却下 A はファイル名の規約（`_gray300` の付き方）に依存し、他書籍で変わりうる。却下 B は入力を複数指定できる仕様（FR-005）と噛み合わず、引数と実体が食い違う余地を残す
