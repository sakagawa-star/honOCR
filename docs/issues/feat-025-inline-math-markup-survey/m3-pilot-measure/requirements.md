- **マイルストーン**: M3（ステージ S3）
- **作成日**: 2026-09-17
- **改訂**: 2026-10-07 閾値実験の中止（ユーザー判断）を §1.1 と C-309 に反映した
- **関連**: `../roadmap.md`（§3 の P6〜P9-1 / §5 入力の次元と `c'_i` / §7 ステージ表と `q` の定義 / §8 の S3 / §9 の M3）、`../m2-1-locate-smoke/design.md`（逆引き処理の仕様。§1.4.1〜§1.4.5・§1.7）、`../m2-population/design.md` §1.6（候補レコードのパス）

**要求 ID の付番**: 本案件内で一意にするため、M1 は 000 番台、M2 は 100 番台、M2-1 は 200 番台、**M3 は 300 番台**（FR-301〜307）を使う。

## 1.1 プロジェクト概要

- **何を作るのか**: **S3 のステージの実行に使うコードは作らない・変えない**（C-301）。ただし判定規則の閾値を実測で定める実験のための**実験コード 2 本**（`experiments/thresholds/extract_samples.py`・`measure_glyphs.py`）は、C-309 に従って作った（S3 の実行では使わない。実験は 2026-10-07 に中止し、判定規則の閾値は設計値のまま未検証である。`design.md` §1.4.4）。M2 が出力した候補レコード 414 件から **30 件を無作為抽出**し、M2-1 で疎通した逆引き処理と `scripts/crop_blocks.py` と目視で原本と突合して、**判定可能率 `q`** と**真の欠落の比率の事前値 `p₀`** を測る。あわせて、**S4 でも使う判定規則の本体**を定める（`roadmap.md` P9-1）
- **なぜ作るのか**: `q` と `p₀` は `roadmap.md` §8 の S4 の想定値（`u`・`k`）の式の入力項であり、本ステージでしか得られない（P8・P9 は未検証）。**本ステージは測るステージであり、想定値を置かない**（`roadmap.md` §8 の S3）
- **誰が使うのか**: Claude Code（M4 が同じ判定規則で本標本 `n` 件を判定する）
- **どこで使うのか**: honOCR リポジトリのローカル環境（Python 3.12、`uv run`）。GPU 不要、ネットワーク不要

## 1.2 用語定義

`roadmap.md` と M1・M2・M2-1 の文書で定義済みの語を同じ意味で使う（定義の本体は下表の参照先にあり、本書では再定義しない）。本マイルストーンで新たに定める語には「新規」と記す。

| 用語 | 意味と定義の所在 |
|---|---|
| **候補レコード** | 5 キー。成分数は `c_i`（`roadmap.md` §5、`../m1-extract-smoke/design.md` §1.4.3） |
| **判定結果レコード** | 候補レコードに原本ページ番号と判定を足した 7 キー。成分数は `c'_i` = `c_i` + 2（`roadmap.md` §5、`../m2-1-locate-smoke/design.md` §1.4.4） |
| **逆引き** | 候補レコードから content_list のブロックを特定して `page_idx` を得ること（`../m2-1-locate-smoke/design.md` §1.4.1〜§1.4.3） |
| **判定** | `missing` / `not_missing` / `undecidable` の 3 値（`../m2-1-locate-smoke/design.md` §1.4.4） |
| **判定規則**（新規） | 目視した原本から判定の 3 値のどれを選ぶかを決める規則。**本体は `design.md` §1.4.4 に置く**（`roadmap.md` P9-1。M4 はこれを参照し、変更しない） |
| **予備標本**（新規） | 本ステージで抽出する 30 件の候補。抽出の手順は `design.md` §1.4.1 |
| **`q`** | 判定可能率 = （欠落の有無を判定できた件数）/ 30（`roadmap.md` §7 の「`q` の定義」） |
| **`p₀`** | 真の欠落の比率の事前値 = （原本で数式として組まれていた件数）/（判定できた件数）（`roadmap.md` §8 の S3） |

## 1.3 機能要求一覧

### FR-301 予備標本 30 件の無作為抽出

- **概要**: 候補レコード 414 件から 30 件を無作為に抽出し、その 30 件だけを含むファイルを作る
- **入力**: `{BASE2}/ocr/feat-025/m2_all_candidates.jsonl`（M2 の出力。414 件）
- **出力**: 予備標本の候補レコード 30 件のファイル
- **受け入れ基準**:
  - [ ] 抽出が**単純無作為抽出**である（`roadmap.md` §2.3 の式が単純無作為標本を前提とするため）
  - [ ] 抽出の手順が**決定的**であり、同じ入力・同じ乱数の種から常に同じ 30 件が得られる（`design.md` §1.4.1 で種を固定する）
  - [ ] 抽出した 30 件が**重複しない**
  - [ ] 抽出した行番号（元ファイルでの物理行番号）と、予備標本ファイル内の行番号との対応が記録されている
  - [ ] 元の候補レコードファイルを変更しない
  - [ ] **M2-1 で判定した 1 件が標本に含まれても、その判定を流用せず、本マイルストーンの判定規則で判定し直す**（`../m2-1-locate-smoke/requirements.md` §1.7）

### FR-302 予備標本の逆引き

- **概要**: 予備標本 30 件について、M2-1 で疎通した逆引き処理で原本ページを特定する
- **入力**: FR-301 の予備標本ファイルと、各章の content_list
- **出力**: 30 件分の逆引き結果（`page_idx` と、標準出力への内訳）
- **受け入れ基準**:
  - [ ] `scripts/locate_candidates.py` を**変更せずに**使う（C-301）
  - [ ] 30 件すべてが処理され、出力が入力の並び順である
  - [ ] 逆引きに失敗した候補は `page_idx` が `null` になり、エラーで止まらない
  - [ ] 各候補のブロック番号・`page_idx`・採用した `K` が記録されている

### FR-303 原本 TIF からの切り出し

- **概要**: 逆引きに成功した候補について、`scripts/crop_blocks.py` で原本の該当領域を PNG に切り出す
- **入力**: FR-302 のブロック番号と、各章の content_list・原本 TIF ディレクトリ
- **出力**: 候補ごとの PNG
- **受け入れ基準**:
  - [ ] `scripts/crop_blocks.py` を**変更せずに**使う（C-302）
  - [ ] 切り出せた PNG の枚数が、**逆引きに成功した候補に含まれる重複なしの `(chapter, ブロック番号)` の組数**と一致する（同一章・同一ブロックの複数候補は 1 枚を共用するため、候補の件数とは一致しない。`design.md` §1.4.3）
  - [ ] 逆引きに失敗した候補については切り出しを行わない
  - [ ] **「候補の元ファイル行番号 → PNG のパス」の対応表が `experiment_log.md` に記録されている**（同一章・同一ブロックに属する複数の候補は 1 枚の PNG を共用するため、ファイル名だけでは候補を一意に識別しない。`design.md` §1.4.3）

### FR-304 判定規則の定義と、目視による判定

- **概要**: 判定の 3 値をどう選ぶかの規則を定め、その規則に従って 30 件を判定する
- **入力**: FR-303 の PNG と、候補レコードの文脈
- **出力**: 候補ごとの判定（3 値のいずれか）と、その根拠
- **受け入れ基準**:
  - [ ] **判定規則の本体が `design.md` §1.4.4 に書かれている**（`roadmap.md` P9-1。M4 はこれを参照する）
  - [ ] 規則が**順序つきの判定手順**として書かれ、同じ PNG に対して同じ判定が出る形になっている
  - [ ] 逆引きに失敗した候補、PNG を判読できない候補が `undecidable` になる
  - [ ] 30 件すべてに判定が付く
  - [ ] 各候補について、**判定と、規則のどの項に当てはまったか**が記録されている
  - [ ] 判定者は Claude Code 本体である（`roadmap.md` P9-1）

### FR-305 判定結果レコードの出力

- **概要**: 30 件の判定結果レコードを 1 つの JSONL にまとめる
- **入力**: FR-302 の逆引き結果と FR-304 の判定
- **出力**: 判定結果レコード 30 件の JSONL
- **受け入れ基準**:
  - [ ] レコードのキーが 7 個であり、`roadmap.md` §5 の `c'_i` = `c_i` + 2 と一致する
  - [ ] 件数が **30 件**である（`roadmap.md` §7 のステージ表の出力の次元 `Σ c'_i` = 30 × 90 に対応する）
  - [ ] 並び順が予備標本ファイルの並び順である
  - [ ] すべてのレコードの `judgment` が `null` でない

### FR-306 `q` と `p₀` の算出

- **概要**: 判定結果から測る項を算出する
- **入力**: FR-305 の判定結果レコード 30 件
- **出力**: `q`（次元 1）と `p₀`（次元 1）
- **受け入れ基準**:
  - [ ] `q` が `roadmap.md` §7 の定義（判定できた件数 / 30）で算出されている
  - [ ] `p₀` が `roadmap.md` §8 の S3 の定義（原本で数式として組まれていた件数 / 判定できた件数）で算出されている
  - [ ] 算出に使った件数（`missing`・`not_missing`・`undecidable` の内訳）が記録されている
  - [ ] **`q` = 0 の場合は `p₀` を算出せず、S4 に進まない**（`roadmap.md` §8 の S3 の停止条件。再計画に入る）

### FR-307 測定結果の記録

- **概要**: 測るステージとして、測った値と経過を `experiment_log.md` に記録する
- **入力**: FR-301〜FR-306 の結果
- **出力**: `experiment_log.md` の記録
- **受け入れ基準**:
  - [ ] **想定値との照合を行わない**（`roadmap.md` §8 の S3 は測るステージであり想定値を置かない）。予測を立てず、測った値を記録する
  - [ ] 抽出した 30 件の行番号、逆引きの内訳、PNG のパス、判定と根拠、`q`・`p₀` とその内訳が記録されている
  - [ ] 再実行のときは、退避した前回の成果物のパスと一覧が記録されている（C-305）

## 1.7 範囲外（本マイルストーンで扱わないこと）

- **本標本 `n` 件の抽出と判定**: M4（ステージ S4）で行う。本マイルストーンは予備標本 30 件のみ
- **`n` の算出**: `n` は `N` と設計定数 `z`・`e` だけから決まり（`roadmap.md` §2.2）、`q`・`p₀` に依存しない。算出は M4 で行う
- **最終出力（`M̂`・`CI`）の計算**: M5（ステージ S5）で行う
- **逆引きの成功率を上げる工夫**: `q` は測る対象であり、本マイルストーンで手段を改良しない（改良するなら「ロードマップの改訂（再計画）」に従う）
- **md の修正**: 本案件全体の範囲外（`roadmap.md` P2）
- **想定値との照合**: 測るステージのため行わない（FR-307）
