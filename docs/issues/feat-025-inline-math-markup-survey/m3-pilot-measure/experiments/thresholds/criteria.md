### 1.4 G4 の判定規則（事前に固定する。`design.md` 改訂で §1.4.4 に入れる）

G4 の字形には、§1.4.4 の手順のうち**大きさ・縦位置の比を使う条件を適用しない**。次のとおりとする。

1. 手順 1・2（PNG なし・特定不能・判読不能）はそのまま適用する
2. 手順 3-1 は、(c) 分数・(d) 根号・(e) 範囲指定・(f) 行列の**構造の条件だけ**を適用する（`√` は (d) に当たる）。(a)(b) は、**G4 の字形の直前または直後の字形**が `T_raise`・`T_drop` の条件を満たす上付き・下付きであれば当てはまるものとする（G4 の字形自身の大きさ・位置は見ない）
3. 手順 3-2・3-3 は適用しない（G4 は大型演算子でもラテン・ギリシャ文字でもない）
4. 手順 3-4 は、**ベースラインの条件を外して**適用する。すなわち直前または直後（同じ行で、間に和文を挟まない位置）に 3-1〜3-3 のいずれかに当てはまる字形があれば `missing`
5. 手順 4（`not_missing`）は**適用しない**
6. 以上のどれにも当てはまらなければ手順 5 により `undecidable`

**この規則の帰結**: G4 の候補は、数式の要素と隣接していない限り `undecidable` になる。候補 414 件のうち G4 の文字は 37 件（`≡` 11・`∞` 6・`±` 4・`≈` 3・`√` 3・`∝` 2・`∩` 2・`∪` 2・`⋯` 1・`∨` 1・`∧` 1・`≠` 1。2026-10-06 計数）である。

## 2. 測る対象の取り方

### 2.1 抽出元

**全10章の成果物 md（`{BASE2}/ocr/final/chapNN/chapNN_gray300.md`）のインライン数式 `$…$`**（`$$…$$` を除く。範囲の定義は `roadmap.md` §6 と同じ正規表現）。インライン数式の中身は、MinerU が原本で数式と認識して LaTeX に変換したものであり、**原本で数式として組まれている字形**の標本として用いる（候補〔`$…$` の外〕は判定の対象そのものであるため、閾値を決める標本には使わない）。

### 2.2 標本の抽出（実験コード `extract_samples.py` の仕様）

#### 入力と出力

- **入力**: 全10章の md（`chap00`〜`chap09` の順）
- **出力**: `{BASE2}/ocr/feat-025/m3-thresholds/population.jsonl`。1 行 1 出現。キーは次の 8 個

| キー | 型 | 内容 |
|---|---|---|
| `group` | `str` | `SUP` / `SUB` / `G1` / `G2` / `G3` |
| `chapter` | `str` | `chap00`〜`chap09` |
| `math_start` | `int` | md 内のインライン数式の開始 `$` の位置（0 始まりの文字数） |
| `math_text` | `str` | インライン数式の全体（両端の `$` を含む） |
| `token_pos` | `int` | `math_text` の中でのトークンの開始位置（0 始まり） |
| `token` | `str` | トークンの文字列（例: `\mu`・`x`・`2`） |
| `before` | `str` | `math_start` の直前の、同じ行の中の最大 10 文字 |
| `after` | `str` | インライン数式の直後の、同じ行の中の最大 10 文字 |

並び順は `chapter` → `math_start` → `token_pos` の昇順。

#### インライン数式の取り出し

`roadmap.md` §6 と同じ正規表現 `\$\$.*?\$\$|\$[^$\n]*?\$`（`re.DOTALL`）で一致を取り、**`$$` で始まる一致は捨てる**。残った一致がインライン数式である。

#### トークンの定義（`math_text` から両端の `$` を除いた中身を左から走査する）

1. 空白（`str.isspace()` が真の文字）は読み飛ばし、トークンにしない
2. `\` に英字（`A`〜`Z`・`a`〜`z`）が 1 文字以上続くもの → **制御語**（英字の連続の終わりまで）
3. `\` に英字以外の 1 文字が続くもの → **制御記号**（2 文字）
4. `{` → **開き括弧**、`}` → **閉じ括弧**（ただし 3 に当たる `\{`・`\}` は制御記号）
5. それ以外の 1 文字 → **単一文字**

`%` を含め、ここに無い特別扱いはしない（md のインライン数式に LaTeX のコメントは書かれていないため、`%` は単一文字として扱う）。

#### 添字の範囲

トークンの列を左から見て、`^` または `_`（単一文字）に出会ったら、その次のトークンを見る。

- 次のトークンが**開き括弧**なら、対応する閉じ括弧までが添字の範囲（括弧の入れ子は深さで数える）。範囲の**中の最初のトークン**を「添字の先頭」とする
- 次のトークンが開き括弧以外なら、**そのトークン 1 つ**が添字の範囲であり、添字の先頭でもある
- 対応する閉じ括弧が無い、または `^`・`_` が中身の末尾にある場合は、その `^`・`_` を無視する

添字の範囲の外にあるトークンを「基底位置にある」という。

#### 群への割り当て

| 群 | 条件 |
|---|---|
| `SUP` | `^` の添字の先頭が、**英数字 1 文字**（`[A-Za-z0-9]`）または**ギリシャ文字の制御語**（下記）であるもの。それ以外（ギリシャ文字でない制御語〔`\mathrm`・`\le` など〕・制御記号・括弧・記号）は数えない |
| `SUB` | `_` について同上 |
| `G1` | 基底位置にある制御語のうち、§2.2.1 で G1 に割り当てたもの |
| `G2` | 基底位置にある制御語のうち、§2.2.1 で G2 に割り当てたもの |
| `G3` | 基底位置にある制御語 `\sum`・`\prod`・`\int` |

**ギリシャ文字の制御語**（`SUP`・`SUB` の判定に使う集合）は、§2.2.1 の **G2 の制御語のすべて**と、**G1 のうち大文字のギリシャ文字の 11 語**（`\Gamma`・`\Delta`・`\Theta`・`\Lambda`・`\Xi`・`\Pi`・`\Sigma`・`\Upsilon`・`\Phi`・`\Psi`・`\Omega`）とする。G1 のうち数学記号の制御語（`\le`・`\leq`・`\ge`・`\geq`・`\in`・`\notin`・`\subset`・`\subseteq`・`\supset`・`\supseteq`・`\forall`・`\exists`・`\partial`・`\nabla`・`\emptyset`・`\varnothing`）は含めない。

添字の先頭がギリシャ文字の制御語である場合、その出現は `SUP`（または `SUB`）にだけ数え、G1・G2 には数えない。

**添字の中の `^`・`_`（入れ子）**: 上の「添字の範囲」の規則は、トークン列の**すべての** `^`・`_` に当てはめる。他の添字の範囲の中にある `^`・`_` も除かない。例: `x^{a_b}` では、`^` の添字の範囲は `a`・`_`・`b` で先頭は `a`（`SUP`）、`_` の添字の範囲は `b` で先頭は `b`（`SUB`）。**添字の範囲の中にあるトークンは、添字の先頭でなくても基底位置の群（G1〜G3）に数えない**（例: `x^{2\mu}` の `\mu` は、`SUP` にも `G2` にも数えない）。中身が空の括弧（`x^{}`）は添字の先頭が無いため数えない。

### 2.3 標本数と抽出

| 定数 | 値 | 根拠 |
|---|---|---|
| `n_need` | **19** | **運用上、事前に固定する標本数**であり、統計的な保証として置くものではない。目安として次の性質を参照した: 同じ母集団から無作為に取った 20 件（有限母集団からの非復元抽出でも、各件は交換可能である）のうち、ある 1 件が他の 19 件の最大値を**厳密に上回る**確率は **1/20 = 5% 以下**である（同値があればさらに小さい）。最小値の側も同じ。ただしこの性質は**本検証の母集団（md のインライン数式の字形）**についてのものであり、S3・S4 の候補の字形について何かを保証するものではない |
| `n_draw` | **24** | 群ごとに抽出する件数。逆引き・字形の特定に失敗する分の予備（§2.4 の実測で、インライン数式の原本での特定は 120 件中 106 件 = 88%） |
| `SEED` | **20261006** | 乱数の種。本書の作成日。実行結果を見てから選ぶ余地が無い |

抽出の手順: 群ごとに、§2.2 の `population.jsonl` の該当群の行を**ファイルの並び順**に並べた列を作り、`random.Random(SEED + 群の番号).sample(列, min(n_draw, 列の長さ))` で抽出する（群の番号: SUP = 1、SUB = 2、G1 = 3、G2 = 4、G3 = 5）。抽出した標本は**元の並び順**に戻してから測る。

**測定の打ち切り**: 群ごとに、元の並び順で測り、**測定に成功した標本が `n_need` = 19 件に達した時点で打ち切る**。24 件を測り終えても 19 件に達しない群があれば、§4.3 に従う。失敗した標本を別の標本で**補充しない**（補充は実行結果を見て標本を選ぶことになるため）。

### 2.4 標本の原本上の位置の特定

各標本について、次の手順で content_list のブロックを特定する。

1. **content_list のパス**: `{BASE2}/ocr/final/{chapter}/*_content_list.json` を glob し、ちょうど 1 個であることを確認する（`../../../m2-1-locate-smoke/design.md` §1.4.1 と同じ規約）
2. **ブロックの検索対象テキスト**: `../../../m2-1-locate-smoke/design.md` §1.4.3 の定義を**そのまま**使う。すなわち `SEARCH_KEYS` = (`text`, `table_body`, `image_caption`, `image_footnote`, `table_caption`, `table_footnote`, `chart_caption`, `chart_footnote`) をこの順に見て、値が `str` ならそのまま、`list` なら要素のうち `str` であるものを順に取り出し、`"\n"` で連結したもの
3. **照合キー**: `before + math_text + after`（§2.2 の出力のキー）。`before`・`after` は同じ行の中から取っているため、照合キーに改行は含まれない
4. **照合**: 照合キーが検索対象テキストに**部分文字列として含まれる**ブロックを、ブロックの添字の昇順に集める。**正規化は一切行わない**（空白・改行・全角半角・Unicode 正規化のいずれも変換しない。照合キーと検索対象テキストをそのまま比べる）。照合キーの長さを変えて再試行すること（M2-1 の `K` の階梯）も**行わない**
5. **判定**: 集めたブロックが**ちょうど 1 個**なら採用する。0 個または 2 個以上なら測定失敗（`特定不能`）とする。同一ブロック内に照合キーが 2 回以上現れる場合は、ブロックが 1 個であるため採用する（M2-1 と同じ扱い）。その場合、字形の対応（§2.2「原本上での字形の対応」）は、ブロックの中で**照合キーが最初に現れる位置**のインライン数式について行う
6. **切り出し**: 採用したブロックを `scripts/crop_blocks.py`（既定の `--margin` 8.0）で切り出す。出力先は `{BASE2}/ocr/feat-025/m3-thresholds/crops/`

（2026-10-06 の下調べ: chap01・chap03・chap05 の先頭 40 個ずつ計 120 個に、`text` フィールドだけを検索対象として上の 3〜5 を当てたところ、一意に定まったのは 106 個。）

## 3. 測り方

### 3.1 量の定義

`design.md` §1.4.4 と同じ定義を使う。

| 記号 | 定義 |
|---|---|
| 基準文字 | `design.md` §1.4.4 の規則（同じ行の漢字 → カタカナ → ひらがなの順に、標本の字形に最も近いもの。同距離なら左） |
| `H` | 基準文字の外接矩形の高さ（画素） |
| `BL` | 基準文字の外接矩形の下端の y 座標（画素） |
| `h` | 標本の字形の外接矩形の高さ（画素） |
| `r` | `h / H` |
| `d` | `(BL − 標本の字形の下端の y 座標) / H`。**正なら `BL` より上、負なら下** |

### 3.2 画素の数え方（実験コード）

切り出した PNG を、実験コード `measure_glyphs.py`（本フォルダに置く）で次のとおり処理する。**使うのは Python 標準ライブラリと Pillow 12.3.0（`pyproject.toml` の `dependencies` に宣言済み）だけ**であり、numpy は使わない（numpy は `pyproject.toml` に宣言されておらず推移的依存として入っているだけのため、使うと依存の追加に当たる）。`extract_samples.py` は標準ライブラリだけを使う。

1. グレースケール値が **200 未満**の画素をインクとする

   **閾値を 200 とする理由**（2026-10-06 改訂。改訂前は 128）: 原本では漢字の画が淡く写ることがあり、閾値 128 では淡い画が面積 4 画素以下の点に分かれて規則 1 で除かれ、字の範囲が欠ける（SUB-05 の基準文字「数」で、行ごとの最小画素値で見た範囲 88〜111 に対し、選べる成分の和集合は 92〜111 だった。本検証の実験ログに記録）。閾値 200 で紙の地を拾わないことは、2026-10-06 に `{OUT}/crops/` の PNG 96 枚で次のとおり実測した
   - **地の行**（画素値 128 未満の画素が 1 つも無い行。7,548 行・11,140,637 画素）の画素値は 128〜255 で、**99.92% が 200 以上**（200 未満は 9,188 画素・0.0825%）
   - 閾値 200 で白黒にしたときの面積 5 以上の成分 16,995 個のうち、**地の行の中だけにある成分は 3 個**（面積 5〜6）。これらは字を構成しないため、規則 2・3 で選ばれることはない
2. インク画素の**8 近傍の連結成分**を求め、各成分の外接矩形を得る。外接矩形は**画素の添字（0 始まり、両端を含む）**で `xmin`・`ymin`・`xmax`・`ymax` とし、**高さ = `ymax − ymin + 1`、下端 = `ymax`**（y は下向きに増える）とする。成分の番号は、§3.2 の規則 1 で除いた成分を除き、`(xmin, ymin)` の昇順に 1 から振る
3. 成分ごとに番号と外接矩形を描き込んだ拡大画像（2 倍）を出力する
4. Claude Code 本体がその画像を Read ツールで見て、**標本の字形を構成する成分の番号**と、**基準文字を構成する成分の番号**（漢字は複数の成分からなる）を指定する。**閲覧の補助として、成分番号つき画像の一部を切り出して拡大して見てよい**（成分の番号と座標は `components.json` のものをそのまま使い、計算には関わらない。補助の出力は `{OUT}/view/` に置き、記録の対象にしない。**補助の画像は、そのとき有効な `annot/` の画像から作ったものだけを見る**）
5. 実験コードが、指定された成分の外接矩形の**和集合**から `h`・`H`・`BL`・下端を計算し、`r`・`d` を出す

**人（Claude Code 本体）が決めるのは「どの成分がどの字か」だけ**であり、高さとずれは画素から計算する。

#### 成分の選択規則

1. **小さな成分の除外**: 面積（画素数）が **4 以下**の成分は、2 値化の雑音として番号を振らず、どの字にも含めない
2. **標本の字形**: 字形を構成する成分を**すべて**選ぶ（`i`・`j` の点、`≤` の下の横線のように離れた画を含む）
3. **基準文字**: `design.md` §1.4.4 の規則で選んだ漢字（またはカタカナ・ひらがな）を構成する成分を**すべて**選ぶ
4. **接触**: 選ぶべき成分のどれかが、**他の字（隣の字・句読点・数式の要素・罫線）と 1 つの成分につながっている**場合は切り分けない。標本の字形なら測定失敗（`成分分離不能`）、基準文字なら測定失敗（`基準文字分離不能`）とする（別の基準文字を選び直さない）
5. **かすれ**: 1 つの字形が 2 つ以上の成分に分かれている場合は、その字形に属する成分をすべて選ぶ（規則 2・3 のとおり）。どの字に属するか見分けられない成分がある場合は、標本なら `字形不明`、基準文字なら `基準文字分離不能` とする
6. **記録**: 選んだ成分の番号の一覧（標本・基準文字それぞれ）と、各成分の外接矩形を記録する

### 3.3 測定の成功・失敗

次のいずれかに当たる標本は**測定失敗**とし、理由を記録する。

| 理由 | 内容 |
|---|---|
| `特定不能` | §2.4 で一致ブロックが 0 個または 2 個以上 |
| `字形不明` | PNG の中に標本の字形を見つけられない |
| `基準文字なし` | 同じ行に漢字・カタカナ・ひらがなが無い |
| `成分分離不能` | 標本の字形が他の字と 1 つの成分につながっている（§3.2 の成分の選択規則 4） |
| `基準文字分離不能` | 基準文字が他の字と 1 つの成分につながっている、または属する成分を見分けられない（同 規則 4・5） |

#### 3.4.1 Q3 の傾きの規則（2026-10-07 追加）

`design.md` §1.4.4 の 3-3 は「字形の外接矩形の上端に接する画の位置が、下端に接する画の位置より右にある」と定めるが、上端・下端に接する画が複数ある場合（`ω` の両腕、`λ` の両脚など）の決め方を定めていない。Q3 では次の規則で、**標本ごとに `yes`・`no`・`判定不能` のちょうど 1 つ**を決める。値を決めるのは実験コード `measure_glyphs.py` であり（§3.6.6）、Claude Code 本体が選ぶのは §3.2 の成分だけである（§3.2「人が決めるのは『どの成分がどの字か』だけ」と同じ）。

1. **画素の集合 `P`**: `--target` で選んだ成分（§3.2）を構成する**インク画素すべて**（§3.2 の 1・2 と同じ白黒化・同じ連結成分。成分の外接矩形の中にある他の成分の画素は含めない）
2. **帯**: 標本の字形の外接矩形（`target_bbox`）の `ymin`・`ymax` と `h` = `ymax − ymin + 1` から、`k` = `max(1, h // 4)`（`//` は切り捨ての整数除算）とし、**上の帯** = 行 `ymin` 〜 `ymin + k − 1`、**下の帯** = 行 `ymax − k + 1` 〜 `ymax`（両端を含む）とする。`h` < 2 のときは 2 つの帯が同じ行になる
3. **位置**: `m_top` = 上の帯にある `P` の画素の x 座標の平均、`m_bot` = 下の帯にある `P` の画素の x 座標の平均（画素 1 個を 1 として数える）。`ymin` の行と `ymax` の行には必ず `P` の画素があるため、どちらの帯も空にならない
4. **差**: `D` = `m_top − m_bot`。計算は**有理数で厳密に**行う（Python の `fractions.Fraction`。浮動小数点で比べない）
5. **値**: `D` > 2 なら `yes`、`D` < −2 なら `no`、−2 ≤ `D` ≤ 2 なら `判定不能`

**規則の理由**
- **1 行でなく帯を使う理由**: 外接矩形の上端・下端の 1 行には、画の先端のかすれで 1〜2 画素しかインクが無いことがある（G2-08 の `λ` では、下端の行のインクは右脚の 1 画素だけで、下端に接する左脚が平均に入らなかった。2026-10-07 の測定中に、外接矩形の中の画素を白黒で表示して確認。本検証の実験ログに記録）。高さの 1/4 の帯をとれば、上端・下端に接する画の先端部分がまとまって入る
- **複数の画を平均でまとめる理由**: 上端（下端）に接する画が複数ある場合に、どの画を代表とするかを選ぶ判断を無くすため、帯の中のすべての画素の平均を画の位置とする
- **`判定不能` の幅を ±2 画素とする理由**: 白黒化（閾値 200）では画の縁の画素がインクになるかどうかが濃淡で揺れ、1 本の画の x 座標の平均は縁の揺れで最大 1 画素程度ずれうる。`D` は 2 つの平均の差であるため、縁の揺れだけで ±2 画素まで動きうる。この幅の中の差は傾きとみなさない
- 本規則は Q3（測定のみ）のためのものであり、`design.md` §1.4.4 の 3-3 の文言・S3 の判定は本検証では変えない（§1.2）

- **部分的な出力を残さない書き方**（書き込みが途中で失敗しても、失敗の前の状態に戻る）

  |---|---|---|
  | `population`・`sample`・`summarize` | 出力と同じディレクトリに一時ファイル（`tempfile.mkstemp(dir=…, prefix=".tmp-")`）を作って書き切り、`os.replace` で出力先に置き換える | 一時ファイルを削除する。出力先は作られない |
  | `locate` | §3.6.4 の段 a〜c のとおり | §3.6.4 のとおり |

  | `compute`・`fail` | `measurements.jsonl` を追記モードで開き、1 行（末尾の `\n` を含む）を書いて `flush` するまでを 1 回の書き込みとする | 追記の途中で失敗して壊れた行が残った場合は、`summarize` の記録の検査（§3.6.9 の 1-5〔形式〕。JSON として読めない行も形式の違反に含める）で終了コード 1 として検出される。その場合は Claude Code 本体が中断して報告する |

| `--crops-dir` | 必須 | `{OUT}/crops`。**存在してはならない**（存在すれば終了コード 1）。本サブコマンドが作る |
| `-o` | 必須 | 出力 `located.jsonl` |

処理:
1. 各標本について §2.4 の手順 1〜5 で content_list のブロックを特定する。採用したブロックの `page_idx` が `int` でなければ `特定不能` とする
2. **実行の前に**、`-o` の出力先と `--crops-dir` が**どちらも存在しない**ことを確認する（どちらかが存在すれば何もせず終了コード 1）。切り出しは `--crops-dir` の親ディレクトリの中に `tempfile.mkdtemp(dir=親, prefix=".crops-")` で作った**一時ディレクトリ**に対して行う。**親ディレクトリが無ければ `mkdir(parents=True, exist_ok=True)` で作る**（失敗時の後片付けでも親ディレクトリは削除しない）。特定に成功した標本の **`(chapter, ブロック番号)` の重複なしの組**ごとに、`scripts/crop_blocks.py` を `[sys.executable, {リポジトリの根}/scripts/crop_blocks.py, {content_list}, {tif-root}/{chapter}/out, -o, {一時ディレクトリ}, --index, {ブロック番号}]` で**1 回ずつ**実行する（`--margin` は指定しない＝既定の 8.0）。`{リポジトリの根}` は `Path(__file__).resolve().parents[6]`（`thresholds` → `experiments` → `m3-pilot-measure` → `feat-025-…` → `issues` → `docs` → 根）。いずれかの実行が 0 以外で終われば、**一時ディレクトリを `shutil.rmtree` で削除して**終了コード 1 で終わる（`--crops-dir` も `located.jsonl` も作らない。したがって同じコマンドでそのまま再実行できる）。すべて成功したら、次の 3 段をこの順に行う。

   | 段 | 処理 | その段で失敗したときの後片付け（後片付けの後、終了コード 1） |
   |---|---|---|
   | a | `located.jsonl` の内容を、`-o` と同じディレクトリの一時ファイル（`tempfile.mkstemp(dir=…, prefix=".located-")`）に書き切る | 一時ファイルと一時ディレクトリを削除する |
   | b | 一時ディレクトリを `os.rename` で `--crops-dir` に改名する | 一時ファイルと一時ディレクトリを削除する |
   | c | 一時ファイルを `os.replace` で `-o` に置き換える | 一時ファイルと、段 b で作った `--crops-dir` を削除する |

   これにより、終了コード 1 で終わったときは**`--crops-dir` も `-o` も存在しない**状態に戻り、同じコマンドでそのまま再実行できる。後片付け自体が失敗した場合は、残ったパスをすべて標準エラー出力に示して終了コード 1 で終わる（その場合は Claude Code 本体が中断して報告する）
3. PNG のパスは `crop_blocks.py` の規約により `{crops-dir}/{content_list の stem}_b{ブロック番号}_p{page_idx}.png`。**この規約から計算して `located.jsonl` に書き、一時ディレクトリにそのファイルが実在するかは確認しない**（実在しなければ、後の `annotate` が「入力が無い」として終了コード 1 で検出する。§3.6.5）

出力: `samples.jsonl` の 9 キーに次の 4 キーを加えた **13 キー**。並び順は `samples.jsonl` と同じ。

#### 3.6.5 `measure_glyphs.py annotate`

| 引数 | 必須 | 内容 |
|---|---|---|
| `--png` | 必須 | 切り出した PNG |
| `--out-dir` | 必須 | `{OUT}/annot`（無ければ作る） |

処理: §3.2 の 1〜3。出力は 2 ファイル。

- `{out-dir}/{PNG の stem}_annot.png`: 元の画像を 2 倍に拡大し、各成分の外接矩形を赤の線で描き、矩形の左上に成分番号を描いたもの
- `{out-dir}/{PNG の stem}_components.json`: `[{"id": int, "xmin": int, "ymin": int, "xmax": int, "ymax": int, "area": int}, …]`（`id` の昇順。座標は**元の画像**の画素の添字）

#### 3.6.6 `measure_glyphs.py compute`

| 引数 | 必須 | 内容 |
|---|---|---|
| `--located` | 必須 | `located.jsonl` |
| `--annot-dir` | 必須 | `{OUT}/annot` |
| `--log` | 必須 | `{OUT}/measurements.jsonl`（追記） |
| `--sample-id` | 必須 | 標本の `sample_id`（`located.jsonl` に無ければ引数の誤り） |
| `--kind` | 必須 | `Q1` または `Q2` |
| `--target` | 必須 | 標本の字形を構成する成分番号（カンマ区切り。Q2 では「別の漢字 1 文字」の成分） |

処理:
1. 標本の `png` に対応する `{PNG の stem}_components.json` を読み、`--target`・`--ref` の成分の外接矩形の和集合から §3.1 の `h`・`H`・`BL`・下端・`r`・`d` を計算する

3. `measurements.jsonl` に 1 行追記する。計算結果の JSON（追記した行と同じもの）を標準出力にも出す。G2 の Q1 のときは、続けて 2 行目に `傾き: m_top={m_top} m_bot={m_bot} D={D}`（同じく小数第 3 位まで）を標準出力に出す（実験ログへの転記に使う。`measurements.jsonl` には書かない）

引数の誤り（終了コード 2）: 成分番号が `components.json` に無い／`--target` と `--ref` に同じ番号がある／番号が空／`locate_status` が `特定不能` の標本を指定した。

記録の矛盾（終了コード 1、追記しない）: 同じ `(kind, sample_id)` の行が既に `measurements.jsonl` にある。

#### 3.6.9 `measure_glyphs.py summarize`

| 引数 | 必須 | 内容 |
|---|---|---|
| `--located` | 必須 | `located.jsonl` |
| `--log` | 必須 | `{OUT}/measurements.jsonl` |
| `--annot-dir` | 必須 | `{OUT}/annot`（記録の検査 8 の再計算に使う） |
| `-o` | 必須 | 出力 `summary.json` |

処理:
1. **記録の検査**（違反があれば終了コード 1、`summary.json` を書かない）
   1. 群ごとに、Q1 の行を `sample_id` の `k` の昇順に並べたとき、**`k` が 1 から途切れず連続している**（§2.3 のとおり元の並び順で測っている）
   2. 群ごとに、Q1 の `ok` の行が **19 件を超えない**。19 件に達した群では、19 件目の `ok` より後の `k` の行が無い（打ち切りを守っている）
   3. 19 件に達していない群では、その群の**全標本**（`located.jsonl` のその群の行すべて）の Q1 の行がある
   4. Q2 の対象画像（§3.6.10）の**すべて**に、Q2 の行がちょうど 1 行ある。対象画像でない PNG の Q2 の行が無い
   5. **形式**: すべての行が JSON のオブジェクトとして読め（読めない行があれば違反）、§3.6.8 の 16 キーをちょうど持ち、各値の型が同表のとおりである。`kind` は `Q1`・`Q2`、`status` は `ok` または §3.6.7 の `--reason` のうちその `kind` に許された値である
   6. **Q1 の対応**: Q1 の行の `sample_id` が `located.jsonl` にあり、`group` と `png` が `located.jsonl` のその標本の `group`・`png` と一致する。`located.jsonl` の `locate_status` が `特定不能` の標本の Q1 の行は `status` = `特定不能` であり、`ok` の標本の Q1 の行は `status` ≠ `特定不能` である
   7. **Q2 の対応**: Q2 の行の `sample_id` と `png` が、§3.6.10 で決まる対象画像とその `sample_id` に一致し、`group` が `Q2` である
   8. **`ok` の行の再計算**: `--annot-dir` の `{PNG の stem}_components.json` を読み、`target_ids`・`ref_ids` から `target_bbox`・`ref_bbox`・`h`・`H`・`BL`・`bottom`・`r`・`d` を §3.6.6 と同じ関数で計算し直して、**すべて一致する**（`r`・`d` は差の絶対値が 1e-9 以下）。`target_ids` と `ref_ids` は空でなく、互いに重ならず、すべて `components.json` にある
   9. **失敗の行**: `status` ≠ `ok` の行は、`target_ids`・`ref_ids`・`target_bbox`・`ref_bbox`・`h`・`H`・`BL`・`bottom`・`r`・`d`・`italic` が**すべて `null`**
   10. **`italic`**: G2 の Q1 の `ok` の行は `yes`・`no`・`判定不能` のいずれかの `str`、それ以外の行は `null`（値が §3.4.1 の規則と一致することは `compute` が書く時点で検査済みであり、`summarize` は画素から計算し直さない）
2. **観測範囲**: 群ごとの Q1 の `ok` の行の `r`・`d` の最小値・最大値、Q2 の `ok` の行の `r`・`d` の最小値・最大値と `|d|` の最大値、G2 の Q1 の `ok` の行の `italic` の値ごとの件数（Q3）
3. **閾値と分離条件**: §4.1 の式と条件をそのまま計算する
4. **判定**: §4.2・§4.3 のとおり、`合格` / `不合格` / `測定不足` のいずれか。`測定不足` は §4.3 の 2・3 に当たる場合。測定不足の群がある場合は、閾値と分離条件を計算せず `null` とする

出力 `summary.json`（1 個の JSON オブジェクト）:

```
{
  "counts": {"SUP": {"measured": int, "ok": int}, "SUB": …, "G1": …, "G2": …, "G3": …, "Q2": {…}},
  "ranges": {"SUP": {"r_min": f|null, "r_max": f|null, "d_min": f|null, "d_max": f|null}, …, "Q2": {…, "absd_max": f|null}},
  "q3_italic": {"yes": int, "no": int, "判定不能": int},
  "thresholds": {"T_bl": f, "T_raise": f, "T_drop": f, "T_small": f, "T_band_G1": [f, f], "T_band_G2": [f, f], "T_large": f},
  "conditions": {"T_raise": bool, "T_drop": bool, "T_small": bool, "T_band_G1_T_large": bool},
  "verdict": "合格" | "不合格" | "測定不足"
}
```

（`f` は `float`。**`ok` の行が 0 件の群（母集団が 0 件、または全標本が失敗）は、その群の `ranges` の値をすべて `null` とする**。`測定不足` のときは `thresholds` と `conditions` の値をすべて `null` とする。`合格`・`不合格` のときは `null` を置かない。）判定の結果を標準出力にも 1 行 `判定: {verdict}` で出す。終了コードは判定の内容によらず 0（記録の検査に違反したときだけ 1）。

#### 3.6.10 Q2 の対象画像の決め方（`summarize` と測定の手順で同じものを使う）

Q1 の `ok` の行を **SUP → SUB → G1 → G2 → G3 の順、群の中は `k` の昇順**に並べ、その `png` を**初出順に重複を除いて**並べたものが Q2 の対象画像である。各対象画像の Q2 の行の `sample_id` は、その PNG が初めて現れた Q1 の行の `sample_id` とする。

#### 3.6.11 `--selftest` とサブコマンドの対応

`--selftest` はサブコマンドより前に置く単独の引数とし（`extract_samples.py --selftest`）、次の固定ケースを、各サブコマンドが使う**同じ関数**に対して実行する（サブコマンドの CLI を通さず、ファイルは一時ディレクトリに作る）。

| スクリプト | ケース | 対応するサブコマンド | 内容と期待 |
|---|---|---|---|
| `extract_samples.py` | E1〜E5 | `population` | §3.5 のとおり |
| `extract_samples.py` | E6 | `sample` | SUP の行を 30 件、SUB の行を 30 件持つ population を与える（各行の `token_pos` に 1〜30 を入れ、ほかのキーは任意）。**SUP は `token_pos` = 6・7・13・15・22・28 の 6 件を除いた 24 件、SUB は 11・17・19・21・24・29 を除いた 24 件**が、`token_pos` の昇順に並び、`sample_id` が `SUP-01`〜`SUP-24`・`SUB-01`〜`SUB-24` になる。G1〜G3 は 0 件（出力に現れない） |

## 4. 判定基準（閾値の決め方。実行前に固定する）

### 4.1 各閾値の導出式と分離条件

観測範囲を `min_X(r)`・`max_X(r)` などと書く（`X` は群）。各閾値は次の式で置き、**分離条件を満たしたときに限り採用する**。

| 閾値 | 導出式 | 分離条件（採用の条件） |
|---|---|---|
| `T_bl` | `max_Q2(|d|)` | 常に採用（Q2 の範囲そのもの） |
| `T_raise` | `min_SUP(d)` | `T_raise` > `T_bl` |
| `T_drop` | `min_SUB(−d)` | `T_drop` > `T_bl` **かつ** `T_drop` > `max_G2(−d)`（G2 の下に伸びる画〔`μ`・`ρ` など〕より深く沈むこと） |
| `T_small` | `max_{SUP∪SUB}(r)` | `T_small` < `min_G1(r)` |
| `T_band(G1)` | 下限 `min_G1(r)`、上限 `max_G1(r)` | `T_band_hi(G1)` < `min_G3(r)` |
| `T_band(G2)` | 下限 `min_G2(r)`、上限 `max_G2(r)` | 常に採用（G2 の大きさの帯は他の群との分離に使わない。上付き・下付きとの区別は `T_raise`・`T_drop` の位置の条件で行う） |
| `T_large` | `min_G3(r)` | `T_large` > `T_band_hi(G1)`（上の `T_band(G1)` の条件と同じ） |

**観測範囲の端をそのまま閾値にする理由**: 群と群の間の観測されない区間（例: `max_{SUP∪SUB}(r)` と `min_G1(r)` の間）は、どちらの群とも言えない見え方であり、`design.md` §1.4.4 の手順では**どの項にも当てはまらず `undecidable` に落ちる**。区間の中に線を引くと、根拠の無い位置で `missing` / `not_missing` を分けることになる。

導出した値は**丸めずに**使う（報告と `design.md` には小数第 3 位まで書き、第 4 位以下は書かない）。

### 4.2 合格ライン

**§4.1 の分離条件 4 つ（`T_raise`・`T_drop`・`T_small`・`T_band(G1)` と `T_large` に共通の条件）がすべて満たされたとき**（`T_bl` と `T_band(G2)` は常に採用する）、本検証は合格とし、導出した値で `design.md` §1.4.4 の閾値を置き直す。

### 4.3 不合格・測定不足のときの扱い

次のいずれかに当たる場合は、**`design.md` の改訂案を作らずに、測った値を記録して人に報告して止まる**。分離しない閾値を別の値や別の式で置き直すこと（事後解釈）はしない。

1. 分離条件を満たさない閾値が 1 つでもある
2. 測定に成功した標本が 19 件に達しない群がある（24 件を測り終えた時点）
3. Q2 で測定に成功した件数が、対象画像のすべてを測り終えた時点で 19 件に達しない
