# feat-025 M2 要求仕様書: 全10章の候補抽出（`N` の確定）

- **マイルストーン**: M2（ステージ S2）
- **作成日**: 2026-09-10
- **関連**: `../roadmap.md`（§2.1 測定値 `N` / §5 入力の次元 / §6 抽出規則 / §7 ステージ表 / §8 の S2 / §9 の M2）、`../m1-extract-smoke/design.md`（本マイルストーンで使う CLI の仕様）、`../m1-extract-smoke/requirements.md`（同 CLI に対する要求）

**要求 ID の付番**: 本案件内で一意にするため、M1 は 000 番台（FR-001〜007）、**M2 は 100 番台**（FR-101〜104）を使う。

## 1.1 プロジェクト概要

- **何を作るのか**: **コードは作らない・変えない。** M1 で完成した抽出 CLI（`scripts/extract_math_candidates.py`）を**全10章に 1 回で適用**し、候補レコードを 1 つのファイルに出力して、測定値 `N`（母集団の候補件数）を確定する
- **なぜ作るのか**: `N` は `roadmap.md` §2.3 の最終出力 `M̂`・`CI` の式の入力であり、標本数 `n` の式の入力でもある（`roadmap.md` §2.2）。ここで確定しないと M3 以降の標本抽出が成り立たない
- **誰が使うのか**: Claude Code（M2-1・M3・M4 が本マイルストーンの出力 JSONL を標本抽出と逆引きの入力として使う）
- **どこで使うのか**: honOCR リポジトリのローカル環境（Python 3.12、`uv run`）。GPU 不要、ネットワーク不要

## 1.2 用語定義

`roadmap.md` と M1 の文書で定義済みの語を同じ意味で使う（定義の本体は下表の参照先にあり、本書では再定義しない）。

| 用語 | 意味と定義の所在 |
|---|---|
| **候補** | 数式マークアップの外側にある、対象文字集合に属する 1 文字（`roadmap.md` §6） |
| **候補レコード** | 候補 1 件を表すデータ。成分数は `c_i`（`roadmap.md` §5）。JSONL の 1 行の形式は `../m1-extract-smoke/design.md` §1.4.3 |
| **`N`** | 母集団の候補件数。全10章の md に `roadmap.md` §6 の抽出規則を適用して得られる候補の総数（`roadmap.md` §2.1 の測定値。本マイルストーンが決める項） |
| **全10章** | `chap00`〜`chap09` の 10 個の成果物 Markdown（`roadmap.md` P1・P5） |
| **1 処理単位** | 本ステージの処理の単位。全10章をまとめて 1 単位とする（`roadmap.md` §7 のステージ表 S2） |

## 1.3 機能要求一覧

### FR-101 全10章を 1 回の実行で処理する

- **概要**: `chap00`〜`chap09` の 10 個の Markdown を、1 回の CLI 実行で処理する
- **入力**: 全10章の Markdown のパス 10 個
- **出力**: 全10章分の候補レコード
- **受け入れ基準**:
  - [ ] CLI の実行が **1 回**である（章ごとに 10 回実行しない。`roadmap.md` §7 の処理単位が全10章 1 単位であるため）
  - [ ] 入力が `chap00`〜`chap09` の 10 個すべてであり、それ以外のファイルを含まない
  - [ ] 入力ファイルの指定順が `chap00` から `chap09` の昇順である
  - [ ] 入力の Markdown を変更しない（読み取りのみ）

### FR-102 候補レコードを 1 つのファイルに出力する

- **概要**: 全10章分の候補レコードを 1 つの JSONL ファイルに書き出す
- **入力**: FR-101 の候補レコード
- **出力**: JSONL ファイル 1 個
- **受け入れ基準**:
  - [ ] 出力先が `design.md` §1.6 で固定した 1 個のパスであり、章ごとに分割されていない
  - [ ] 出力先のパスが **M1 の出力ファイルと異なり**、M1 の出力を上書き・削除しない（C-102）
  - [ ] CLI が終了コード 0 で終わり、標準エラー出力にファイルごとの件数と合計が出る

**出力の形式・順序について**: 1 行 1 レコードであること、JSON として読み戻せること、キーが 5 個であること、章が指定順・章内が `offset` 昇順であることは、M1 の FR-004・FR-005 で要求され、`tests/test_extract_math_candidates.py`（T-12・T-16・T-19）で検証済みである。本マイルストーンはコードを変えないため、これらを再検証しない（§1.7）。

### FR-103 測定値 `N` を確定する

- **概要**: 出力 JSONL のレコード件数を測定値 `N` とし、`roadmap.md` §8 の S2 の想定値と照合する
- **入力**: FR-102 の出力 JSONL
- **出力**: `N`（次元 1 の測定値）
- **受け入れ基準**:
  - [ ] `N` が出力 JSONL の行数として定まり、CLI が標準エラー出力に出した合計件数と一致する
  - [ ] `N` が **`roadmap.md` §8 の S2 の想定値と外れの幅の範囲に収まる**（判定の閾値は `roadmap.md` を参照する。本書には再掲も追加もしない）
  - [ ] 照合を合計 `N` に対して行う（章ごとの中間値には照合しない。`roadmap.md` §8 の S2）

### FR-104 予測と実測の照合を記録する

- **概要**: 実行前の予測と実行後の実測の照合を `experiment_log.md` に記録する
- **入力**: `roadmap.md` §8 の S2 の想定値の式と、FR-103 の `N`
- **出力**: `experiment_log.md` の記録
- **受け入れ基準**:
  - [ ] 実行の**前**に直前予測（式・入力値とその出所・予測値・幅）が記録され、その 1 ファイルだけがコミットされている
  - [ ] 実行の後に実測（`N` と CLI の標準エラー出力）が記録されている
  - [ ] 予測値・実測値・差の照合が記録されている
  - [ ] 実測が想定の幅を外れた場合、`experiment_log.md` に書く内容を `CLAUDE.md`「ロードマップの改訂（再計画）」の「書いてよいもの」に限る
