## レビュー結果（回収した内容）

[AGENTS.md適用]

**高**: 再測定で旧閾値 128 の閲覧補助 `{OUT}/view/` を残すため、旧い成分番号を見て新しい成分を指定できてしまう。§3.2 は `view/` の拡大画像を成分選択に使うことを認めているが、§6 の再実行手順は、成分番号が変わる `annot/` と `measurements.jsonl` だけを退避し、`view/` は退避対象外としている。成分番号は閾値依存なので、旧画像を参照して `compute` すると別の成分を選ぶおそれがある。`summarize` は番号と外接矩形の整合だけを検査するため、字形として誤った選択を検出できない。

修正案: 再測定前に `view/` も退避または削除し、閾値 200 の `annot/` から再生成することを必須化する。閾値別ディレクトリに分ける方法でもよい。

閾値 200 の根拠値は experiment_log と一致している。旧測定値を再利用せず SUP-01 から測り直すため、閾値導出値や合否に合わせた事後解釈には当たらない。

## 対応（Claude Code 本体）

- §6 の再実行の扱いで、`view/` を退避の対象に加えた（使えない理由として、閾値 128 の成分番号が描かれていることを明記）。手順 1 で 3 つの有無を確認し、手順 3 で `view/` も必ず移動する。手順 5 に、閲覧の補助は閾値 200 の `annot/` から改めて作ったものだけを見ることを加えた
- §3.2 の手順 4 の閲覧の補助の規定に、「補助の画像は、そのとき有効な `annot/` の画像から作ったものだけを見る」を加えた
