## 指摘

### 1. 【高】幅計算が未導入の SciPy を必須としている

`roadmap.md:217`（§8 の S4）

S4 の幅計算が `scipy.stats.beta.ppf` / `binom.ppf` を必須としている一方、**SciPy は `pyproject.toml`・`docs/TECH_STACK.md` に未宣言で、現行の仮想環境でも import できない**（Codex が `.venv/bin/python` で `import scipy` を実行して `ModuleNotFoundError` を確認）。さらに S4 はその新規手段の単体疎通を前段に置いていない。このままでは予測幅を計画どおり算出できない。

**修正案**: SciPy を固定版で導入して先行疎通ステージを追加するか、既存環境だけで再現可能な算出手段へ式・手段を改めること。

### 2. 【中】Clopper–Pearson 区間の端点計算が未定義

`roadmap.md:217`, `roadmap.md:228`

S3 は `p₀` = 0 または 1 を許して S4 へ進めるが、§8 の S4 は `beta.ppf` の形状母数と `x` = 0 ／ `x` = `t` のときの端点規則を示していない。このままでは `p₀_lo` または `p₀_hi` が未定義となり、`k` の幅を計算できない。

**修正案**: 成功数 `x`・試行数 `t` に対し、`x` = 0 なら下端 0、`x` = `t` なら上端 1、それ以外は Beta 分布の分位点、という完全な定義を加えること。

## 適合と判定された項目

1.11 の式追跡では、上記の幅計算以外は整合している。`N` は S2、`k`・`u` は S4 から S5 へ接続され、最終出力 `M̂`: 1 と `CI`: 2 は測定値の個数と混同されていない。`q`・`p₀` も先行する測定ステージ S3 から S4 の予測式へ接続され、最終出力への精度要求を置かない扱いも明記されている。
