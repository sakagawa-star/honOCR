## 経緯（規定の改訂 update-015）

codex-16 の反映（update-014 への対応）で、Claude Code は「同じステージで先に計算する量（`n`・`n_eff`・`p̂`）が 3 種のどれでもない入力に見える」と報告し、**式を展開して回避**した。この報告を契機に **update-015** で規定側が改訂された（コミット `24da5f1`）。改訂内容:

- **(a)「入力」の定義を追加**: 入力とは**そのステージの外から入る量**であり、3 種はその全部である。同じステージの式で先に計算する量（`n` のような途中の値）は入力ではなく式の途中の値で、**由来を書かない（展開して書く必要もない）**
- **(b) 3 種の 1 つ目を拡張**: 「前のステージの実測」→「**前のステージの出力**（`experiment_log.md` に記録した値。実測値と、そのステージで計算して確定した値の両方）」
- **(c) 3 種に当たらない入力が出たときの動作**: ラベルを作らず、(1) 測れるなら測るステージを前に置く → (2) 自分のステージの前回の実行結果なら繰り返しを別ステージに分ける → (3) 止まって報告（規定を直すまで収束させない）

Claude Code が報告した問題は「3 種への当てはめ方」だったが、**規定側が特定した原因は「入力の定義が無かったこと」**であり、より上位の欠落だった。
