## 対応（Claude Code 本体）

### 指摘（高）: `undecidable` 時の記録

記録する項目を 3 つに整理し、3 つ目を次のとおり定めた。

- **PNG で読めた該当箇所の文字列**。読めた文字列が存在しない場合（手順 1・2 で `undecidable` になった場合）は **`null`** とし、**理由**を 3 語から選んで記録する
  - `PNG なし`（逆引きに失敗して切り出していない。手順 1）
  - `特定不能`（PNG はあるが `before` の末尾・`after` の先頭と対応する箇所が見つからない。手順 2）
  - `判読不能`（該当箇所は特定できたが字形を判読できない。手順 2 の `--margin` 32.0 の再試行後も同じ）
- 手順 5 で `undecidable` になった場合（該当箇所は読めているが 3 のどの項にも当てはまらず 4 の 3 条件も満たせない場合）は、**読めた文字列をそのまま記録し、理由の欄は空にする**

### 指摘（中）: `H`・`BL` の基準の一意化

**基準文字**という語を新設し、次の規則で**一意に**選ぶこととした。

1. 同じ行の**漢字**のうち、候補に最も近いもの（左右の距離が同じなら**左**）
2. 漢字が無ければ**カタカナ**、それも無ければ**ひらがな**に同じ規則を当てる
3. いずれも無ければ基準文字は定まらない（「同じ行に和文が無い場合」の扱いに従う）

漢字を最優先にする理由（字面が上下いっぱいで高さが安定しており、`っ`・`ー` のような字面の小さい文字を基準にすると比が実態と合わない）も明記した。`H` = 基準文字の外接矩形の高さ、`BL` = 基準文字の外接矩形の下端を通る水平線、と定義し直し、「条件を確認できない場合の扱い」にも**基準文字を選べない場合**を加えた。§2.2「実装判断ゼロの確認」に 2 項目を追加した。
