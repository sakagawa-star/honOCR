## 1.4 各機能の詳細設計

### 1.4.1 章名から content_list を決める（FR-201）

#### データフロー

- 入力: `final_dir` … `Path`（`{BASE2}/ocr/final`）、`chapter` … `str`（候補レコードの `chapter`。例 `chap01`）
- 出力: content_list のパス（`Path`）

#### 処理ロジック

`final_dir / chapter` の直下を `*_content_list.json` で glob し、**ちょうど 1 個であることを要求する**。0 個または 2 個以上なら運用エラー（終了コード 1）とする。

ファイル名の接尾辞（`_gray300`）に依存しないため、他書籍・他の実行でも同じ規約で解決できる（ADR-12）。

#### エラーハンドリング

| 想定されるエラー | 検出方法 | 処理 | 終了コード |
|---|---|---|---|
| `final_dir / chapter` が存在しない | `Path.is_dir()` | 標準エラー出力に `章のディレクトリが存在しない: {path}` | 1 |
| glob の結果が 0 個 | 件数の確認 | 標準エラー出力に `content_list が見つからない: {path}` | 1 |
| glob の結果が 2 個以上 | 件数の確認 | 標準エラー出力に `content_list が複数ある: {path}` | 1 |

### 1.4.2 照合キーと `K` の階梯（FR-201）

#### データフロー

- 入力: 候補レコード（`before`・`char`・`after`）と、ブロックの検索対象テキストの列
- 出力: `(block_idx, page_idx, k)` または**逆引き失敗**

#### 照合キーの作り方

**まず文脈を改行で切り詰める**（ADR-17）。候補レコードの `before` は**最後の改行より後**の部分だけを、`after` は**最初の改行より前**の部分だけを使う。

```
b = record["before"].rsplit("\n", 1)[-1]     # 改行が無ければ before 全体
a = record["after"].split("\n", 1)[0]        # 改行が無ければ after 全体
```

そのうえで、`K` を文脈の片側の文字数として照合キーを作る。

```
key(K) = b[-K:] + record["char"] + a[:K]
```

`b` が `K` 文字に満たない場合は、あるだけを使う（`a` も同様。M1 の `design.md` §1.4.3 のとおり文脈は最大 40 文字である）。

**切り詰めは候補レコードを変更しない**。`before` / `after` は原文のまま出力に残り、`c_i`（`roadmap.md` §5）も変わらない。切り詰めるのは照合キーを作るときだけである。

#### `K` の階梯

**`K` の並びを `[40, 20, 10, 5]` に固定する**（ADR-13）。先頭から順に次を行う。

1. `key(K)` を作る
2. content_list の全ブロックについて、検索対象テキスト（§1.4.3）に `key(K)` が**部分文字列として含まれるか**を調べ、含まれるブロックの添字を集める
3. 集めた添字が**ちょうど 1 個**なら、そのブロックを採用して打ち切る（`k` = その `K`）
4. **0 個**なら次の `K` に進む
5. **2 個以上**なら、より短い `K` では曖昧さが増すだけであるため、その場で**逆引き失敗**として打ち切る

すべての `K` で 0 個だった場合も**逆引き失敗**とする。

採用したブロックの `page_idx` が `int` でない場合（欠落・型違い）も**逆引き失敗**とする。

逆引き失敗は**エラーではない**。原本ページ番号を `null` として処理を続ける（`roadmap.md` P8 のとおり、判定できない候補が一定数あることは織り込み済みで、その割合 `q` は S3 で測る）。

#### 決定性

走査はブロックの添字の昇順、`K` は固定の並びで行い、乱数・外部状態・時刻・辞書の反復順に依存しない（NFR-204）。

#### 境界条件

| 入力 | 振る舞い |
|---|---|
| `before`・`after` がともに空 | `key(K)` が `char` の 1 文字になる。一意に定まることはほぼ無く、多くは 2 個以上で逆引き失敗になる |
| 切り詰めの結果 `b`・`a` がともに空（候補の直前が改行、直後も改行） | 上と同じく `key(K)` が `char` の 1 文字になる |
| `before` に改行が無い | `b` = `before` 全体（切り詰めが起きない） |
| content_list のブロックが 0 個 | すべての `K` で 0 件となり、逆引き失敗 |
| 同一ブロック内に照合キーが 2 回現れる | ブロックの添字は 1 個であるため**一意**として扱う（同じブロック＝同じページ・同じ `bbox` であり、切り出しの結果が変わらないため） |

### 1.4.3 ブロックの検索対象テキスト（FR-201）

#### データフロー

- 入力: content_list のブロック 1 個（`dict`）
- 出力: 検索対象テキスト（`str`）

#### 処理ロジック

次のキーを**この順に**見て、値が `str` ならそのまま、`list` なら要素のうち `str` であるものを順に、取り出す。取り出した文字列を `"\n"` で連結したものを検索対象テキストとする。

```
SEARCH_KEYS = ("text", "table_body", "image_caption", "image_footnote",
               "table_caption", "table_footnote", "chart_caption", "chart_footnote")
```

`text` 以外も含める理由は、候補が表（`table_body` の HTML）や図表のキャプションの中にも現れうるためである（`roadmap.md` §4.2 の md と content_list の乖離）。キーが無いブロックはその分を飛ばす。

#### 境界条件

| 入力 | 振る舞い |
|---|---|
| 上記のキーを 1 つも持たないブロック（`page_number` 等） | 空文字列になり、どの照合キーにも一致しない |
| `list` の中に `str` でない要素がある | その要素を飛ばす（例外にしない） |

### 1.4.4 判定結果レコードの生成と出力（FR-202・FR-205）

#### データフロー

- 入力: 候補レコード、`page_idx`（`int` または `None`）、`judgment`（`str` または `None`）
- 出力: 判定結果レコード（`dict`。**7 キー**）

| キー | 型 | 内容 |
|---|---|---|
| `chapter` | `str` | 候補レコードの値をそのまま |
| `offset` | `int` | 同上 |
| `char` | `str` | 同上 |
| `before` | `str` | 同上 |
| `after` | `str` | 同上 |
| `page_idx` | `int` \| `null` | 原本ページ番号。逆引き失敗なら `null` |
| `judgment` | `str` \| `null` | 判定。与えられなければ `null` |

**キーは 7 個に限る**。ブロック番号・採用した `K` を**レコードに入れない**——`roadmap.md` §5 が判定結果レコードの成分数を `c'_i` = `c_i` + 2（原本ページ番号 1 ＋ 判定 1）と定めているため（ADR-14）。これらは §1.8 のとおり標準出力に出す。

#### 判定の値の集合

`judgment` に入れてよい値は次の 3 つに限る。CLI はこれ以外の値を受け付けない（引数の誤りとして終了コード 2）。

| 値 | 意味 |
|---|---|
| `missing` | 原本で数式として組まれており、md で数式マークアップを失っている（`roadmap.md` の `k` に数える型） |
| `not_missing` | 原本で数式として組まれていない（欠落ではない） |
| `undecidable` | 判定できない（`roadmap.md` の `u` に数える型） |

**判定規則の本体（どの見え方をもって「数式として組まれている」とするか）は M3 の `design.md` で定める**（`roadmap.md` P9-1）。本マイルストーンは値を書き込む器と経路だけを通し、1 件の判定を S3・S4 の測定に用いない（`requirements.md` §1.7）。

逆引き失敗（`page_idx` が `null`）のとき、`judgment` に `missing` または `not_missing` を与えることを**禁止する**（原本を見ていないため）。与えられた場合は引数の誤りとして終了コード 2 で終わる。逆引き失敗の候補に与えてよいのは `undecidable` だけである。

**`judgment` が `null` の出力は、本ステージの最終出力ではない。** レコードの形は同じ 7 キーであり、**判定結果レコードとしての定義（`roadmap.md` §5 の `c'_i` = `c_i` + 2）は変わらない**——変わるのは、それが本ステージの最終出力に当たるかどうかだけである。`judgment` が `null` になるのは、判定を与えずに実行したときの出力（§1.9.2 手順 3 の中間出力 `m2_1_located.jsonl` と、§1.4.5 の全件処理の出力）である。本ステージの**最終出力**である `m2_1_judged.jsonl` は**逆引きに成功したときにだけ作られ**、そのレコードの `judgment` は `null` でない（ADR-16、`requirements.md` FR-205）。

S3・S4（M3・M4）は全件処理の経路を使うため、逆引きに失敗した候補も `page_idx` = `null` のレコードとして出力に含まれ、判定は別途 `undecidable` として集計される（`roadmap.md` の `u`）。本マイルストーンの手順がそれと異なるのは、S2-1 が**手段の単体疎通**であり、疎通の成否そのものが出力だからである（ADR-16）。

#### ファイル形式と出力先の保護

M1・M2 と同一の JSONL（`../m1-extract-smoke/design.md` §1.4.4）。`json.dumps(rec, ensure_ascii=False)` に改行を付けたものを連結し、UTF-8・改行コード `\n` で書く。同じディレクトリに一時ファイルを作って書き切ってから `os.replace` で置き換える。

書き込みの前に次を判定し、該当したら書き込まずに終了コード 1 で終える。

1. 出力先が存在し、`--overwrite` が無い → `出力先が既に存在する: {out}（上書きするには --overwrite を付ける）`
2. 出力先が存在し、ディレクトリである → `出力先がディレクトリである: {out}`

親ディレクトリが存在しなければ `mkdir(parents=True, exist_ok=True)` で作る。

### 1.4.5 処理対象の候補の選び方（FR-203）

#### 本マイルストーンで投入する候補

**`{BASE2}/ocr/feat-025/m2_all_candidates.jsonl` の先頭レコード（1 行目）**とする。`--select 1` で指定する。

**`--select` の番号は物理行番号に固定する**（ADR-15）。候補 JSONL の先頭行を 1 とし、**空行も 1 行として数える**。§1.4.8 の検証で空行は候補として飛ばすため、`--select` に空行の行番号や存在しない行番号を与えた場合は、対応する候補レコードが無いものとして**引数の誤り（終了コード 2）**で終わる（標準エラー出力に `--select の行番号に候補レコードが無い: {N}`）。

物理行番号に固定する理由は、§1.4.8 の検証エラーのメッセージ・§1.8 の標準出力の内訳が**いずれも物理行番号**を出すためである。3 か所で同じ番号系を使うことで、内訳・エラー・`--select` の指定が突き合わせられる。

**この選び方を採る理由**: `roadmap.md` §8 の S2-1 は投入する候補を「前のステージの出力から 1 件を選ぶ」とだけ定めており、どの 1 件かは本設計で固定する必要がある。先頭レコードは入力ファイルだけから決まり、実行結果を見てから選ぶ余地が無い（`CLAUDE.md`「実験・検証の進め方」手順4 の事後解釈の禁止）。

#### 全件処理（M3・M4 が使う経路。本マイルストーンでは使わない）

`--select` を省略したときは候補レコードの全件を処理する。手順を次に固定する。

1. `read_candidates` で候補 JSONL を読み、**全件を先に検証する**（§1.4.8）。1 件でも不正なら、逆引きを 1 件も行わず、出力ファイルを作らずに終了コード 1 で終わる
2. 検証を通ったレコードを**入力ファイルの並び順**（先頭行から末尾行）に 1 件ずつ処理する。並べ替え・章ごとのまとめ直しをしない
3. 各レコードについて、その `chapter` から §1.4.1 で content_list を解決する。**同じ章の content_list は 1 回だけ読み、`dict[str, list]` に保持して以降は再利用する**（同じ章が連続しない並びでも結果は変わらない。読み込みの回数だけが変わる）
4. 章の content_list の解決・読み込みに失敗した時点で、**それまでの結果を出力せずに**終了コード 1 で終わる（部分的な結果を残さない。§1.4.1 のエラーハンドリング）
5. 各レコードの逆引きの内訳を、処理した順に 1 行ずつ標準出力に出す（§1.8）
6. 全件の処理が終わってから、結果を**入力順のまま** 1 つの JSONL に原子的に書き出す（§1.4.4）

`--judgment` は `--select` との併用時のみ許可するため（§1.7）、全件処理では `judgment` が全件 `null` になる。

**逆引き失敗は異常ではない**（§1.4.2）。失敗した候補も `page_idx` = `null` のレコードとして出力に含め、処理を続ける。終了コードは 0 のままである。

### 1.4.8 候補 JSONL の読み込みと検証（FR-203）

#### データフロー

- 入力: 候補レコードの JSONL のパス
- 出力: **（物理行番号, 候補レコード）の対の列**（`list[tuple[int, dict]]`。入力ファイルの並び順を保つ）。物理行番号は 1 始まりで、**空行も 1 行として数えた値**である（§1.4.5 の `--select` と §1.8 の標準出力が同じ番号系を使う）

#### 処理ロジック

1 行ずつ読み、**行番号を 1 始まりで数える**。各行について次を行う。

1. 行末の改行を除いた文字列が空なら、その行を飛ばす（候補の件数に数えない。**ただし物理行番号は 1 進める**）
2. `json.loads` で読む。読めなければ検証エラー
3. 読んだ値が `dict` でなければ検証エラー
4. キーの集合が **`RECORD_KEYS` = `("chapter", "offset", "char", "before", "after")` と完全に一致する**か（過不足が無いか）を見る。一致しなければ検証エラー
5. 各キーの型と値域を見る。合わなければ検証エラー

| キー | 型 | 値域 |
|---|---|---|
| `chapter` | `str` | 空でない |
| `offset` | `int`（`bool` を除く） | 0 以上 |
| `char` | `str` | **ちょうど 1 文字** |
| `before` | `str` | 制限なし（空でもよい） |
| `after` | `str` | 制限なし（空でもよい） |

検証エラーが 1 件でもあれば、**逆引きを 1 件も行わず、出力ファイルを作らずに**終了コード 1 で終わる（§1.4.5 の手順 1）。

#### エラーハンドリング

| 想定されるエラー | 標準エラー出力のメッセージ | 終了コード |
|---|---|---|
| 入力ファイルが無い・ファイルでない | `候補ファイルが存在しない: {path}` | 1 |
| JSON として読めない | `JSON として読めない行がある: {path}:{行番号}` | 1 |
| `dict` でない | `候補レコードがオブジェクトでない: {path}:{行番号}` | 1 |
| キーが過不足している | `候補レコードのキーが不正: {path}:{行番号}（{実際のキーの並び}）` | 1 |
| 型・値域が合わない | `候補レコードの値が不正: {path}:{行番号}（{キー名}）` | 1 |

**最初に見つかった検証エラーで打ち切ってよい**（全件を列挙しない）。行番号を示すことで、どの行が原因かが分かる。

#### 境界条件

| 入力 | 振る舞い |
|---|---|
| 0 バイトのファイル | 候補 0 件。`--select` を指定していれば範囲外として終了コード 2、指定していなければ 0 件を処理して 0 バイトの出力を作り終了コード 0 |
| 末尾に空行がある | 空行を飛ばすため件数に影響しない |

## 1.7 インターフェース定義

公開関数のシグネチャ。すべて `scripts/locate_candidates.py` に置く（1 モジュール・クラスなし）。

```python
def resolve_content_list(final_dir: Path, chapter: str) -> Path: ...
def block_search_text(block: dict[str, object]) -> str: ...
def build_key(record: dict[str, object], k: int) -> str: ...
def locate_block(record: dict[str, object], blocks: list[dict[str, object]]) -> tuple[int | None, int | None, int | None]: ...
def make_result(record: dict[str, object], page_idx: int | None, judgment: str | None) -> dict[str, object]: ...
def read_candidates(path: Path) -> list[tuple[int, dict[str, object]]]: ...
def write_jsonl(records: list[dict[str, object]], out: Path, overwrite: bool) -> None: ...
def parse_args(argv: list[str] | None = None) -> argparse.Namespace: ...
def main(argv: list[str] | None = None) -> int: ...
```

- `locate_block` は `(block_idx, page_idx, k)` を返す。逆引き失敗のときは `(None, None, None)`
- `read_candidates` は §1.4.8 の検証を行い、**（物理行番号, レコード）の対**を入力ファイルの並び順のまま返す。検証エラーでは例外を送出し、`main` が終了コード 1 に変換する
- `main` は終了コードを**返す**（`sys.exit` を内部で呼ばない）。スクリプト末尾で `if __name__ == "__main__": sys.exit(main())` とする
- 定数は `UPPER_SNAKE_CASE`（`SEARCH_KEYS`・`KEY_LENGTHS`・`JUDGMENTS`・`RECORD_KEYS`・`RESULT_KEYS`）
- クラスは作らない（状態を持たないため）

### CLI

```
uv run python scripts/locate_candidates.py <candidates.jsonl> --final-dir <final ディレクトリ> -o <出力 JSONL> [--select N] [--judgment 値] [--overwrite]
```

| 引数 | 型 | 必須 | 既定値 | 説明 |
|---|---|---|---|---|
| `candidates`（位置引数） | `Path` | 必須 | なし | 候補レコードの JSONL |
| `--final-dir` | `Path` | 必須 | なし | content_list の親ディレクトリ（`{BASE2}/ocr/final`） |
| `-o` / `--output` | `Path` | 必須 | なし | 出力先の JSONL |
| `--select` | `int` | 任意 | なし（全件） | 処理する候補の**物理行番号**（候補 JSONL の先頭行を 1 とする。空行も 1 行と数える。§1.4.5）。1 件だけを処理する |
| `--judgment` | `str` | 任意 | なし（`null`） | 判定の値。`missing` / `not_missing` / `undecidable` のいずれか。**`--select` と併用するときのみ許可**する（全件に同じ判定を書けてしまうことを防ぐため） |
| `--overwrite` | フラグ | 任意 | 偽 | 出力先が存在するとき上書きする |

### 終了コードの体系

| コード | 意味 |
|---|---|
| 0 | 正常終了（逆引き失敗を含む。失敗は `page_idx` = `null` として出力される） |
| 1 | 運用エラー（入力・`final_dir` の不在、content_list の解決・読み込みの失敗、候補レコードの検証エラー〔§1.4.8〕、出力先の保護に掛かった）。**いずれも出力ファイルを作らない** |
| 2 | 引数の形式・必須引数の誤り（`argparse` の `SystemExit(2)`）、`--judgment` の値が集合外、`--judgment` を `--select` なしで指定、**`--select` の物理行番号に候補レコードが無い**（空行・範囲外）、逆引き失敗の候補に `missing` / `not_missing` を指定 |

## 2. 記述ルールへの適合

### 2.1 曖昧表現の排除

本設計書に「適切に」「必要に応じて」「等」を使っていない。文脈の切り詰めの規則（最後の改行より後・最初の改行より前）、`K` の階梯（`[40, 20, 10, 5]`）、`SEARCH_KEYS` の 8 キーとその順序、判定の 3 値、終了コード、メッセージ文言、`--margin` の再試行値（32.0）をすべて具体値で示した。

### 2.2 実装判断ゼロの確認

次の点を明示したことで、2 通り以上の実装が考えられる箇所を無くした。

- content_list を **glob（`*_content_list.json`）で解決し、ちょうど 1 個を要求する**こと（ADR-12）
- **照合キーを作る前に文脈を改行で切り詰める**こと（`before` は最後の改行より後、`after` は最初の改行より前。ADR-17）と、切り詰めが候補レコードを変更しないこと
- 照合キーの作り方（`b[-K:] + char + a[:K]`）と `K` の並び
- 一致が **2 件以上のときは短い `K` に進まず逆引き失敗**にすること（ADR-13）
- 同一ブロック内の複数一致を**一意として扱う**こと
- 判定結果レコードのキーを **7 個に限る**こと（ブロック番号・`K` を入れない。ADR-14）
- 逆引き失敗のとき `missing` / `not_missing` を**受け付けない**こと
- 投入する候補を**入力ファイルの先頭レコード**とすること（§1.4.5）
- `--judgment` を `--select` との併用時のみ許可すること
- 全件処理で**入力順を保ち**、章ごとに content_list を 1 回だけ読むこと（§1.4.5）
- 候補レコードを**全件先に検証**し、1 件でも不正なら出力を作らずに終了コード 1 で終わること（§1.4.8）
- 章の content_list の解決に失敗したとき、**部分的な結果を出力しない**こと
- `--select`・標準出力の内訳・検証エラーが**すべて物理行番号**を使うこと（ADR-15）
- 再実行のときに前回の成果物を**退避**（`mv`）し、削除も上書きもしないこと。退避先の名前の付け方（`prev/m2-1-{YYYYMMDD-HHMMSS}/`）
- 退避の前に**許可リストで直下のエントリを検査**し、許可外があれば `mkdir`・`mv` を行わずに中断すること。退避先が既に在る場合も同じく移動の前に中断すること
- 退避の対象は M2-1 の 3 つだけで、M1・M2 の出力と `prev/` は動かさないこと
- 手順 3・6 に `--overwrite` を付けないこと
- **M2-1 の手順では**逆引き失敗のときに手順 6 を行わず、本ステージの最終出力を作らない（照合の対象になる件数は 0）まま再計画に入ること（§1.9.2 手順 3、ADR-16）。M3・M4 では全件処理の経路で `undecidable` として記録すること（§1.4.4・§1.4.5）

### 2.3 コード例の位置づけ

本書のコード片（`key(K)` の式、`SEARCH_KEYS` の並び、関数シグネチャ）は仕様の記述であり、スクリプト本体は `scripts/locate_candidates.py` に置く。

## 2.2 設計判断の記録（ADR）

### ADR-10: 逆引き処理を `scripts/` に置く（プロダクトコード）

- **採用**: `scripts/locate_candidates.py`、テストは `tests/test_locate_candidates.py`
- **却下**: マイルストーンフォルダ `m2-1-locate-smoke/` に置く（実験コードとして扱う）
- **理由**: `CLAUDE.md`「ドキュメント作成ルール」の判定基準は「**その案件が終わった後も使うか**」である。本 CLI は M3（予備標本 30 件）・M4（本標本 `n` 件）でも使い、feat-025 の完了後も候補から原本ページを引く経路として再現する必要がある（後続の修正案件が同じ突合を行う場合）。またマイルストーンフォルダ配下に置くと `tests/` のテストが案件フォルダ配下のコードを import する構造になり、`CLAUDE.md`「テスト」節と噛み合わない（M1 の ADR-1 と同じ判断）

### ADR-11: 切り出しは既存の `crop_blocks.py` をそのまま使う

- **採用**: `scripts/crop_blocks.py` を無変更で使い、逆引き処理からは呼び出さない（手順として別々に実行する）
- **却下 A**: `locate_candidates.py` が `crop_blocks.py` を import して切り出しまで一気に行う
- **却下 B**: 切り出し機能を `locate_candidates.py` に書き直す
- **理由**: `roadmap.md` §7 のステージ表は S3 の手段を「S2-1 で疎通した逆引き処理＋`scripts/crop_blocks.py`＋目視」と、**2 つの手段の組み合わせ**として定めている。却下 A は 2 つを 1 つに融合させることになり、ステージ表の手段の記述と食い違う。却下 B は既存の実績ある実装（feat-021。テスト済み）を捨てて新しい手段を増やすことになり、単体疎通の対象が広がる。分けておけば、逆引きが失敗した候補では切り出しを行わない（手順 3 の分岐）という制御も自然に書ける

### ADR-12: content_list を glob で解決し、ちょうど 1 個を要求する

- **採用**: `{final_dir}/{chapter}/*_content_list.json` を glob し、1 個でなければ運用エラー
- **却下 A**: `{final_dir}/{chapter}/{chapter}_gray300_content_list.json` とファイル名を組み立てる
- **却下 B**: content_list のパスを候補ごとに CLI 引数で受け取る
- **理由**: 却下 A は `_gray300` という実行時の設定に由来する接尾辞に依存し、他書籍・別解像度の実行で壊れる（M1 の ADR-5 で章名をファイル名から取らなかったのと同じ理由）。却下 B は M3・M4 で 10 章分を渡すことになり、`--select` を使わない全件処理と噛み合わない。glob で 1 個を要求すれば、想定と違う状態（0 個・複数）を黙って通さずに検出できる（実データで各章 1 個であることは 2026-09-10 に確認した）

### ADR-13: 一致が 2 件以上のときは短い `K` に進まず逆引き失敗にする

- **採用**: ある `K` で一致ブロックが 2 件以上なら、その場で逆引き失敗として打ち切る
- **却下 A**: より短い `K` を試し続ける
- **却下 B**: 2 件以上のときは先頭のブロックを採る
- **理由**: 照合キーは `K` が短いほど一般的になるため、`K` を短くしても曖昧さは解消しない（増える）。却下 A は無駄な走査であり、結果も変わらない。却下 B は**間違ったページを原本として目視することになり、判定を誤る**。判定できない候補が一定数出ることは `roadmap.md` P8 で織り込まれており、その割合 `q` は S3 で測る。**誤った特定より、失敗として `u`（判定不能）に数えるほうが測定として正しい**

### ADR-18: 再実行では前回の成果物を退避し、`--overwrite` を使わない

- **採用**: 再実行の前に、`feat-025/` 直下のエントリを**許可リストと突き合わせて検査してから**、前回の実行の中間出力・最終出力・PNG のディレクトリを `{BASE2}/ocr/feat-025/prev/m2-1-{YYYYMMDD-HHMMSS}/` に `mv` で移動する（§1.9.2 の手順 -1。**検査を終えるまで `mkdir`・`mv` を行わない**）。手順 3・6 のコマンドには `--overwrite` を付けない
- **却下 A**: 手順 3・6 に `--overwrite` を付けて、残っている出力を上書きする
- **却下 B**: 再実行の前に前回の出力を削除する
- **却下 C**: M2 の `design.md` §1.4.2 と同じく「既存の出力を確認したうえで中断して報告する」だけにする
- **理由**: 却下 A・B は前回の実行の成果物が失われ、`experiment_log.md` に残る記録と実体が食い違う（M2 の ADR-9 と同じ考え方——実行が 2 回以上行われたことを記録から見分けられなくなる）。却下 C は、M2（S2）が 1 回しか実行しない前提のステージであるのに対し、**S2-1 は再計画によって再実行されることが規定上あり得る**ステージ（`CLAUDE.md`「ロードマップの改訂（再計画）」の「改訂後の `roadmap.md` をステップ3 に通してから再実行する」）であり、そのたびに中断していては手順が完了しない。退避なら、前回の成果物を保ったまま、手順 3・6 を変えずに（`--overwrite` なしで）再実行できる
- **検査を先に行う理由**: 想定外の残留物があるときに中断するのであれば、**中断の判断は移動の前に終わっていなければならない**（移動した後で中断しても、既に状態を変えている）。また「想定外」を実行時の判断に委ねないため、直下に在ってよいエントリを許可リストとして列挙で固定し、退避の対象と対象外（M1・M2 の出力、`prev/`）も同じ表で定めた。退避先が既に在る場合（同一秒での二重退避）も、移動の前に検出して中断する（codex-48 の指摘）
- **経緯**: 2026-09-14 の再実行で、中間出力 `m2_1_located.jsonl` が 2026-09-10 の実行から残っていたため、Claude Code 本体がその場の自己判断で `--overwrite` を付けて回避した（`experiment_log.md` に逸脱として記録）。本 ADR はその状況に対する手順を設計に定めたものである

### ADR-17: 照合キーを作る前に文脈を改行で切り詰める

- **採用**: `before` は最後の改行より後、`after` は最初の改行より前だけを使って照合キーを作る（§1.4.2）
- **却下 A**: 文脈をそのまま使う（本 ADR の追加前の設計）
- **却下 B**: 文脈を段落境界（`\n\n`）だけで切り詰める
- **理由**: 却下 A は 2026-09-10 の S2-1 の実行で、投入した候補 1 件（`chap00`・`offset` = 3277）が `K` = 40 / 20 / 10 / 5 のすべてで一致 0 件となり、逆引きに失敗した（`experiment_log.md`。`roadmap.md` P15）。同日の計数では、候補 414 件に同じ階梯を当てたときに一意に定まる件数は、却下 A が 319 件、採用案が **358 件**、却下 B が 357 件である。採用案は却下 B を含む（`\n\n` は `\n` を含むため）ぶん切り詰めが強く、実測でも一意に定まる件数が多い
- **候補レコードとの関係**: 切り詰めは照合キーの生成にだけ効き、候補レコードの `before` / `after` は原文のまま残る。したがって `roadmap.md` §5 の `c_i`・`c'_i` と、§7 のステージ表の入出力の次元は変わらない（`roadmap.md` 第4版の改訂は「式の変更」の水準であり、次元を動かしていない）

### ADR-16: 逆引きに失敗したとき、M2-1 の手順では判定結果レコードを作らない

- **採用**: M2-1 の実行手順では、逆引きに失敗した（または PNG を判読できなかった）ときに判定の記録（手順 6）を行わず、本ステージの**最終出力** `m2_1_judged.jsonl` を作らない。照合の対象になる件数は 0 件となり、`roadmap.md` §8 の S2-1 の幅を外れる
- **却下**: 失敗時に `--judgment undecidable` で判定結果レコードを 1 件出力してから再計画に入る
- **理由**: `roadmap.md` §8 の S2-1 は幅（0）の外れを「**1 件のレコードが出ないこと**、すなわち原本ページを特定できないか PNG を切り出せないこと」と定めており、この 2 つを同じものとして書いている。却下案では失敗時にもレコードが 1 件出るため、件数（1）とページ特定の成否（失敗）が食い違い、ロードマップの記述と一致しなくなる。ロードマップは人レビューを通過して固定されており（criteria lock）、その記述に合う設計が取れる以上、こちらを採る。**CLI の機能としては `undecidable` を書ける**（§1.4.4）——S3・S4 は全件処理の経路で判定不能を `u` として数える必要があるため。本 ADR が定めるのは M2-1 の**実行手順**であって、CLI の仕様ではない
- **経緯**: 本設計は当初、失敗時にも `undecidable` のレコードを出す形にしていた（codex-34 の指摘への対応）。しかし codex-35 で、その形がロードマップ §8 の S2-1 の幅の定義と一致しないことが判明したため、ロードマップを動かさない側に改めた

### ADR-15: 行番号を物理行番号に統一する

- **採用**: `--select` の番号、標準出力の内訳の `{行番号}`、§1.4.8 の検証エラーのメッセージの行番号を、**すべて候補 JSONL の物理行番号**（1 始まり。空行も 1 行と数える）に統一する。`read_candidates` は（物理行番号, レコード）の対を返す
- **却下 A**: `--select` を「有効なレコードの通し番号」（空行を除いて数えた番号）にする
- **却下 B**: `--select` は有効レコード番号、エラーは物理行番号と、用途ごとに使い分ける
- **理由**: 却下 A は、検証エラーのメッセージ（`{path}:{行番号}`）が物理行番号でなければ原因の行を開けないため、番号系が 2 つになる。却下 B は 2 つの番号系が同一文書に共存し、実行時にどちらを指しているか判断が要る（`design.md` の細かさの下限「判断なしに実行できる」に反する）。物理行番号なら、エディタの行番号・`sed -n '{N}p'`・標準出力の内訳がそのまま対応する。空行を指定した場合はエラー（終了コード 2）にすることで、番号の食い違いを黙って通さない

### ADR-14: 判定結果レコードにブロック番号と `K` を入れない

- **採用**: レコードは 7 キー（候補レコードの 5 キー ＋ `page_idx` ＋ `judgment`）。ブロック番号と採用した `K` は標準出力に出す
- **却下**: `block_idx`・`k` もレコードに入れる（切り出しの再現に便利であるため）
- **理由**: `roadmap.md` §5 は判定結果レコードの成分数を `c'_i` = `c_i` + 2（**原本ページ番号 1 ＋ 判定 1**）と定めており、ステージ表 S2-1・S3・S4 の出力の次元（`Σ c'_i` = 件数 × 90）はこれに依る。レコードにキーを足すと `c'_i` = `c_i` + 4 となり、**ロードマップの次元の式と食い違う**（次元を変えるならロードマップの改訂と人レビューが要る）。ブロック番号は標準出力から得られ、同じ入力に対して決定的に再現できるため、レコードに持たせる必要はない
