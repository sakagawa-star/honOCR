## 2. 現象

`{BASE2}/ocr/final/chap02/chap02_gray300.md` の 546〜548 行目（2026-08-31 実測）。

```
## ? 2.2 本文の例の条件つき確率を式 (2.7) で求めようとしたら、 $\frac{3/16}{9/16}$ なんという分数の分数になっ
                                                        ← 空行
てしまいました。これはどうやって計算したらいいのですか？
```

原本では1つの Q&A 見出し（枠囲みの質問文）が2行に組まれているが、MinerU がその
2行目を見出しとは別のブロックとして切り出したため、Markdown 上で
「見出し行 ＋ 空行 ＋ 本文段落」の3ブロックに分断されている。

`{BASE2}/ocr/final/chap02/chap02_gray300_content_list.json` での対応（配列 index）:

| index | `type` | `text_level` | `page_idx` | `bbox` | 内容 |
|---|---|---|---|---|---|
| 250 | `text` | 2 | 15 | `[96, 273, 829, 305]` | `? 2.2 本文の例の…なんという分数の分数になっ` |
| 251 | `text` | なし | 15 | `[178, 305, 617, 324]` | `てしまいました。これはどうやって計算したらいいのですか？` |

2つのブロックは同一ページの上下に隣接している（index 250 の下端 305 ＝ index 251 の上端 305）。

## 3. 原本での確認（2026-08-31）

`page_idx` = 15 から、原本 TIF `{BASE2}/dewarping/chap02/out/page-08_2R.tif`
（`{BASE2}/ocr/pdf/chap02_gray300.pdf.manifest.json` の `files[15]["path"]`）の
該当領域（bbox `[60, 262, 900, 332]` 相当）を切り出して目視確認した。原本の記述は次のとおりである。

```
? 2.2  本文の例の条件つき確率を式 (2.7) で求めようとしたら、(3/16)/(9/16) なんていう分数の分数になっ
       てしまいました。これはどうやって計算したらいいのですか？
```

（`(3/16)/(9/16)` は原本では分子 `3/16`・分母 `9/16` の組分数として組まれており、
OCR は `$\frac{3/16}{9/16}$` と正しく認識している。数式部分に誤りはない。）

確認できた事実は2点ある。

1. **原本では1つの見出し（Q&A の質問文）**であり、2行に組まれているのは行送りによるものである。
   分断は OCR（MinerU の layout 解析）に起因する
2. **原本は「なんていう」であり、OCR の「なんという」は誤読である**（「て」→「と」の誤り）

## 4. 派生して発見した「なんという」の誤読（2026-08-31）

§3 の 2 点目を受けて確率統計 final 全10章を全文検索したところ、「なんという」が
**計10件**あった。**全10件について原本 TIF を目視確認し、すべて原本は「なんていう」**であった
（OCR が一貫して「て」→「と」と誤読している）。

| 章 | md 件数 | 箇所 |
|---|---|---|
| chap01 | 1 | `? 1.5` 見出し（`chap01_gray300.md:204`） |
| chap02 | 1 | **`? 2.2` 見出し（`chap02_gray300.md:546`）＝ 本案件の分断箇所と同一行** |
| chap03 | 3 | 本文1（`:966`）、図 3.15 キャプション（`:1263`）、図 3.16 キャプション（`:1274`） |
| chap06 | 4 | 本文4（`:523`、`:567`、`:571`、`:627`） |
| chap08 | 1 | 本文1（`:366`） |

このうち **chap02 の1件は本案件の分断箇所と同一行**にあり、分断を結合する `old` / `new` に
必ず含まれる。誤読を残したまま結合するのは不自然であるため、**本案件で同時に修正する**
（2026-08-31 ユーザー決定）。

**残り9件（chap01・chap03・chap06・chap08）は本案件のスコープ外**であり、
別案件（feat-017 として起票予定）で扱う。

## 5. 検出の限界（本件が既存の警告に掛からない理由）

### 5.1 見出しの分断

- 分断は**ブロック分割の問題**であり、文字の認識誤りではない。`normalize_punct.py` の
  字形正規化・JIS X 0208 外漢字の警告・旧字体の警告のいずれの対象でもない
- `build_final.py` の3種類の機械検証（バイト同一・md の画像参照・`img_path` 集合の一致）は
  ファイルの整合性を検査するものであり、本文の構造は検査しない
- したがって本件はユーザーの手動テストによってのみ発見された

### 5.2 「なんという」の誤読

- 「と」「て」はいずれも JIS X 0208 内の文字であり、feat-011 の「JIS X 0208 外漢字の警告」には現れない
- 字形の 1 対 1 対応ではない**語彙単位の誤り**であり、feat-013 で21種に拡充した
  字形正規化テーブルでも扱えない（「なんという」は「なんという大事件だ」等で正当に使われる）
- feat-016 の「上的 → 上の」と同種であり、CLAUDE.md のドメイン知識に記載済みの既知の類型である

## 6. 影響範囲の調査（2026-08-31 実測）

### 6.1 見出しの分断

確率統計 final 全10章の `content_list.json` を対象に、「見出しブロック（`text_level` あり）の
直後に、同一ページで隣接する非見出しブロックが続く」箇所を機械走査し、そのうち
**見出しテキストが文の途中で切れているもの**（文末が `。` `？` `！` `……` や閉じ括弧で
終わっていないもの）を抽出した。

結果、文中で切れている見出しは **chap02 の本件1件のみ**であった。
（`? 1.5`・`? 1.7`・`? 3.1` 等の他の Q&A 見出しは `。` または `……` で正しく終わっており、分断ではない。）

### 6.2 「なんという」

§4 のとおり確率統計で10件。PRML（`{BASE}/ocr/final/chap00〜07`）の md には **0件**である。
