# feat-007 要求仕様書: 図画像のカラー再切出スクリプト（colorize_images.py）

## 1.1 プロジェクト概要

- **何を作るのか**: MinerU の content_list に記録された図ブロックの座標（bbox・page_idx）を使い、原本 TIF（600dpi カラー）から同じ領域をカラーで切り出して画像ファイルを生成する CLI `scripts/colorize_images.py`
- **なぜ作るのか**: 現在の図画像は OCR 入力（グレースケール PDF）由来のグレー画像で、ユーザーの学習用途に使えない。確認済みの OCR テキストには手を付けずに、図だけをカラー・高解像度に差し替えるため
- **誰が使うのか**: ユーザー本人（Claude Code なしで実行できること）
- **どこで使うのか**: 本リポジトリの uv 環境。GPU 不要

## 1.2 用語定義

feat-005/006 の用語（`{ROOT}`・content list・対象TIF・MinerU 生出力・run ディレクトリ）を継承する。追加分:

| 用語 | 定義 |
|---|---|
| 図ブロック | content_list 中で `img_path` キーを持つブロック（type は image / chart / table。今後の型追加にも `img_path` の有無で対応する） |
| bbox | 図ブロックの座標。ページ左上原点の 0–1000 正規化 [x0, y0, x1, y1]（案件 README の実測検証のとおり） |
| TIF 列 | TIF ディレクトリ直下の `page-*_1L.tif`・`page-*_2R.tif` を辞書順に並べた列（feat-005/006 の対象TIF と同一規則）。`page_idx` はこの列の 0 始まり位置に一致する |

## 1.3 機能要求一覧

### FR-001: カラー再切出

- **機能名**: 図ブロックのカラー切り出し
- **概要**: content_list の全図ブロックについて、`page_idx` 番目の TIF から `bbox/1000 × TIFピクセルサイズ` の領域を切り出し、`img_path` と同じベース名で出力ディレクトリに保存する
- **入力**: content_list の JSON パス、TIF ディレクトリ、出力ディレクトリ `-o`
- **出力**: 出力ディレクトリ配下のカラー JPEG（quality 95、RGB。ファイル名は `img_path` のベース名と同一 — md・content_list の参照を書き換えずに差し替え可能にする）。**既定で切り出し結果を 1/3 に縮小して保存する**（600dpi 切出の 1/3 = 200dpi 相当。旧 MinerU 生成画像と**同等の表示サイズ**になる — 丸めにより数 px（1% 以内）の差は許容する。2026-08-18 手動テストの表示過大指摘への対応）。`--scale` オプション（0 より大きい実数）で変更可（`--scale 1.0` で原寸）
- **受け入れ基準**:
  1. content_list 中の図ブロック全件が処理され、生成ファイル数が `img_path` のユニーク数と一致する（同一 `img_path` が複数ブロックに現れる場合は1回のみ生成）
  2. 出力画像はカラー（RGB）で、ピクセルサイズが「`bbox/1000 × TIF サイズ` の四捨五入値（TIF 境界へのクランプを除く）× scale の四捨五入値（最小 1px）」と一致する
  3. 原本 TIF・content_list・md・既存の `images/` を変更しない（出力は指定ディレクトリへの新規書き込みのみ）
  4. 図ブロックが 0 件の content_list（例: 図のない章）では、出力 0 件・その旨の報告で正常終了する

### FR-002: 入力検証とエラー処理

- **機能名**: 入力検証とエラー処理
- **概要**: 不正な入力を実行前に検出し、処理中の異常を明確に報告する
- **入力**: FR-001 と同じ
- **出力**: エラーメッセージ（標準エラー）と終了コード
- **受け入れ基準**:
  1. content_list が存在しない・JSON として読めない → 終了コード 1
  2. TIF ディレクトリが存在しない・TIF 列が 0 件 → 終了コード 1
  3. `page_idx` が TIF 列の範囲外、`bbox` が欠落・不正（長さ4でない、数値でない、x0≥x1 または y0≥y1、0–1000 の範囲外）→ 該当ブロックを報告して終了コード 1（部分的な出力で成功扱いにしない）
  3b. `--scale` が 0 以下 → 終了コード 1・出力なし
  4. 出力先の同名ファイルが既存の場合は拒否して終了コード 1（`--overwrite` 指定時は上書き）
  5. 正常終了時は「処理ブロック数・生成ファイル数・出力先」を標準出力に表示し、終了コード 0

### FR-003: 自動テスト

- **機能名**: pytest による自動テスト
- **概要**: ダミー TIF（小サイズのカラー画像）とダミー content_list で切り出しロジックと検証を固定する
- **入力**: `tests/test_colorize_images.py`
- **出力**: `uv run pytest -v` 全件 PASS、結果を `tests/results/feat-007_test_result.txt` に保存
- **受け入れ基準**: 座標変換（bbox→ピクセル）・クランプ・重複 img_path・図ブロック 0 件・各エラー系（FR-002）の合否をテストで固定する

## 1.4 非機能要求

- **処理時間**: 1章あたり 60 秒以内（GPU 不要。I/O と JPEG エンコードのみ）
- **対応環境**: 本リポジトリの uv 環境（Python 3.12、pillow は既存依存）
- **信頼性**: 入力（TIF・content_list・既存 images/）を変更しない

## 1.5 制約条件

- **使用必須**: Python 3.12 標準ライブラリ＋pillow（既存依存）
- **使用禁止**: 新規ライブラリの追加。MinerU の再実行（GPU ジョブ）は行わない
- **参照の維持**: 出力ファイル名は `img_path` のベース名と同一とし、md・content_list の書き換えを行わない
- **既存スクリプトの改変禁止**: `make_ocr_pdf.py`・`normalize_punct.py`・`ocr_dir.py` は変更しない

## 品質確認の扱い

数値判定を伴う実験はない（通常の実装・自動テストの範囲）。動作確認は chap01 の実データで行い、生成画像がカラーであること・md の図参照位置で正しく表示されることをユーザーが目視確認する（手動テストステップ）。
