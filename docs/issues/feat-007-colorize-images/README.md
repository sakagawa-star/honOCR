# feat-007: 図画像のカラー再切出スクリプト（colorize_images.py）

- **ステータス**: Closed（2026-08-18 完了）
- **種別**: feat（機能追加）

## 概要

MinerU が切り出した図画像（`images/*.jpg`）はグレースケール（OCR 入力 PDF がグレースケールのため）。content_list の座標情報（bbox・page_idx）を使って**原本 TIF（600dpi カラー）から同じ領域をカラーで切り出し直す** CLI `scripts/colorize_images.py` を追加する。

- ユーザー要望（2026-08-18）: 「OCR のテキスト化は問題ないが、画像が白黒だと使えないのでカラーにしてほしい」
- 方式はユーザー選択（2026-08-18）: **案A = 原本からの再切出**（確認済みテキストには一切手を付けない。GPU 不要）。案B（カラー PDF で全章再変換）は、テキストが再生成されて確認をやり直しになるため不採用

## 調査記録（2026-08-18。chap01 run-01 の実データで検証）

- content_list で `img_path` を持つブロック: **type = image（27）・chart（26）・table（2）の計55**。全ブロックが `bbox` と `page_idx` を持つ
- md が参照する画像は53件で、上記55件の部分集合（`images/` ディレクトリの残り157ファイルは md からも content_list からも参照されない中間生成物）
- **bbox は 0–1000 正規化座標**（ページ左上原点、[x0, y0, x1, y1]）。実測検証: chap01 page_idx=3 の写真ブロック（bbox=[233,280,746,768]）を「bbox/1000 × TIF ピクセルサイズ」で原本 `page-02_2R.tif` から切り出したところ、保存済み jpg と同一領域・同一アスペクト比（0.667 = 0.667）のカラー画像が得られた
- page_idx と TIF の対応: 対象TIF（`page-*_1L.tif`・`page-*_2R.tif` の辞書順、feat-005/006 と同一規則）の 0 始まり位置がそのまま page_idx に一致する（feat-005 の page_idx 検査で全章確認済み）
- 保存済み jpg は MinerU 内部 200dpi レンダリング由来（例: 631×946px）。原本 600dpi からの切出は同じ図で約3倍の解像度になる
